--------------------------------------------------------------------------------
 WINDOWS  (Windows 11 25H2 or newer, PowerShell 7)
--------------------------------------------------------------------------------
  1. Unzip the kit (right click > Extract All) to a folder, for example C:\pki-devkit.
  2. Start PowerShell 7 AS ADMINISTRATOR, then:
         cd C:\pki-devkit
         .\Install-PkiTrust.ps1
     (If Windows blocks the script: Unblock-File .\*.ps1   or   .\PkiTransport.ps1 -Unblock)
     It asks for the password, checks the machine, unpacks, installs the CAs. OpenSSL 4.0.1+ must be installed:
     .\Install-PkiTrust.ps1 -InstallMissing  installs it for you.
     No OpenSSL 4 yet? First (once, as Administrator):  .\Install-DevEnvironment.ps1 -Only OpenSSL,7Zip
     (installs OpenSSL 4.x, writes the FIPS config and adds it to the Path; open a NEW PowerShell afterwards).
     Ubuntu:  ./Install-DevEnvironment.sh --yes --only openssl
              (default: the OpenSSL of Ubuntu itself - 3.5.x on 26.04, 3.0.x on 24.04 - enough for the .sh generators; nothing is built.
               OpenSSL 4 from YOUR PPA: add  --openssl-source ppa ;  built from source: --openssl-source build.   nginx from the PPA: --only nginx).
  3. Make certificates (a normal PowerShell is enough from now on):
         .\GenerateLeafCertificate.ps1 -OV -DnsName www.example.com
         .\GenerateLeafCertificate.ps1 -EV -DnsName api.example.com -Purpose ServerAuth -NoRevocationInfo
         .\GeneratePersonLeafCertificate.ps1 -ExampleFile persons.json      (edit persons.json, then)
         .\GeneratePersonLeafCertificate.ps1 -File persons.json
         .\GenerateOffice365LeafCertificate.ps1 -ExampleFile office365.json
         .\GenerateOffice365LeafCertificate.ps1 -File office365.json -NoRevocationInfo
     The certificates are written to the folder leafcerts\ (every folder has the .crt, .key, .pfx, chain files).
     A colleague sends a CSR:   .\SignCsr.ps1 -Csr his.csr -Check     (report only: what is wrong, in colour)
                                .\SignCsr.ps1 -Csr his.csr            (DV, default)    -OV / -EV / -Quantum / -FIPS / -Purpose / -Days
     The result is in csr-signed\ - send him the *-fullchain.crt. Only the intermediate CAs of the kit sign; roots are signed by the owner.
     Help of every script:  .\<script>.ps1 -Help

--------------------------------------------------------------------------------
 UBUNTU / LINUX  (you do not need to be a Linux person: copy and paste)
--------------------------------------------------------------------------------
  1. Copy the zip to the Ubuntu machine and unpack it:      unzip agantra-pki-devkit-*.zip && cd agantra-pki-devkit-*
  2. Make the scripts executable (once):                     bash make-executable.sh
     (A kit unpacked on Windows and copied over loses the executable bit; this puts it back and fixes Windows line endings.
      You can also start any script with   bash ./name.sh   and never need the executable bit.)
  3. Install the PKI:                                        ./Install-PkiTrust.sh
     It asks for the package password, uses sudo only for the system store and for missing packages (7-Zip).
  4. Make certificates:
         ./GenerateLeafCertificate.sh --ov --dns www.example.com
         ./GenerateLeafCertificate.sh --ev --dns api.example.com --purpose ServerAuth --no-revocation-info
         ./GeneratePersonLeafCertificate.sh --example-file persons.json ; ./GeneratePersonLeafCertificate.sh --file persons.json
         ./GenerateOffice365LeafCertificate.sh --example-file office365.json ; ./GenerateOffice365LeafCertificate.sh --file office365.json
     A colleague sends a CSR:   ./SignCsr.sh --csr his.csr --check ;  ./SignCsr.sh --csr his.csr --ov --purpose ServerAuth
     Help of every script:  ./<script>.sh --help
     The .sh generators need bash, openssl 3.0+ and python3 (Ubuntu has them; python3 only reads the JSON files).

--------------------------------------------------------------------------------
 GOOD TO KNOW
--------------------------------------------------------------------------------
  * Certificates made here are DEVELOPMENT certificates. They are not in the revocation database (CRL / OCSP) of the master PKI:
    nobody can revoke them centrally. Do not use them for production. The serial numbers are random and different on every copy.
  * Do not copy the pki\ folder to other machines or into Git: it holds the keys of the issuing CAs. leafcerts\ is private too.
  * -NoCrl / -NoOcsp / -NoRevocationInfo (--no-crl / --no-ocsp / --no-revocation-info) leave the revocation URLs out: use them when
    Word / Excel / a tool says "cannot connect to the revocation server".
  * Trouble? docs\DevKit-MANUAL.txt has the list of messages and what to do.

RELEASE OF THIS KIT
  The kit holds ONE PKI (see PKI_RELEASE / PKI_VARIANT in devkit.env). The generators use it automatically; --release / -Release and
  --no-ca-revocation-info / -NoCaRevocationInfo are only needed when the PKI folder holds several. A PKI made with NoCR has CA certificates without CRL / OCSP URLs.
