 WINDOWS   (Windows 11 24H2 or newer, PowerShell 7)
----------------------------------------------------------------------------------------------------
 Step 1   Unzip the kit (right-click, Extract All) to a short folder, for example C:\pki-devkit.
 Step 2   If Windows blocks the scripts:   Unblock-File .\*.ps1
 Step 3   No OpenSSL 4 yet? Once, as administrator:
              .\Install-DevEnvironment.ps1 -Only OpenSSL,7Zip
          Then open a NEW PowerShell.
 Step 4   Start PowerShell 7 AS ADMINISTRATOR:
              cd C:\pki-devkit
              .\Install-PkiTrust.ps1
          It asks for the password, unpacks the kit and installs the CAs.
          -InstallMissing installs OpenSSL and 7-Zip for you.
 Step 5   Make certificates. A normal PowerShell is enough from now on:
              .\GenerateLeafCertificate.ps1 -OV -DnsName www.example.com
              .\GenerateLeafCertificate.ps1 -EV -DnsName api.example.com -Purpose ServerAuth
              .\GeneratePersonLeafCertificate.ps1 -ExampleFile persons.json
                  (edit persons.json, then)  .\GeneratePersonLeafCertificate.ps1 -File persons.json
              .\GenerateOffice365LeafCertificate.ps1 -ExampleFile office365.json
                  (edit office365.json, then)
                  .\GenerateOffice365LeafCertificate.ps1 -File office365.json
 Step 6   Find the files in the folder
 leafcerts\ . Every folder has the .crt, .key, .pfx, the chain
          files and the hash files.
 A colleague sends a request (CSR)?
              .\SignCsr.ps1 -Csr his.csr -Check       Report only: what is wrong, in colour.
              .\SignCsr.ps1 -Csr his.csr              Sign it (DV by default).
          The result is in csr-signed\ . Send him the *-fullchain.crt.

 LINUX / UBUNTU   (copy and paste; you do not need to be a Linux person)
----------------------------------------------------------------------------------------------------
 Step 1   Copy the zip to the machine and unpack it:
              unzip agantra-pki-devkit-*.zip && cd agantra-pki-devkit-*
 Step 2   Make the scripts executable (once):
              bash make-executable.sh
          A kit unpacked on Windows loses the executable bit. This puts it back and fixes Windows
          line endings. You can also start any script with  bash ./name.sh  without the bit.
 Step 3   Install the PKI:
              ./Install-PkiTrust.sh
          It asks for the password. It uses sudo only for the system store and for missing packages.
 Step 4   Make certificates:
              ./GenerateLeafCertificate.sh --ov --dns www.example.com
              ./GenerateLeafCertificate.sh --ev --dns api.example.com --purpose ServerAuth
              ./GeneratePersonLeafCertificate.sh --example-file persons.json
              ./GeneratePersonLeafCertificate.sh --file persons.json
              ./GenerateOffice365LeafCertificate.sh --example-file office365.json
              ./GenerateOffice365LeafCertificate.sh --file office365.json
 A colleague sends a request (CSR)?
              ./SignCsr.sh --csr his.csr --check ;
              ./SignCsr.sh --csr his.csr --ov --purpose ServerAuth
 You need bash, openssl 3.0+ and python3. Ubuntu has them. python3 only reads the JSON files and
 checks requests.
 Need OpenSSL 4?   ./Install-DevEnvironment.sh --yes --only openssl
     By default it uses the OpenSSL of Ubuntu itself, which is enough for the .sh scripts.
     OpenSSL 4 from the PPA of the owner: add  --openssl-source ppa
     Built from source: --openssl-source build.     nginx from the PPA: --only nginx

----------------------------------------------------------------------------------------------------
 GOOD TO KNOW
----------------------------------------------------------------------------------------------------
 * Certificates made here are DEVELOPMENT certificates. They are not in the CRL / OCSP database of
   the master PKI. Nobody can revoke them centrally. Do not use them in production. The serial
   numbers are random and differ on every copy.
 * Do not copy the pki\ folder to other machines or into Git. It holds the keys of the issuing CAs.
   leafcerts\ is private too.
 * Word or Excel say "cannot connect to the revocation server"? Add -NoRevocationInfo
   (--no-revocation-info). The manual explains the limits of this switch.
 * Trouble? docs\DevKit-MANUAL.txt, section 15, lists the messages and the fixes.

 SERVER KIT   (CRL, OCSP and time stamping on an Ubuntu 24.04 / 26.04 machine)
----------------------------------------------------------------------------------------------------
 The folder server\ holds everything for the PKI servers. Copy THAT folder (not the rest of this
 kit) to the Ubuntu machine, then:
     cd server && bash linux/fix-permissions.sh
     sudo ./linux/pki-server/pki-server.sh install --crl-only --source ./pki
         CRL and CA certificates only
     sudo ./linux/pki-server/pki-server.sh install --no-tsa --source ./pki
         CRL and OCSP (first: csr --no-tsa, sign, import-cert)
     sudo ./linux/pki-server/pki-server.sh install --tsa-only --source ./pki
         time stamp server only (first: csr --tsa-only, sign, import-cert)
     sudo ./linux/pki-server/pki-server.sh install --source ./pki
         all three (first: csr, sign, import-cert)
     ./linux/pki-server/pki-server.sh dns
         hosts-file lines and router DNS records
 server\README-SERVER-PACKAGE.txt and server\docs\PKI-SERVER-MANUAL.txt have every step. The
 server\pki folder has NO private key. The OCSP and time stamp keys are made on the server and
 signed on the CA machine (PkiRevocation.ps1 -Action SignCsr). For a new CRL, build the kit again.
 A kit of SEVERAL PKIs has one server kit per PKI: server-<folder>\ (server-pki-default-01 ...).
 Use the one of the PKI that the server serves; the commands are the same.

----------------------------------------------------------------------------------------------------
 THE PKIs OF THIS KIT
----------------------------------------------------------------------------------------------------
 The kit can hold SEVERAL PKIs: every company, every release, normal and NoCR (the owner chose
 them when building the kit; the default is all). Install-PkiTrust installs ALL of them. The list:
 env\pkis.tsv, or  .\PkiTransport.ps1 -List -Package <the .certpacked>.
 The generators and SignCsr use the DEFAULT company (DefaultPki in pki_tools.cnf), its latest
 normal release. Choose another one:
     PowerShell   -Pki raksaka   -Release 2   -NoCaRevocationInfo
     Shell        --pki raksaka  --release 2  --no-ca-revocation-info
 A PKI made with NoCR has CA certificates without CRL and OCSP addresses.
