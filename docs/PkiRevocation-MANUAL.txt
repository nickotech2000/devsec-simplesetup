====================================================================================================
 1  WHAT THIS SCRIPT DOES
====================================================================================================
 A certificate has an end date. Sometimes it must stop earlier: a key is stolen, a person leaves,
 a server is thrown away. Then you REVOKE the certificate. Clients must learn about it. Two
 services tell them:

     CRL    Certificate Revocation List. A signed file with the serial numbers of all revoked
            certificates of one CA. The client downloads it from the address in the certificate.
     OCSP   Online Certificate Status Protocol. A small server. The client asks "is serial
            123 good?" and gets "good", "revoked" or "unknown". It signs its answers with its own
            certificate (the OCSP responder certificate).

 This script does four jobs:
   1. shows the state of every CRL and responder (Status, Info)
   2. revokes a certificate (Revoke)
   3. makes a new CRL (NewCrl)
   4. makes or renews the OCSP responder certificate and the time stamp certificate (NewOcsp,
      NewTsa, SignCsr)

====================================================================================================
 2  THE WORDS YOU NEED
====================================================================================================
 Revoke         Declare a certificate bad before its end date. It cannot be undone.
 CRL            The signed list of revoked serial numbers. It has a number and a "next update"
                date. After that date clients may refuse everything from that CA.
 OCSP           The question-and-answer service for one certificate at a time.
 Responder      The OCSP server. Its certificate has the usage "OCSP Signing" and "nocheck".
 Time stamp     A signed proof that a file existed at a given time (RFC 3161).
 TSA            Time Stamping Authority. The server that gives time stamps.
 index.txt      The list of issued certificates that every CA keeps. Revoke changes it.
 Serial         The number that identifies one certificate inside one CA.
 Replace        Issue a certificate again with a new value. A certificate cannot be edited.

 3  BEFORE YOU START
====================================================================================================
 - A PKI made by pki_setup.ps1. The script finds the latest release in .\pki\ by itself.
 - PowerShell 7 and OpenSSL 4. Install-DevEnvironment-MANUAL.txt installs OpenSSL.
 - To revoke you need the certificate file (.crt) or its serial number and the name of the CA that
   signed it (for example q1-ev).
 - A computer that is allowed: Windows 11 24H2 or newer, Windows Server 2025 and 2022 (Server 2022:
   Classic only). Linux with PowerShell: Ubuntu 24+, CentOS Stream / RHEL / Rocky / Oracle 10+,
   SLES / openSUSE 15+. Others: error, exit 5, nothing is done.
 - Certificates signed inside a DevKit are NOT in your index.txt. You cannot revoke them one by
   one (SignCsr-MANUAL.txt section 11).

 4  QUICK START
====================================================================================================
     .\PkiRevocation.ps1                                          look at everything
     .\PkiRevocation.ps1 -Action Revoke -Certificate .\site.crt   revoke one certificate
     .\PkiRevocation.ps1 -Action NewCrl                           new CRL for every CA
     .\New-PkiServerPackage.ps1                                   package for the server
     (on the server)  sudo ./linux/pki-server/pki-server.sh update --source ./pki

 The last two lines matter. The server only knows what you copied to it.

====================================================================================================
 5  LOOK AT THE STATE (STATUS, INFO)
====================================================================================================
     .\PkiRevocation.ps1                      same as -Action Status
     .\PkiRevocation.ps1 -Action Info         Status, and rewrites the info files

 The Status table has one row per CA:

 Column            Meaning
 ----------------  -----------------------------------------------------------------------
 CRL number        Goes up by one every time a new CRL is made.
 Next update       The date after which this CRL is no longer valid.
 Days left         How long until then. Make a new CRL BEFORE it reaches zero.
 Revoked/issued    How many certificates were revoked, out of how many were issued.
 OCSP responder    Is there a responder certificate for this CA, and how long it is valid.

 Info writes these files in the PKI folder:
   revocation-info.json and REVOCATION-INFO.txt   addresses, CRL numbers, dates, how to renew
   server\                                         server-info.json, ca-list.tsv, server.env,
                                                   expected-urls.tsv, DNS-RECORDS.txt. The
                                                   server script pki-server.sh reads these.
 Every action that changes something refreshes them.

====================================================================================================
 6  REVOKE A CERTIFICATE
====================================================================================================
 By file:        .\PkiRevocation.ps1 -Action Revoke -Certificate .\site.crt -Reason keyCompromise
 By serial:      .\PkiRevocation.ps1 -Action Revoke -Serial 0A1B2C -Ca q1-ev

 What happens:
   1. index.txt of the issuing CA marks the certificate revoked.
   2. A new CRL of that CA is made at once (-NoCrl: later).
   3. The OCSP server answers "revoked" after you do the server update (section 4).

 -Reason is one of:
   unspecified (default)   keyCompromise   CACompromise   affiliationChanged   superseded
   cessationOfOperation    certificateHold
 When a private key is stolen or lost, use keyCompromise. Clients and auditors read the reason.

 Revoking cannot be undone. Check the file name or the serial twice. The serial is easy to see:
     openssl x509 -in site.crt -noout -serial -issuer

====================================================================================================
 7  MAKE A NEW CRL
====================================================================================================
     .\PkiRevocation.ps1 -Action NewCrl                      every CA
     .\PkiRevocation.ps1 -Action NewCrl -Ca q1-ev,q1-ov      two CAs
     .\PkiRevocation.ps1 -Action NewCrl -CrlDays 90          valid for 90 days (default 365)

 A new CRL gets a new CRL number and a new validity. It replaces the old one in publish\. Do this
 before "days left" in Status reaches zero. Put it in your calendar. A CA whose CRL has expired
 can make every client refuse its certificates.

 CRLs are written as DER and PEM in publish\, together with the CA certificates (LF line ends).

====================================================================================================
 8  OCSP AND TIME STAMP CERTIFICATES
====================================================================================================
 Make:
     .\PkiRevocation.ps1 -Action NewOcsp [-Ca q1-ev,q1-ov]     skips a responder that exists
     .\PkiRevocation.ps1 -Action NewTsa [-Level EV|OV|DV]

 Change ("edit"): a certificate cannot be changed. You issue it again with the new value and
 -Replace. The old files move to old-<date>\.
     OCSP   -Action NewOcsp -Ca q1-ev -Replace -OcspDays 180 -OcspKeyBits 3072
            -KeyType RSA|ECDSA -CommonName "..." [-RevokeOld]
     TSA    -Action NewTsa -Replace -TimestampDays 3650 -TimestampPolicyOid 1.3.6.1.4.1.<PEN>.1.4
            -TimestampQuadrant 1
 -RevokeOld also revokes the old certificate (reason superseded) and makes a new CRL.

 Files of a responder: pki\ocsp\<ca>\<ca>-ocsp.crt, .key, .pub, -fullchain.crt, ocsp-info.json.
 Always copy to the server afterwards (section 4).

====================================================================================================
 9  KEYS ON THE SERVER (SIGNCSR)
====================================================================================================
 Best practice: the private key of the responder and of the time stamp server never leaves the
 server. The server makes its own key and a CSR. You sign the CSR. The certificate goes back.

   On the server:    sudo ./linux/pki-server/pki-server.sh csr --source ./pki --out ./csr
   Here:             .\PkiRevocation.ps1 -Action SignCsr -Csr .\csr\ocsp-q1-ev.csr `
                         -For Ocsp -Ca q1-ev
                     .\PkiRevocation.ps1 -Action SignCsr -Csr .\csr\tsa-q1-ev.csr `
                         -For Tsa -Ca q1-ev
   On the server:    sudo ./linux/pki-server/pki-server.sh import-cert \
                         --cert ocsp-q1-ev.crt --cert tsa-q1-ev.crt

 The CSR is checked (signature, RSA 2048 or more, or ECDSA). The certificate gets the right usage,
 the policies of the CA, the CRL / OCSP / AIA addresses and, for a TSA, the time stamp policy OID.
 The output is <name>.crt and <name>-fullchain.crt in the folder given with -OutFolder.

====================================================================================================
 10  THE TIME STAMP CERTIFICATE
====================================================================================================
 Question: do I need a special certificate for time stamping? No.
 A time stamp server needs a normal leaf certificate whose ONLY extended key usage is
 timeStamping, marked CRITICAL (RFC 3161, 2.3). That is the TimeStamping certificate of
 GenerateLeafCertificate.ps1 and of this script. You do NOT need a separate CA, a special
 hierarchy or a code-signing usage. Programs that check signed code only need to trust the chain
 of the time stamp server.

 Defaults made here: Classic non-FIPS (Quadrant 1), RSA 2048, valid 1825 days (a time stamp must
 stay checkable for years), policy OID 1.3.6.1.4.1.<PEN>.<arc>.4. -TimestampQuadrant 2, 3 or 4
 only prepares FIPS or quantum time stamping. The PKI server signs with RSA / ECDSA only.

====================================================================================================
 11  WHICH PKI IS USED
====================================================================================================
 -Pki <name>            The company. Default agantra. The files are <name>_pki.cnf. List them:
                        .\pki_setup.ps1 -ListPki   (Tab after -Pki shows the names)
 -Release <n>           R1, R2 ... Default: the latest in .\pki\. A deleted release is not an
                        error: the latest is used and a warning says so.
 -NoCaRevocationInfo    The NoCR family (pki-<name>-nocr-NN): CA certificates without CRL and
                        OCSP addresses.
 -PkiRoot <folder>      One PKI folder. Overrides the three above.
 Folders: .\pki\pki-default-NN (agantra) and .\pki\pki-<name>-NN. More: PkiProfiles-MANUAL.txt.

====================================================================================================
 12  WHAT IS MADE FOR YOU AUTOMATICALLY
====================================================================================================
 pki_setup.ps1 (without -SkipRevocation) makes, after the CAs:
   pki\...\ocsp\<ca>\   one OCSP responder certificate per Classic intermediate CA
                        (usage OCSP Signing + ocsp-nocheck, 365 days, own key)
   pki\...\tsa\<ca>\    one time stamp certificate (timeStamping, critical, 1825 days,
                        Classic non-FIPS, policy OID <PEN>.1.4)
   pki\...\publish\     the CRLs (DER + PEM) and the CA certificates, LF only
   revocation-info.json and REVOCATION-INFO.txt
 Settings of pki_setup.ps1: -SkipRevocation  -CrlDays  -OcspDays  -TimestampQuadrant
 -TimestampPolicyOid  -TimestampDays. In agantra_pki.cnf: [ revocation ] CrlDays OcspDays
 OcspKeyBits, and [ timestamp ] Quadrant PolicyOid Days.

====================================================================================================
 13  RECIPES, COPY AND PASTE
====================================================================================================
 Status:                 .\PkiRevocation.ps1
 New 90-day CRL:         .\PkiRevocation.ps1 -Action NewCrl -CrlDays 90
 Stolen key:             .\PkiRevocation.ps1 -Action Revoke -Certificate .\site.crt `
                              -Reason keyCompromise
 Without the file:       .\PkiRevocation.ps1 -Action Revoke -Serial 0A1B2C -Ca q1-ev
 Revoke, CRL later:      .\PkiRevocation.ps1 -Action Revoke -Certificate .\site.crt -NoCrl
 Stronger responder:     .\PkiRevocation.ps1 -Action NewOcsp -Ca q1-ev -Replace -OcspKeyBits 3072
                              -OcspDays 180 -RevokeOld
 Longer time stamp:      .\PkiRevocation.ps1 -Action NewTsa -Replace -TimestampDays 3650
 Sign a server CSR:      .\PkiRevocation.ps1 -Action SignCsr -Csr .\ocsp-q1-ev.csr -For Ocsp `
                              -Ca q1-ev
 Server package:         .\New-PkiServerPackage.ps1 [-Tar]
                         (a zip with the scripts and the PKI without private keys, LF, mode 755)
 On the server:          unzip, then  sudo ./linux/pki-server/pki-server.sh update --source ./pki

====================================================================================================
 14  PROBLEMS AND ANSWERS
====================================================================================================
 "No Classic intermediate CA selected"
     NewOcsp works for Classic intermediates only. Use -Ca q1-ev (or q1-ov, q1-dv, q2-...).
 "-Action SignCsr needs -Csr, -For and -Ca"
     Give all three.
 Revoked, but the browser still says good
     You did not copy the PKI to the server. Do section 4 (package and update). OCSP and CRL
     answers are also cached by clients for some hours.
 The CRL "days left" is negative
     Make a new CRL at once (section 7) and copy it to the server.
 "Responder exists, skipped"
     That is normal. Use -Replace to issue a new one.
 Wrong certificate revoked
     It cannot be undone. Issue a new certificate for that holder.
 Exit code 5
     This computer is refused (section 3). Nothing was done.

====================================================================================================
 15  LIMITS YOU MUST KNOW
====================================================================================================
 - Revocation cannot be undone. There is no "un-revoke" in this script.
 - A certificate signed in a DevKit is not in your index.txt. Revoke the kit's intermediate if a
   kit leaks.
 - The server only changes after you copy the PKI to it again.
 - NewOcsp makes responder certificates for Classic intermediate CAs only.
 - New certificates carry the addresses of the config file as they were on the day of issue.
   Old certificates keep their old addresses.

 16  ALL OPTIONS
====================================================================================================
 -Action Status|Info|NewCrl|Revoke|NewOcsp|NewTsa|SignCsr    What to do. Default Status.
 -Ca <ids>                       CA ids (q1-ev, q1-ov, q1-dv, q2-ev ...). NewCrl takes any CA.
 -CrlDays N                      CRL validity, 1 to 3650 days. Default 365.
 -Certificate <file>             Revoke: the certificate file.
 -Serial <hex>                   Revoke: the serial number (needs -Ca).
 -Reason <r>                     Revoke: unspecified, keyCompromise, CACompromise,
                                 affiliationChanged, superseded, cessationOfOperation,
                                 certificateHold.
 -NoCrl                          Revoke: do not make a new CRL now.
 -OcspDays N                     Responder validity, 1 to 3650 days. Default 365.
 -OcspKeyBits 2048|3072|4096     Key size of the responder / TSA.
 -KeyType RSA|ECDSA              Key type.            -CommonName "..."   Subject name.
 -Replace                        Issue again. The old files go to old-<date>\.
 -RevokeOld                      Also revoke the old certificate (superseded).
 -Level EV|OV|DV                 Time stamp level. Default EV.
 -TimestampQuadrant 1|2|3|4      -TimestampPolicyOid <oid>      -TimestampDays N
 -Csr <file>  -For Ocsp|Tsa  -Days N  -OutFolder <folder>       SignCsr only.
 -Pki <name>  -Release <n>  -NoCaRevocationInfo  -PkiRoot <folder>   Which PKI (section 11).
 -ConfigFile  -OpenSslPath  -FipsModuleConfig  -Verbose         Paths and details.
 -Unblock                        Unblock and unlock the script and pki folders, then stop.
 -Help                           The help.
 Exit codes: 0 ok, 1 error, 5 this system is refused.
