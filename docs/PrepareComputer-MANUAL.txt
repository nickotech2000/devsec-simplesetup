1. WHAT IT IS FOR
   The certificate request maker needs OpenSSL; the project's helper scripts need Python 3. Run this once on a new computer. It looks for the programs, installs what is
   missing with the standard package manager of the system, and makes sure `openssl` and `python` work in a NEW shell (it adds them to the PATH when they are installed
   but not found). It never touches certificates: if the PKI is already installed on the computer (Local Machine store, ca-certificates) nothing changes.

2. RUN IT
      Windows (right-click PowerShell, Run as administrator)       .\Prepare-Computer.ps1 -Check        only look
                                                                    .\Prepare-Computer.ps1               install what is missing
      Linux (sudo is used by itself)                               ./prepare-computer.sh --check
                                                                    ./prepare-computer.sh
   Then open a NEW shell and try:  openssl version   python --version (python3 --version on Linux).

3. WHAT IT USES
   Windows   winget first:  FireDaemon.OpenSSL (OpenSSL 4.x), Python.Python.3.x (the highest version "winget search" lists).
             Chocolatey second (or -Manager Chocolatey):  openssl, python. If the package gives OpenSSL below 4 the script says so (exit 4); RSA and ECDSA still work.
   Linux     Ubuntu 24 / 26: apt (openssl, ca-certificates, python3, python3-pip, python3-venv).   CentOS Stream 10, RHEL 10, Rocky 10, Oracle Linux 10: dnf.
             SLES 15 / 16, openSUSE Leap 15 / 16, Tumbleweed: zypper (openssl-3; the newest of python313 / 312 / 311, else python3).
             Whatever OpenSSL the distribution ships (3.x or 4.x) is accepted: RSA / ECDSA need 3.0, ML-DSA (quantum) needs 3.5 or 4. OpenSSL 4 on Linux:
             linux/Install-DevEnvironment.sh --openssl-source ppa|build (full project).
   "Latest Python" means the newest the package manager offers. A Python 3.10 or newer that already works is kept; -Force / --force installs or upgrades anyway.

4. THE PATH
   Windows   Looks for openssl.exe in the usual folders (FireDaemon OpenSSL, OpenSSL-Win64, Chocolatey) and python.exe (Program Files\Python3xx, %LOCALAPPDATA%\Programs\Python).
             Found but not on the PATH: its folder is added - for all users when you are Administrator (HKLM), else for you (HKCU). An OLDER openssl first on the PATH is overtaken:
             the new folder goes in front. The Microsoft Store "python" stub is not a Python and is overtaken too. This window is updated; other windows must be restarted.
   Linux     A newer openssl in a folder that is not on the PATH (for example /opt/openssl4/bin): the folder is put in front in /etc/profile.d/pki-openssl.sh (root) or ~/.profile.
   -NoPath / --no-path leaves the PATH alone. -Check / --check shows what would be added.

5. OPTIONS
   -Only All|OpenSsl|Python   -Manager Auto|Winget|Chocolatey   -Check   -Yes   -Force   -NoPath   -Help          (Windows)
   --only all|openssl|python                                   --check  --yes  --force  --no-path  --help      (Linux)
   Exit codes: 0 ok, 1 error, 4 something is still missing (OpenSSL below 3.0 / 4, Python not found, no package manager), 5 system not supported.

6. WHERE IT RUNS
   Windows 11 24H2+, Windows Server 2025 / 2022 (Windows PowerShell 5.1 or 7). Linux: Ubuntu 24+, CentOS Stream / RHEL / Rocky / Oracle Linux 10+, SLES / openSUSE 15+.
   Needs Internet access to the package source. It replaces Install-OpenSsl.ps1 / install-openssl.sh of 5.2.2.

7. NOT TESTED HERE
   Run on Linux only (Ubuntu 24.04: --check, a real --force --yes, a PATH test with a stripped PATH; the other distributions with --check and a fake os-release). Windows was run with a fake
   winget and PKI_FAKE_OS: the real winget / Chocolatey installs and the registry PATH change are untested. What to run on your machines: PKI-Acceptance-Checklists.txt, E32.
