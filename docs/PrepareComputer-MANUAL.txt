====================================================================================================
 1  WHAT THIS SCRIPT DOES
====================================================================================================
 The PKI tools are small scripts. They need some programs. Without them they stop with a message:

   - the certificate request maker (New-PkiCsr) needs OpenSSL
   - the helper scripts need Python 3
   - the backup and restore scripts need PowerShell 7, OpenSSL 4, Python 3, .NET SDK 8 and 10

 Prepare-Computer looks for each program, installs what is missing with the normal package manager
 of the system, and makes sure the program works in a NEW window. Run it once on a new computer.

====================================================================================================
 2  THE WORDS YOU NEED
====================================================================================================
 PATH           The list of folders where the system looks for programs. If a program is not on
                the PATH, typing its name says "not found", even when it is installed.
 Package manager  The system's installer: winget or Chocolatey (Windows), apt, dnf, zypper
                (Linux).
 winget         The Windows package manager from Microsoft.
 Chocolatey     Another Windows package manager (the second choice here).
 SDK            Software Development Kit. The .NET SDK builds and runs .NET programs.
 OpenSSL        The program that makes keys and certificates.
 Administrator  A PowerShell window started with "Run as administrator".
 sudo           Linux: run one command as the administrator.

====================================================================================================
 3  BEFORE YOU START
====================================================================================================
 - Internet access to the package source.
 - Windows: an Administrator window. Windows PowerShell 5.1 or PowerShell 7 both work for this
   script.
 - Linux: sudo, or root. The script calls sudo by itself.
 - A computer that is allowed: Windows 11 24H2 or newer, Windows Server 2025 and 2022. Linux:
   Ubuntu 24+, CentOS Stream / RHEL / Rocky / Oracle Linux 10+, SLES / openSUSE 15+. Others: exit 5,
   nothing is done. RHEL needs a registered subscription for its repositories.

 6  WHAT IT INSTALLS ON LINUX
====================================================================================================

 --------------------------------------------------  ----------------

                                                     python3-pip, python3-venv)

 or the .NET SDKs from this script.

====================================================================================================
 7  IS THE LATEST ALREADY THERE?
====================================================================================================
 "Latest Python" means the newest the package manager offers. On Windows, for PowerShell, each .NET
 SDK, OpenSSL and Python the script asks the package manager for the latest version (winget show
 --id <id> --exact; Chocolatey: choco search <name> --exact; Python: the highest Python.Python.3.x)
 and compares it with the installed one (three numbers, for example 4.0.3 against 4.0.2).

 Case                         What happens
 ---------------------------  --------------------------------------------------------------
 installed is the latest      "... is the latest version: nothing to install." Only the PATH is
 or newer                     checked.
 installed is older           "the latest version is x: it will be updated." It is updated. With
                              -Check it is only listed.
 not installed                It is installed.
 the latest cannot be read    An installed version that meets the minimum is kept (PowerShell 7,
                              SDK 8 and 10, OpenSSL 4, Python 3.10).

 -Force (Windows) or --force (Linux) installs or upgrades anyway. On Linux a Python 3.10 or newer
 that already works is kept.

====================================================================================================
 8  THE PATH
====================================================================================================
 Windows   The script looks for pwsh.exe (7 or newer), openssl.exe in the usual folders (FireDaemon
           OpenSSL, OpenSSL-Win64, Chocolatey) and python.exe (Program Files\Python3xx,
           %LOCALAPPDATA%\Programs\Python). The folder of dotnet.exe is added when it is missing.
           A program that is found but not on the PATH: its folder is added. For all users when you
           are Administrator (HKLM), else for you (HKCU).
           An OLDER openssl first on the PATH is overtaken: the new folder goes in front. The
           Microsoft Store "python" stub is not a Python and is overtaken too.
           This window is updated. Other windows must be restarted.
 Linux     A newer openssl in a folder that is not on the PATH (for example /opt/openssl4/bin): the
           folder is put in front in /etc/profile.d/pki-openssl.sh (root) or ~/.profile.

 -NoPath / --no-path leaves the PATH alone.

====================================================================================================
 9  LOOK FIRST (-Check / --check)
====================================================================================================
 .\Prepare-Computer.ps1 -Check        ./prepare-computer.sh --check
 It lists what is there, what would be installed and what would be added to the PATH. Nothing is
 changed. Do this on a computer you do not know.

====================================================================================================
 10  WHAT IT DOES NOT DO
====================================================================================================
 - It never touches certificates. If the PKI is already installed on the computer (Windows Local
   Machine store, Linux ca-certificates), nothing changes.
 - It does not install the PKI. For that use the trust kit (PkiTrustKit-MANUAL.txt).
 - It does not build OpenSSL from source (Install-DevEnvironment.sh does).

====================================================================================================
 14  PROBLEMS AND ANSWERS
====================================================================================================
 "openssl: not found" after the install
     Open a NEW window. The PATH is read when a window starts.
 Exit 4, OpenSSL below 4 (Windows)
     The Chocolatey package is old. Use winget (the default), or install FireDaemon OpenSSL 4.
 Exit 4, "no package manager"
     Install winget (App Installer from the Microsoft Store) or Chocolatey, then run again.
 Exit 4, Python not found
     Run again with -Force. Check the Internet access.
 Exit 5
     This computer is refused (section 3). Nothing was done.
 "python" opens the Microsoft Store
     That is the Store stub. The script overtakes it. Open a NEW window after the install.
 Linux: "Unable to locate package"
     The repositories are not set up (RHEL: no subscription). Fix the repositories, run again.
 Linux: OpenSSL is 3.0 and I need ML-DSA
     Use Install-DevEnvironment.sh --openssl-source ppa or build.

====================================================================================================
 15  LIMITS YOU MUST KNOW
====================================================================================================
 - It needs Internet access to the package source.
 - It installs what the package manager offers. If the package is old, the result is old.
 - Linux: no PowerShell and no .NET SDK from this script.
 - A Windows computer with no winget and no Chocolatey cannot be prepared by this script.
 - It replaces Install-OpenSsl.ps1 and install-openssl.sh of version 5.2.2.
