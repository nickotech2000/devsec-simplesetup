 READ THIS FIRST
----------------------------------------------------------------------------------------------------
 What it is   : A script that checks the CA request of another department and signs it with your
                Quadrant Root. That department can then run its own intermediate CA, and everything
                it issues chains to YOUR Enterprise Root.
 Who reads it : The OWNER of the PKI. No PKI knowledge is needed. Every new word is explained in
                GLOSSARY.txt and GLOSSARY-ENGLISH.txt.
 Time needed  : 10 minutes to read sections 1 to 5. A signing takes a few seconds.
 You need     : The ORIGINAL PKI from pki_setup.ps1 (a DevKit has no root key), PowerShell 7,
                OpenSSL 4, and the CA request (.csr) of the department.
 Start with   : Section 4 (Quick start).

====================================================================================================
 1  WHAT SIGNEXTERNALCA DOES
====================================================================================================
 A department wants its own CA. It makes its own CA key and a request (CSR) and sends you ONLY the
 CSR. SignExternalCa:

     DEPARTMENT                                   YOU (SignExternalCa)
     CA key (stays with them)
     dept-ca.csr   ------------------------->    1. checks the CSR against the rules
                                                  2. signs it with a Quadrant Root
     folder with CA certificate  <-------------   3. writes a folder with the result

 Nothing but the CSR comes in. No private key of yours goes out.

====================================================================================================
 2  THE WORDS YOU NEED
====================================================================================================
 CA request     A CSR for a CA certificate. It asks for CA:TRUE.
 Quadrant Root  A root of one PKI family. Q1 = Classic, not FIPS. Q2 = Classic, FIPS.
 Intermediate   A CA below a root. Here: the CA of the department.
 pathLen        pathLenConstraint. How many CA levels may be below a CA. 0 = it may sign only
                end-entity certificates (servers, people).
 Name constraint  A limit inside a CA certificate: the CA may issue only for some names.
 Level          DV, OV or EV. How much of the identity is checked.
 SAN, CN        Subject Alternative Name, Common Name.
 Revoke         Declare a certificate bad before its end date.

====================================================================================================
 3  BEFORE YOU START
====================================================================================================
 - The ORIGINAL PKI made by pki_setup.ps1, on this computer. A DevKit cannot do this job.
 - PowerShell 7 and OpenSSL 4.
 - The CA request. Ask the department to use New-PkiCsr.ps1 -CertificateType IntermediateCA.
 - Decide the level (OV, EV or DV). Check that the company is real before you sign OV or EV. The
   script cannot check that.
 - A computer that is allowed: Windows 11 24H2 or newer, Windows Server 2025 and 2022; Linux with
   PowerShell: Ubuntu 24+, CentOS Stream / RHEL / Rocky / Oracle 10+, SLES / openSUSE 15+. Others:
   exit 5, nothing is done.

====================================================================================================
 4  QUICK START
====================================================================================================
     .\SignExternalCa.ps1 -Csr .\dept-ca.csr -Check     read the report
     .\SignExternalCa.ps1 -Csr .\dept-ca.csr             sign

 The new folder is external-ca\dept-ca_<date>-<time>\. Send it to the department. It has no
 private key.

====================================================================================================
 5  THE STEPS IN DETAIL
====================================================================================================
 Step 1  Check only. -Check prints the report and signs nothing. Do it every time.
 Step 2  Read the report (section 8). Red ERROR = the department makes a new CSR.
 Step 3  Choose the options (section 16): -Level, -Fips, -Days, -PathLen, -PermitDns,
         -PermitEmail.
 Step 4  Sign. Run the command without -Check.
 Step 5  Send the folder. README.txt inside tells them what to do. Compare the fingerprint in
         ca-info.json with them if the channel is not trusted.

 Every run makes a NEW folder. Nothing is overwritten. .\SignExternalCa.ps1 -List shows the
 earlier requests.

====================================================================================================
 6  WHICH ROOT SIGNS
====================================================================================================
 Option        Root       Family
 ------------  ---------  --------------------------------
 (default)     q1-root    Classic, non-FIPS (Quadrant 1)
 -Fips         q2-root    Classic, FIPS (Quadrant 2)

 -Quadrant 1|2 does the same by number. Never an intermediate. Never a Quantum Quadrant Root.
 Never the Track or Enterprise Root: they sign your own CAs only. The DevKit holds issuing keys
 only, so a CA request can ONLY be signed here.

 A Quadrant Root has pathLenConstraint 1. So the department's CA sits next to your own
 intermediates and may issue end-entity certificates only (pathLen 0), unless you raise -PathLen.

====================================================================================================
 7  WHAT HIS REQUEST MUST CONTAIN
====================================================================================================
 Level (-Level)  Required in the subject
 --------------  ------------------------------------------------------------------------------
 OV (default)    C (2 letters), O, OU, CN. Recommended: ST, L. Allowed: street, postalCode, name,
                 emailAddress, telephoneNumber. Policies: OV + High Assurance + PEN.
 EV              Everything of OV, plus ST, L, serialNumber, businessCategory and jurisdictionC.
                 businessCategory is one of: Private Organization, Government Entity,
                 Business Entity, Non-Commercial Entity. Recommended: jurisdictionST, postalCode.
                 Validity 397 days at most.
 DV              CN. Any other field is dropped (WARN).

 Key: RSA 4096 or 8192, or ECDSA P-384 or P-521. P-256, RSA 2048 or 3072, Ed25519 and ML-DSA are
 refused: this is a Classic CA.
 Signature of the CSR: valid, SHA-256 or stronger.
 The CN must not be the name of one of YOUR CAs (SUBJ-OUR-CA).
 Kind of request (-CsrType, default Auto): CA:TRUE = a CA request. A request for a server (names,
 no CA:TRUE) is refused with the command to use (SignCsr.ps1). A hand-made CA request without
 CA:TRUE is accepted as a CA request.

====================================================================================================
 8  READ THE REPORT
====================================================================================================
 Colour    Meaning
 --------  ----------------------------------------------------------------------------------
 ERROR     red. The CSR breaks a rule. Nothing is signed. Exit code 2.
 WARN      yellow. Allowed, but something was changed or dropped. -Strict makes it ERROR.
 OK        green. Passed.
 INFO      cyan. A fact.

 Each line names the field, says what is wrong and gives the fix, with a code in [ ]. The codes
 are the same as in SignCsr-MANUAL.txt section 12 (KEY-*, SUBJ-*, EXT-*, VAL-EV). Plain text:
 -NoColor or NO_COLOR.

====================================================================================================
 9  WHAT YOU GET
====================================================================================================
 A new folder:  external-ca\<name>_<yyyyMMdd-HHmmss>\

 File                  What it is
 --------------------  ----------------------------------------------------------------------
 <name>.csr            His request, unchanged.
 <name>.crt            HIS CA CERTIFICATE, signed by you.
 <name>-fullchain.crt  His certificate + your chain, up to but not including the Enterprise
                       Root. This is the chain for HIS certificates.
 <name>-chain.crt      Your chain only.
 root.crt              Your Enterprise Root (the trust anchor).
 our-ca-bundle.crt     Chain + root.
 ca-info.json          Signer, subject, key, dates, serial, fingerprint, constraints, the
                       verification result.
 README.txt            What the department does next.

 The certificate is written in the index.txt of the signing root. So you can revoke it:
 PkiRevocation.ps1 -Action Revoke (PkiRevocation-MANUAL.txt). It is then in the CRL.

====================================================================================================
 10  WHAT THE CA CERTIFICATE CONTAINS
====================================================================================================
 basicConstraints CA:TRUE (critical) with pathLenConstraint (-PathLen, default 0)
 keyUsage         keyCertSign, cRLSign
 Name constraints (critical), when you give -PermitDns or -PermitEmail
 Policies, CRL and OCSP addresses of the signing root, key identifiers
 Subject          the subject of the request, in its order
 Validity         -Days (default 1825 = 5 years; EV 397), cut to what the signer still has

====================================================================================================
 11  LIMITS OF HIS CA
====================================================================================================
 -PathLen 0..3 sets how many CA levels may be below his CA. It is limited to the signer's pathLen
 minus 1. With the default 0 his CA may issue only servers, people and programs. The department
 cannot make another CA below it.
 -Force issues even when the signer has pathLenConstraint 0. For a lab only.

====================================================================================================
 12  NAME CONSTRAINTS
====================================================================================================
 You can limit the names that his CA may ever issue. The limit is inside the certificate and is
 critical: clients enforce it.
   -PermitDns example.internal         DNS names under example.internal only
   -PermitEmail @example.internal      e-mail addresses of that domain only
 Several values with commas. Use this whenever you can. A department CA without limits can issue a
 certificate for any name, also names that are not theirs.

====================================================================================================
 13  RECIPES, COPY AND PASTE
====================================================================================================
 OV, Q1, five years:        .\SignExternalCa.ps1 -Csr .\dept-ca.csr
 FIPS, limited to a domain: .\SignExternalCa.ps1 -Csr .\dept-ca.csr -Fips -PermitDns dept.internal
                                -Days 3650
 Would EV be accepted?      .\SignExternalCa.ps1 -Csr .\dept-ca.csr -Level EV -Check
 A name for the folder:     .\SignExternalCa.ps1 -Csr .\dept-ca.csr -Name dept-issuing-g1
 Earlier requests:          .\SignExternalCa.ps1 -List
 How the department makes the CSR (New-PkiCsr.ps1 is easier):
     openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:4096 -out dept-ca.key
     openssl req -new -key dept-ca.key -sha384 -out dept-ca.csr \
         -subj "/C=EE/ST=Harju/L=Tallinn/O=Dept Ltd/OU=IT Department/CN=Dept Issuing CA G1"
     (EV adds /serialNumber=12345678/businessCategory=Private Organization/jurisdictionC=EE)
 They keep dept-ca.key. They send only dept-ca.csr.

====================================================================================================
 14  PROBLEMS AND ANSWERS
====================================================================================================
 "the request is not a CA request: nothing was signed"
     The CSR is for a server (exit 2). Use SignCsr.ps1. The reverse also works: SignCsr refuses a
     CSR with CA:TRUE and names this script.
 Exit code 2
     Read the report. The department makes a new CSR, or choose another -Level.
 "pathLenConstraint" error
     The signer cannot sign a CA. Use a Quadrant Root (default), or -Force in a lab.
 "SUBJ-OUR-CA"
     The CN is the name of one of your CAs. They choose another CN.
 "The signing CA 'q2-root' does not exist in this PKI"
     You gave -Fips, but the PKI was built without Quadrant 2. The message lists the roots that
     exist. Build with pki_setup.ps1 -Quadrant 1,2,3,4, or sign without -Fips.
 A DevKit says it cannot sign a CA
     That is correct. Do it on the original PKI.
 Exit code 5
     This computer is refused (section 3). Nothing was done.

====================================================================================================
 15  LIMITS YOU MUST KNOW
====================================================================================================
 - Only Classic CAs. No ML-DSA CA is signed here.
 - Only a Quadrant Root signs. Never an intermediate.
 - The script does not check that the company is real. You must.
 - The department's CA key is as dangerous as a root key. Tell them: offline, or in an HSM.
 - Your own revocation list (CRL) must be copied to the server after a revoke (PkiRevocation).

====================================================================================================
 16  ALL OPTIONS
====================================================================================================
 -Csr <file>                       His PKCS#10 request (PEM). Required.
 -CsrType Auto|Leaf|IntermediateCA Kind of request. Default Auto.
 -Level DV|OV|EV                   Default OV.
 -Fips   -Quadrant 1|2             Which root signs.
 -Name <text>                      Folder and file name. Default: his CN.
 -Days <n>                         Default 1825. EV 397.
 -PathLen 0..3                     Default 0.
 -PermitDns <a,b>   -PermitEmail <a,b>   Name constraints.
 -OutFolder <path>                 Default external-ca\ next to the pki folder.
 -Check   -Strict   -NoColor   -Force   -List   -Unblock
 -Pki <name>   -Release <n>   -NoCaRevocationInfo   -PkiRoot <folder>
 -ConfigFile   -OpenSslPath   -FipsModuleConfig   -Verbose   -Help
 Exit codes: 0 ok, 1 error, 2 the CSR breaks a rule, 5 this system is refused.
