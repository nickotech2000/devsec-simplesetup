====================================================================================================
 1  WHAT THE TRANSPORT DOES
====================================================================================================
 The PKI from pki_setup.ps1 lives on one computer. Your other computers must trust it. The
 transport carries it there:

     SOURCE (the computer with the pki folder)          DESTINATION (the other computers)

     PkiTransport.ps1 -Pack  --->  name.certpacked  --->  Windows : PkiTransport.ps1 -Install
                                   (one encrypted        any OS   : Unpack-PkiTransport.ps1
                                    file + password)     Linux    : pki-transport.sh

 There are three scripts:

 Script                     Where     Job
 -------------------------  --------  -----------------------------------------------------------
 PkiTransport.ps1           Source    -Pack makes the package. -DevKit, -Server and others make
                                      special zips.
                            Windows   -Install checks the computer, unpacks and installs the trust.
 Unpack-PkiTransport.ps1    Any       Only unpacks. Installs nothing.
 pki-transport.sh           Linux     Checks, prepares, unpacks and installs the trust in the
                                      system store.

 With -Kit, -Pack also writes a small folder (<name>-kit) with the scripts, so that the destination
 needs nothing else.

====================================================================================================
 2  THE WORDS YOU NEED
====================================================================================================
 Package        The .certpacked file. It is an archive with a password.
 Source         The computer that holds the PKI. You pack here.
 Destination    The computer that receives the package.
 Trust          Put the root CAs into the computer, so that programs accept your certificates.
 Root, intermediate   The CAs at the top and the CAs below them. Roots go to the "Trusted Root"
                store. Intermediates go to the "Intermediate" store.
 Scope          What the package holds: only public CA certificates, or also private keys.
 SHA-256        A fingerprint of a file. If one byte changes, it changes.
 AES-256        A strong way to encrypt. The package uses it.
 Full list      GLOSSARY.txt and GLOSSARY-ENGLISH.txt.

 3  BEFORE YOU START
====================================================================================================
 SOURCE
   1. The PKI exists (pki_setup.ps1 was run, folder .\pki).
   2. PowerShell 7.
   3. A way to send the file, and ANOTHER way to send the password.

 DESTINATION (the scripts refuse other systems with exit code 5)
   Windows   : Windows 11 24H2 or newer, Windows Server 2025, Windows Server 2022. Windows Server
               2022 gets the Classic CAs only (no post-quantum CAs). Administrator rights are
               needed for -Install.
   Linux     : Ubuntu 24+, CentOS Stream 10+, RHEL 10+, Rocky 10+, Oracle Linux 10+, SUSE Linux
               Enterprise 15+, openSUSE. root or sudo for the system store.
   Not supported: Windows 10, older Windows 11, macOS and the special editions.
   Unpack-PkiTransport.ps1 needs only PowerShell 7 and runs on the same systems.
   OpenSSL 4.0.1 or newer is needed to prove the chains. 7-Zip is needed only for 7z packages (and
   for AES-256 zips on Linux). The scripts can install both (section 12).

====================================================================================================
 4  QUICK START
====================================================================================================
 1. SOURCE. Make the package:
        .\PkiTransport.ps1 -Pack -GeneratePassword -Kit
    The password is shown ONCE at the end. Write it down.
    Without other options the package holds EVERY CA of every company and every release (7.9.1).
    -Pki, -Release, -Latest, -PkiFolder and -Ca take only a part (section 11).
 2. Copy the .certpacked and the <name>-kit folder to the destination. Send the password another
   way.
 3. DESTINATION, Windows (PowerShell 7 as administrator, in the kit folder):
        .\PkiTransport.ps1 -Check                                      the scan only
        .\PkiTransport.ps1 -Install -Package ..\name.certpacked        scan, unpack, install
    DESTINATION, Linux:
        sudo ./linux/pki-transport.sh --package name.certpacked --yes
    DESTINATION, only unpack, any computer:
        .\Unpack-PkiTransport.ps1 -Package ..\name.certpacked -Extract roots
 4. Test: open a page with a certificate from your PKI. The browser must show no warning
    (Firefox has its own store: import the root there).

====================================================================================================
 5  MAKE A PACKAGE (-Pack)
====================================================================================================
 .\PkiTransport.ps1 -Pack [options]
 The PKIs are read from .\pki: by default EVERY PKI folder there (every company, every release,
 normal and NoCR). Section 11 shows how to take only a part. Leaf certificates are read from
 .\leafcerts.

 WHAT IS IN THE PACKAGE (the scope; certpack.json says which)

 Scope                       Option             Contains                          Private keys
 --------------------------  -----------------  --------------------------------  ---------------
 CA certificates (default)   (none)             Roots, intermediates, chains,     none
                                                bundles, CRLs
 + leaf certificates         -IncludeLeafCerts  The leafcerts folders             leaf keys
 + CA keys                   -IncludeCaKeys     The PKI folders                   the CA keys (*)
 + issuing CA keys           -IssuingKeysOnly   The PKI folders                   intermediates
                                                                                  only, no root
 DevKit                      -DevKit            See DevKit-MANUAL.txt             issuing CAs only
 (*) Without -Ca: every key of the folder. With -Ca: only the keys of the CAs you chose (and of the
     CAs below a chosen root). A parent that is only there to complete the chain never gives its
     key. -IssuingKeysOnly never packs a root key, an OCSP / time stamp key or a .pfx.

 Files in the archive: certpack.json and certpack.tsv (the list), SHA256SUMS, README.txt, and for
 every PKI folder (pki-default-01, pki-raksaka-01 ...):
   ca\roots\<folder>-<slug>.crt           ca\intermediates\<folder>-<slug>.crt
   ca\chains\<folder>-<slug>-fullchain.crt ca\publish\<folder>\*     (CRLs, published files)
   ca\external\<folder>-external-chain.pem and ca\cross-sign\<folder>-*   (a root signed by a
                                                                           public CA)
   pki\<folder>\*                           (-IncludeCaKeys / -IssuingKeysOnly)
 and once: ca\ca-bundle-roots.crt, ca\ca-bundle-all.crt (the CAs of ALL packed PKIs), leafcerts\*.
 certpack.json lists the PKIs (pkis) and gives every CA its company (pki) and folder (release).
 The DevKit package (7.9.8) uses the same layout: every PKI of the kit in pki\<folder>\.

 FORMATS. A .certpacked IS an archive under another name. Rename it to .zip or .7z and 7-Zip opens
 it with the password. The scripts read the first bytes, never the extension.

 Kind                     Made by                       Needs at the destination
 -----------------------  ----------------------------  ----------------------------------------
 zip + AES-256 (default)  PkiTransport.ps1 itself       Windows: nothing. Linux: 7-Zip (installed
                                                        for you).
 zip + ZipCrypto          the same (-ZipEncryption      Plain unzip. WEAK. Only for packages
                          ZipCrypto)                    WITHOUT private keys.
 7z + AES-256             7-Zip (-ArchiveFormat 7z)     7-Zip on both sides. Smaller. File names
                                                        are encrypted too.

 OPTIONS
   -Out <file>           Default .\transport\<name>-<yyyyMMdd-HHmmss>.certpacked: allpki (every
                         CA), agantra-pki (one company), agantra-raksaka-pki (two or three),
                         multipki (more). The extension is always .certpacked.
   -GeneratePassword     A 20-character password, shown once at the end.
   -PackagePassword <t>  Your own password (alias -Password). Also: PKI_TRANSPORT_PASSWORD, or a
                         prompt (asked twice).
   -ArchiveFormat zip|7z     -ZipEncryption Aes256|ZipCrypto     -SevenZipPath <exe>
   -IncludeLeafCerts [-LeafName a*,b]   Add the leafcerts folders (all, or those that match).
   -IncludeCaKeys        Add the PKI folders with the CA private keys. Only for a machine that
                         must issue certificates. With -Ca: the keys of the chosen CAs only.
   -IssuingKeysOnly      Like -IncludeCaKeys, but only the keys of the intermediate (issuing) CAs.
   -Pki -Release -Latest -NoCaRevocationInfo -PkiFolder -PkiRoot -Ca -AllCa -ListCa
                         Which PKIs and which CAs: section 11.
   -Kit                  Also write <name>-kit\ : the three scripts, the modules, the bootstrap
                         scripts, the CSR tools, Create-WebServerConfig, the manuals and
                         RUN-SCRIPTS-WINDOWS.txt. Never a generator, SignCsr or Sign-Code.
   -Comment <text>       Stored in the package, shown when it is opened.
   -NoVerify             Do not read the package back after writing.
 After writing, the script reads the package back (every entry is decrypted and authenticated).

 SAFEGUARDS
   * Every file has its SHA-256 in the package. The destination checks ALL of them before it writes
     anything. One changed byte stops the unpack.
   * A wrong password writes nothing. A name inside the archive that tries to leave the destination
     (../..) is refused.
   * ZipCrypto is refused for a package with private keys.
   * -Pack prints the SHA-256 of the package. Compare it after the transfer.
   * Send the package and the password by different ways. A package with private keys is as
     sensitive as the keys. Delete it and the extracted keys when the job is done.

====================================================================================================
 6  PASSWORDS
====================================================================================================
 A package password has these rules:
   * Printable ASCII only. At least 12 characters. At least 3 of 4: lower case, upper case, digits,
     symbols.
   * -AllowWeakPassword relaxes the length and the classes. Never the ASCII rule.
   * -GeneratePassword makes 20 characters without quotes, $, ! or backslash, so it pastes safely
     into any shell.

 Where to put the password at the destination, safest first:
   1. The prompt (not shown on screen).
   2. A file: --password-file (Linux scripts only).
   3. The variable PKI_TRANSPORT_PASSWORD.
   4. -PackagePassword / --password. Visible in the process list and the shell history.

====================================================================================================
 7  WINDOWS: SCAN AND INSTALL
====================================================================================================
 .\PkiTransport.ps1 -Check [-Package <file>]   The scan. With -Package also: does the password open
                                               the file?
 .\PkiTransport.ps1 -Install -Package <file>
 The scan, then (only if it passes) unpack and install.

 THE SCAN. Nothing is unpacked or installed unless all of it passes.

 Check       Rule
 ----------  -----------------------------------------------------------------------------------
 Windows     Windows 11 24H2 (build 26100) or newer, Server 2025 or Server 2022. Others: the reason
             is printed and the script stops (exit code 2 or 5).
 OpenSSL     4.0.1 or newer. Missing: it is installed when you agree or give -InstallMissing,
             otherwise the script stops (exit code 4). -SkipOpenSslCheck goes on anyway.
 Elevation   An administrator PowerShell. Checked BEFORE anything is unpacked.
 Also shown  The PowerShell version, and whether 7-Zip exists (only a 7z package needs it).

 WHAT -Install DOES, IN ORDER
   1. Opens the package and checks the SHA-256 of every file.
   2. Writes the selection (-Extract, default ca) to -Destination
      (default .\certpacked-received\<package name>). -Pki, -Release, -PkiFolder and -Ca choose
      some of the PKIs of the package (default: all of them; section 11).
   3. REPLACE: for each PKI that is installed, the OLDER copy of exactly that PKI is removed from
      Trusted Root and Intermediate first. Only certificates PROVEN to be ours go (section 11).
      -KeepOld leaves them.
   4. Puts every ROOT in Trusted Root Certification Authorities and every INTERMEDIATE in
      Intermediate Certification Authorities. The stores are read back. A wrong placement is an
      error. What was installed is written to %ProgramData%\PkiTransport\installed.tsv.
   5. -InstallLeafPfx: imports the leaf PFX files into LocalMachine\My (the leaf only). -PfxPassword
      is their password (default Abc12345!).
   6. OpenSSL 4 proves that every CA and every extracted leaf chains to the roots (ML-DSA too).

 Remove the trust again:   .\PkiTransport.ps1 -RemoveTrust -Package <file> [-Pki x] [-Release n]
 (By the thumbprints of the package only. The leaf PFX files in My stay.)
 Exit codes: 0 done, 1 error, 2 Windows not supported, 3 not Windows (use pki-transport.sh),
 4 OpenSSL 4.0.1+ missing, 5 this system is refused.
 To see the exit code use  pwsh -File .\PkiTransport.ps1 ...  ("pwsh -Command" shows only 0 or 1).
 Scripts blocked, or Windows Sandbox (no PowerShell 7, no winget)? Free one window only:
     Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
     pwsh -NoProfile -ExecutionPolicy Bypass -File .\PkiTransport.ps1 -Install -Package <file>
 All steps, also Install-DevEnvironment for pwsh in a Sandbox: RUN-SCRIPTS-WINDOWS.txt (in the
 kit and in docs\).

====================================================================================================
 8  UNPACK ONLY (ANY COMPUTER)
====================================================================================================
 .\Unpack-PkiTransport.ps1 -Package <file> [-Extract <list>] [-LeafName <w>] [-Destination <folder>]
                           [-Pki <a,b>] [-Release <n | folder>] [-Ca <list>] [-List] [-Force]

 It installs NOTHING and touches no certificate store. Use it to get the files, for example for a
 server that reads a CA file.
 * Default destination: .\certpacked-received\<package name>. certpack.json and README.txt are
   always written.
 * Identical files that already exist are left alone. A different file stops the run unless -Force.
 * -List shows the PKIs of the package (company, PKI folder, number of CAs), then every CA with its
   company, folder, kind and id. It writes nothing.
 * A package can hold many PKIs. All are unpacked, each in its own names (section 5). Choose some:
     -Pki raksaka                       one company (several: -Pki agantra,raksaka)
     -Release 2                         release 2 of each company (normal and NoCR)
     -Release pki-default-nocr-01       exactly this PKI folder (wildcards: 'pki-default-*')
     -Ca q1-root                        this root and every CA below it, plus its parents
     -Ca '*OV*'                         every CA whose id, slug or name matches, plus its parents
   The bundles and the leaf certificates are always written. -Ca chooses CA certificates and chains;
   the CRLs and the pki\<folder> files of a chosen PKI are written whole.
 * -Extract pki also rewrites the absolute paths in the manifest and the CA settings to the new
   place (each PKI folder: pki\<folder>). Then  GenerateLeafCertificate.ps1 -PkiRoot <folder>\pki
   can issue from the moved PKI.
 * A wrong password, a damaged or a changed file: it says so and writes nothing.

====================================================================================================
 9  LINUX: pki-transport.sh
====================================================================================================
 ./linux/pki-transport.sh --package <file> [options]

 It does these four things, and nothing else:
   1. SCAN     platform, privileges (root or sudo), OpenSSL 4.0.1+, 7-Zip, unzip, store tools.
   2. PREPARE  installs what is missing (ca-certificates, 7-Zip; OpenSSL 4 with your consent).
   3. UNPACK   asks for the password, checks every SHA-256, writes the selection.
   4. INSTALL  puts the CA certificates in the system store and proves the chains with OpenSSL 4.

 SYSTEM STORES

 Family                                   Anchors go to                       Store command
 ---------------------------------------  ----------------------------------  ---------------------
 Ubuntu                                   /usr/local/share/ca-certificates    update-ca-certificates
 CentOS Stream, RHEL, Rocky, Oracle       /etc/pki/ca-trust/source/anchors
 update-ca-trust extract
 SUSE Linux Enterprise, openSUSE          /etc/pki/trust/anchors              update-ca-certificates
 Another Linux                            --store-dir DIR                     --update-cmd CMD

 The family is read from /etc/os-release. The files it adds are named agantra-pki-* (for a package
 with several PKIs: agantra-pki-<folder>-<slug>.crt), so --remove-trust takes out exactly those.
 What it placed is written to /var/lib/pki-transport/installed.tsv (company, PKI folder, file,
 SHA-1 thumbprint).

 SEVERAL PKIs, AND THE OLDER COPY (7.9.1)
   --pki LIST        only these companies (agantra,raksaka)
   --release LIST    release numbers (2) or PKI folders (pki-raksaka-01, 'pki-default-*')
   --ca LIST         CAs by id, slug or common name (wildcards): a root brings every CA below it,
                     any CA brings its parents
   --keep-old        do not remove the older copy
   Before the new files go in, the older copy of each chosen PKI is removed: the files that
   pki-transport.sh (its list, checked against the thumbprint inside the file) or a trust kit (its
   list, file pki-<company>-*) put there for EXACTLY that company and PKI folder. Never a file
   because of its name. Public CAs and other PKIs stay. Section 11.

 WHICH CAs GO IN (--trust)
   roots (default)   every root: Enterprise, Track and Quadrant roots. A Linux store has one kind of
                     anchor, so every root goes in.
   enterprise        only the Enterprise Root. Servers must then send the whole chain.
   all-ca            roots and intermediates.
   none              install nothing (same as --no-trust).
 An Enterprise Root signed by a public CA is not installed as an anchor on Linux.

 USEFUL SWITCHES
   --yes             Do not ask. Install what is missing. Needed when there is no terminal.
   --dry-run         Print every system-changing command instead of running it.
   --destdir DIR     Put the anchors under DIR and do not rebuild the store (image builds).
   --check           The scan only.
   --list            What is inside. Nothing is written.
   --remove-trust    Take the CAs out (with --package: exactly that package's, checked by
                     thumbprint; --pki / --release / --ca choose a part).
 Exit codes: 0 done, 1 error, 2 platform not supported, 4 OpenSSL missing, 5 wrong password (or this
 system is refused), 6 a prerequisite could not be installed.
 OpenSSL 4 missing: --install-openssl builds a FULL OpenSSL 4.0.3 from the official release into
 /opt/openssl-4.0.3 (the system openssl is not replaced). It takes about 5 minutes on 8 cores and
 over an hour on one core.

 10  PACKAGES FOR SERVERS
====================================================================================================
 PkiTransport.ps1 makes more than the .certpacked. Each mode writes a zip to .\transport\.

 Mode                  Package                              For
 --------------------  -----------------------------------  ------------------------------------
 -DevKit               agantra-pki-devkit-<date>.zip        Developers. See DevKit-MANUAL.txt.
 -CrlServer            agantra-pki-crl-server-<date>.zip    CRL and CA certificates only.
 -CrlOcspServer        agantra-pki-crl-ocsp-server-...zip   CRL and OCSP, no time stamping.
 -TimestampServer      agantra-pki-timestamp-server-...zip  Time stamp server (RFC 3161) only.
 -Server               agantra-pki-server-<date>.zip        CRL, OCSP and time stamping.

 The server modes run New-PkiServerPackage.ps1. Rules:
   * No password. The package holds nothing secret and NO private key. The script opens the package
     again and scans it. One private key inside = the package is deleted (exit 5).
   * The modes cannot be combined with each other. -IncludeServiceKeys (the OCSP and time stamp
     keys) is a LAB option. -CrlServer and -TimestampServer refuse it. A CA key is never packed.
   * Options: -Out <file.zip>  -Force  -Tar (also a .tar.gz)  -Release  -NoCaRevocationInfo
     -PkiRoot.
 On the Ubuntu 24.04 / 26.04 server:

     unzip agantra-pki-crl-server-*.zip
     sudo ./linux/pki-server/pki-server.sh install --crl-only --source ./pki
     ./linux/pki-server/pki-server.sh dns          the hosts-file lines or router DNS records

 For OCSP and time stamping the keys are made ON the server and signed on the CA machine:
     sudo ./linux/pki-server/pki-server.sh csr --no-tsa --source ./pki --out ./csr
     (sign) PkiRevocation.ps1 -Action SignCsr -For Ocsp          (time stamping: -For Tsa -Ca <ca>)
     sudo ./linux/pki-server/pki-server.sh import-cert --cert ./signed/ocsp-<ca>.crt
     sudo ./linux/pki-server/pki-server.sh install --no-tsa --source ./pki
 Use --tsa-only for the time stamp server, and no flag for all three. A new CRL: run
 PkiRevocation.ps1 -Action NewCrl, build the package again, copy it, unzip it, and run
  pki-server.sh update --crl-only --source ./pki .
 The CRL and certificate addresses are the ones in the certificates, for example
 http://crl.nextmantra.internal/<ca>.crl. Full steps: PKI-SERVER-MANUAL.txt.

====================================================================================================
 11  WHICH PKIs GO IN, WHAT IS REPLACED
====================================================================================================
 A. WHICH PKIs AND CAs GO INTO A PACKAGE (source, -Pack)
 Since 7.9.1 one package can hold MANY PKIs: several companies, several releases, NoCR and normal.
 Without any of the options below, -Pack takes EVERY CA of every company and every release that is
 built in .\pki (the same as -AllCa). The options take a part; they can be combined:

 Option                         Takes
 -----------------------------  ------------------------------------------------------------------
 (none)  or  -AllCa             every PKI folder in .\pki: every company, every release, NoCR too
 -Pki raksaka                   one company. Several: -Pki agantra,raksaka
 -Pki D:\cfg\raksaka_pki.cnf    the company of that configuration file (the name of the file
   (also -ConfigFile <file>)    says which: <name>_pki.cnf). Its PKI folders are in .\pki.
 -Release 2   -Release 1,3      these release numbers (of each chosen company)
 -NoCaRevocationInfo            only the NoCR family
 -Latest                        only the latest release of each company
 -PkiFolder pki-raksaka-01      exactly these PKI folders of .\pki (several: comma)
 -PkiRoot D:\other\pki-x-01     exactly these PKI folders, anywhere
 -Ca q1-root                    a root (Enterprise, Track or Quadrant root): it and every CA below
                                it, plus its parents
 -Ca q1-dv  -Ca '*OV*'          these CAs (id, slug or common name; wildcards), plus their parents.
                                A chain is always complete.
 -IncludeCaKeys / -IssuingKeysOnly   with the private keys (section 5); without them: no key.
 -ListCa                        shows the PKIs and their CAs (+ = would be packed). Packs nothing.

 Examples
   .\PkiTransport.ps1 -Pack -GeneratePassword                          every CA, no key
   .\PkiTransport.ps1 -Pack -Pki raksaka -Latest                       the newest raksaka PKI
   .\PkiTransport.ps1 -Pack -Pki agantra -Release 2 -Ca q2-root        release 2, the Q2 tree only
   .\PkiTransport.ps1 -Pack -PkiFolder pki-default-nocr-01 -IssuingKeysOnly
   .\PkiTransport.ps1 -Pack -Pki raksaka -Ca q1-root -ListCa           look before packing
 -DevKit (7.9.8) takes EVERY PKI by default too, with the same choices (-Pki, -Release, -Latest,
 -NoCaRevocationInfo, -PkiFolder, -PkiRoot, -Ca, -ListCa); see DevKit-MANUAL.txt section 4.
 The server packages still take ONE PKI: the latest release of -Pki (default agantra), or
 -Release / -NoCaRevocationInfo / -PkiRoot.
 Settings for all runs: pki_tools.cnf has TransportFolder, ArchiveFormat and ZipEncryption.
 See pki_setup-MANUAL.txt, section 9.

 B. READING A PACKAGE (destination)
 PkiTransport.ps1 -Install / -List / -RemoveTrust, Unpack-PkiTransport.ps1 and pki-transport.sh
 read every PKI of a package: several roots, several intermediates, several companies, several
 releases. All of them are used unless -Pki / -Release / -PkiFolder / -Ca (pki-transport.sh:
 --pki / --release / --ca) choose some. Packages made before 7.9.1 (one PKI) are read as before:
 their PKI is named from the folder they were made from.

 C. REPLACING THE OLDER COPY, AND WHAT IS NEVER TOUCHED
 When a PKI of the package is installed, its OLDER copy is removed first, then the new certificates
 go in. "Older copy" means: the same company AND the same PKI folder (for example pki-raksaka-01
 that was built again). Another release of the same company is another PKI: it stays.
 A certificate in a store is removed ONLY when it is PROVEN to be ours:
   Windows  its SHA-1 thumbprint is in the list of what PkiTransport installed
            (%ProgramData%\PkiTransport\installed.tsv) or a trust kit installed for the computer
            (%ProgramData%\PkiTrustKit\installed.tsv), for that company and PKI folder; or it is a
            certificate file of that PKI folder on this computer (.\pki\<folder>).
   Linux    the file is in the list of pki-transport.sh (/var/lib/pki-transport/installed.tsv) and
            still holds the certificate with that thumbprint, or a trust kit listed it
            (/var/lib/pki-trust-kit/installed.tsv, file pki-<company>-*).
 NEVER removed, for any reason:
   * a certificate of a public CA (DigiCert, GlobalSign, Microsoft, Let's Encrypt ...);
   * a certificate of another company's PKI, or of any private PKI that is not yours;
   * a certificate that only has the same NAME as one of yours (a name is never proof);
   * a certificate of the package itself (it is kept, not installed twice);
   * on Linux, a file that has our name but holds another certificate.
 A computer that got the PKI from a version before 7.9.1 has no such list yet: nothing is removed
 there (the log says so). Remove the old copy once with -RemoveTrust -Package <the old package>
 (exactly its thumbprints), or with pki_setup.ps1 / the trust kit remove scripts. From then on
 every install remembers what it put in, and the next package replaces exactly that.
 -KeepOld (Windows) / --keep-old (Linux): remove nothing, only add.

 12  WHAT IS INSTALLED FOR YOU
====================================================================================================
 The transport needs three programs. When one is missing, the scripts install it.

 Program                 Needed for                  Windows                        Linux
 ----------------------  --------------------------  -----------------------------  ---------------
 OpenSSL 4.0.1+ (ready)  The scan, the chain proof   -InstallMissing, or answer
 --install-openssl
                         (ML-DSA too)                yes. Uses                      (a full build)
                                                     Install-DevEnvironment.ps1
                                                     -Only OpenSSL.
 7-Zip                   A 7z package; on Linux an   -InstallMissing (winget        asks, or --yes
                         AES-256 zip                 7zip.7zip)

 "Ready" OpenSSL means: the FIPS module, ML-DSA and ML-KEM are present. A stripped build is NOT

 13  RECIPES, COPY AND PASTE
====================================================================================================
 Trust only, for many Linux or Windows machines
     .\PkiTransport.ps1 -Pack -GeneratePassword -Kit
     then on each:  sudo ./linux/pki-transport.sh --package <file> --yes

 A service identity for one VM
     .\PkiTransport.ps1 -Pack -IncludeLeafCerts -LeafName api.example.com -GeneratePassword
     ./linux/pki-transport.sh --package <file> --extract ca,leafcerts --leaf 'api*' --no-trust

 A build computer that issues certificates
     .\PkiTransport.ps1 -Pack -IncludeCaKeys -IncludeLeafCerts -GeneratePassword
     .\Unpack-PkiTransport.ps1 -Package <file> -Extract pki -Destination D:\pki-build
     .\GenerateLeafCertificate.ps1 -PkiRoot D:\pki-build\pki -DnsName x.example.com

 A smaller package
     .\PkiTransport.ps1 -Pack -ArchiveFormat 7z -GeneratePassword

 No 7-Zip anywhere, CA certificates only
     .\PkiTransport.ps1 -Pack -ZipEncryption ZipCrypto -GeneratePassword      (then unzip -P works)

 Every company and release in one file; each machine takes what it needs
     .\PkiTransport.ps1 -Pack -GeneratePassword
     .\PkiTransport.ps1 -Install -Package <file> -Pki raksaka           (Windows: raksaka only)
     sudo ./linux/pki-transport.sh --package <file> --release 2 --yes    (Linux: release 2 only)

 A newer copy of the same PKI (built again): install the new package; the old copy goes by itself
     .\PkiTransport.ps1 -Install -Package <new file>

 Take the CAs out again
     .\PkiTransport.ps1 -RemoveTrust -Package <file>
     sudo ./linux/pki-transport.sh --package <file> --remove-trust

 Look inside, write nothing
     .\Unpack-PkiTransport.ps1 -Package <file> -List
     ./linux/pki-transport.sh --package <file> --list

 Image build (Dockerfile, VM template)
     ./linux/pki-transport.sh --package <file> --destdir /target --yes
     then run update-ca-certificates in the image

 Developers get one zip
     .\PkiTransport.ps1 -DevKit -GeneratePassword

====================================================================================================
 15  LIMITS YOU MUST KNOW
====================================================================================================
 * 7-Zip receives the password as an argument. It is visible in the process list while it runs. The
   default zip engine of the script has no such process.
 * A package with private keys is only as safe as its password and its handling.
 * The ZipCrypto zip is weak. Use it only without private keys.
 * An Enterprise Root signed by a public CA is not installed as an anchor on Linux.
 * Windows Server 2022 gets no post-quantum CAs. Older Windows is refused instead of installing half
   of the PKI.
 * macOS is refused since version 5.0.0. The macOS code paths in pki-transport.sh are not reachable.
 * The trust is installed per computer. Firefox, Java and some containers have their own stores.
