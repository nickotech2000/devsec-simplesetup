====================================================================================================
 1  WHAT THE BACKUP DOES
====================================================================================================
 Your PKI is only files: the CA keys and certificates in pki\, the leaf certificates in
 leafcerts\, and the company settings (<company>_pki.cnf). If the disk dies, the PKI is gone. No
 PKI means no way to sign, revoke or renew.

     PKI computer                      other disk or computer              new computer
     Backup-Pki.ps1  ---- zip ---->    keep the zip safe  ---- zip ---->   Prepare-Computer.ps1
     (asks a password)                 Test-PkiBackup.ps1 (now and then)   Test-PkiBackup.ps1
                                                                           Restore-Pki.ps1

 The backup is ONE password-protected file (a .certpacked, AES-256, the same format as the
 transport file) inside a zip. The zip also holds the checksums and the restore tools. So the zip
 alone is enough to restore on a new computer.

 These scripts run on Windows only, in PowerShell 7.

====================================================================================================
 2  THE WORDS YOU NEED
====================================================================================================
 Backup zip     pki-payload-....zip in the folder backup-pki\. This is what you copy away.
 .certpacked    The encrypted file inside the zip. Rename it to .zip and 7-Zip opens it with the
                password.
 Checksum       A short fingerprint of a file (SHA-256, SHA-512). If one byte changes, the
                fingerprint changes. SHA256SUMS and SHA512SUMS list them.
 Private key    The secret file of a certificate. A backup holds ALL of them.
 Password       The only way to open the .certpacked. It is stored nowhere.
 Administrator  A PowerShell window started with "Run as administrator".
 Local Machine store   The Windows place for trusted certificates of all users. NOT in the backup.
 Prepare-Computer      The script that installs PowerShell 7, OpenSSL 4, Python 3 and .NET SDKs.
 Deep check     -Deep: open the .certpacked and check every file inside, not only the zip files.

====================================================================================================
 3  BEFORE YOU START
====================================================================================================
 All three scripts check the computer first. Nothing is done when a check fails.

 Windows        Windows 11 Home or Pro, 24H2 or newer, or Windows Server 2025 (Essentials,
                Standard, Datacenter).
 Processor      Intel or AMD, 64 bit (AMD64, x86-64) ONLY. ARM and 32 bit are refused (exit 5),
                also when a program is emulated.
 Window         PowerShell 7 (pwsh) started with "Run as administrator". Any other window is
                refused (exit 2).
 Software       Restore-Pki.ps1 checks ALL of this on the PATH: PowerShell 7, OpenSSL 4, Python 3,
                .NET SDK 8 and .NET SDK 10. Anything missing is listed. Run Prepare-Computer.ps1
                (exit 4, nothing is written).
 Standalone     Backup-Pki.ps1, Restore-Pki.ps1, Test-PkiBackup.ps1 and Prepare-Computer.ps1 need
                NO other .ps1 file. The backup zip holds just these four.

====================================================================================================
 5  MAKE A BACKUP (Backup-Pki.ps1)
====================================================================================================
     .\Backup-Pki.ps1                       back up the PKI in the folder of the script
     .\Backup-Pki.ps1 -Check                list what would be backed up (files, MB, key files,
                                            PKI folders). No password, nothing written.
     .\Backup-Pki.ps1 -List                 list the backups in backup-pki\
     .\Backup-Pki.ps1 -PkiRoot <folder>     the folder that holds pki\ (default: the script folder)
     .\Backup-Pki.ps1 -BackupRoot <folder>  another backup folder

 What is backed up:   pki\ (all PKIs, all releases, all keys), leafcerts\, external-ca\,
                      csr-signed\, every *_pki.cnf, pki_tools.cnf, devkit.env.
 What is NOT:         transport\ and backup-pki\ itself, the Windows certificate stores, the
                      OpenSSL and Python installation.

 ONLY YOUR PKI: certificates of other CAs (DigiCert, GlobalSign, Sectigo ...) are never backed up.
 Your organizations are read from the "Organization =" lines of your *_pki.cnf files. A
 certificate is yours when its issuer's O is yours, or it is a self-signed root of yours, or it is
 a CA of yours (key present). A file, key, .pfx or whole PKI folder that holds only other CAs is
 left out and listed under "Left out".

 PRIVATE KEYS: a backup is made to restore from, so it holds the key of EVERY certificate: all
 roots, all intermediates, all leaf certificates and the .pfx files. The script proves it. It
 matches each certificate with its key by the public key (OpenSSL).
   A CA certificate without a key is a WARNING (a CA signed by SignExternalCa keeps its key in the
   other department).
   A certificate signed from a request has its key with the requester (INFO).
 The result is printed, stored in the backup, and printed again by Restore-Pki.ps1.

 After packing, the script opens the .certpacked again (every file is authenticated) and prints
 the SHA-256 and SHA-512 of the zip. Write them down to compare after a copy.

====================================================================================================
 6  PASSWORDS
====================================================================================================
 - It is asked FIRST, right after the PKI is found and before the long scan. So an Enter you press
   while waiting is not taken as an empty password.
 - You type it twice. No password, no backup (exit 3).
 - At least 12 characters, with at least 1 upper case letter, 1 lower case letter, 1 digit and
   1 special character. Printable ASCII only. Every broken rule is shown. Three tries.
 - It is stored NOWHERE and cannot be recovered. Without it the backup is only noise.
 - Keep it apart from the zip: two places, two ways.
 - Unattended runs: the environment variable PKI_BACKUP_PASSWORD is accepted (the rules still
   apply). Other programs can read an environment variable: prefer the prompt.

====================================================================================================
 7  THE BACKUP ZIP, INSIDE AND OUT
====================================================================================================
 backup-pki\pki-payload-<yyyymmdd>-<computer>-<windows-version>-<6 hex>.zip
 Example: pki-payload-20261014-pc01-windows-11-25h2-a1b2c3.zip
 <windows-version> is windows-11-24h2, windows-11-25h2, windows-11-26h2 ... or
 windows-server-2025. The 6 hex characters are random: two backups of one day never collide.

 Inside the zip (one folder with the same name):

 File                    What it is
 ----------------------  ----------------------------------------------------------------------
 <name>.certpacked       The encrypted backup.
 SHA256SUMS, SHA512SUMS  Checksums of every other file in the folder (sha256sum -c works too).
 Restore-Pki.ps1         Puts the backup back.
 Test-PkiBackup.ps1      Checks the backup.
 Backup-Pki.ps1          Makes the next backup.
 Prepare-Computer.ps1    Installs the software for a restore.
 README.txt              The same steps as this manual, short.

 The folder backup-pki\ is made when it does not exist. It is in .gitignore, because it holds
 private keys.

 Inside the .certpacked: certpack.json (format "agantra-pki-backup", every file with its SHA-256,
 the folders including empty ones, for each PKI the list of its CA certificates with thumbprint and
 whether their private key is in the backup, and the key totals), SHA256SUMS, README.txt, and
 data\<the PKI files>.

====================================================================================================
 8  TEST A BACKUP (Test-PkiBackup.ps1)
====================================================================================================
     .\Test-PkiBackup.ps1                          the unzipped folder you are in
     .\Test-PkiBackup.ps1 -Backup <zip | folder | backup-pki>
                                                   a zip, an unzipped backup, or every zip of the
                                                   backup folder
     .\Test-PkiBackup.ps1 -Backup .\backup-pki -Deep
                                                   also asks for the password, opens the
                                                   .certpacked and checks the SHA-256 of every
                                                   file inside

 It prints OK or FAIL for every file. One changed byte, a missing file or an extra file is a FAIL
 and exit 6. Run it after every copy, and from time to time (disks rot). Use -Deep now and then:
 it proves that the password still works.

====================================================================================================
 9  RESTORE A BACKUP (Restore-Pki.ps1)
====================================================================================================
     .\Restore-Pki.ps1 -Destination C:\PKI-DevSecOps
                 from the unzipped backup folder (the .certpacked is next to the script)
     .\Restore-Pki.ps1 -Package <zip | .certpacked | folder> -Destination <folder>
     .\Restore-Pki.ps1 -Check ...     everything except writing

 The order. It stops at the first problem, before anything is written:
   1. The computer (section 3).
   2. The Administrator window.
   3. ALL the software is there (else: run Prepare-Computer.ps1).
   4. SHA256SUMS of the zip files.
   5. The password. Every file inside is decrypted and checked.
   6. The ONE BY ONE comparison with this computer (below).
   7. Only what is missing is written.
   8. The written files are checked again.

 ONE BY ONE. Every PKI of the backup is compared with
   (a) <Destination>\pki\<name>: each file by SHA-256. Identical, different or missing.
   (b) the Local Machine certificate store (Root and Intermediate): each CA certificate of that PKI
       by thumbprint ("in Local Machine store" or "NOT in ...").

 What happens:
   - A PKI folder that is there with all files identical is NOT restored.
   - A PKI whose CA certificates are ALL in the Local Machine store is NOT restored. The store
     holds certificates, not private keys. The output says so. -Force restores the keys anyway.
   - A PKI folder that is there but different: you are asked "Replace it with the version in the
     backup? [Y/n]". Enter = Y. With Y the old folder is renamed <name>.before-restore-<time>
     (never deleted) and the backup version is written. With n the old one stays. With nobody to
     ask (no keyboard) the old one stays.
   - The other files (leafcerts, external-ca, csr-signed, settings) are compared file by file:
     identical = skipped, missing = written, different = you are asked.
   - If nothing is missing: "Nothing to restore", nothing is changed, exit 0.
   - ONLY YOUR PKI is restored. Certificates of other CAs in an older backup are listed as "Not
     restored" and never written.
   - NOTHING IS DELETED OR SILENTLY OVERWRITTEN.

 -Destination: without it, the folder of the script is used when it is the project (it has
 pki_setup.ps1). A script from the backup zip needs -Destination.
 -Yes              answer Y to every replace question (old folders and files are still renamed)
 -Force            restore anyway. A PKI folder or file that exists is RENAMED to
                   <name>.before-restore-<yyyymmdd-HHmmss> first.
 -RestrictAccess   pki\, leafcerts\, external-ca\, csr-signed\ get access for Administrators and
                   SYSTEM only (icacls), BEFORE the keys are written.
 While it runs, the decrypted files are in a temporary folder of the administrator. The folder is
 deleted at the end, also after an error.

====================================================================================================
 10  THE WINDOWS CERTIFICATE STORES
====================================================================================================
 The stores are not part of the backup. After a restore, in the restored folder:

     .\pki_setup.ps1 -InstallTrust

 This puts the roots and intermediates into Windows again, so the computer trusts the PKI.

====================================================================================================
 11  KEEP IT SAFE
====================================================================================================
 - The zip holds every private key of your PKI. Whoever has the zip and the password IS your CA.
 - Keep the zip and the password apart, in two safe places.
 - Keep at least one copy on another disk or computer, in another room if you can.
 - Make a new backup at every change of the PKI (a new release, a new CA, new leaf certificates).
 - Test the copy after you make it. Test again now and then, with -Deep.
 - Do not e-mail the zip. Do not put it in a git repository.

====================================================================================================
 12  RESTORE ON A NEW COMPUTER, STEP BY STEP
====================================================================================================
 1. Copy the backup zip to the new computer. Unzip it. Go into the folder.
 2. Open Windows PowerShell as administrator in that folder. Run (once):
        .\Prepare-Computer.ps1
    It installs PowerShell 7, .NET SDK 8 and 10, OpenSSL 4, Python 3. What is already the latest
    is not installed again.
 3. Open a NEW PowerShell 7 (pwsh) window as administrator, in the same folder.
 4. .\Test-PkiBackup.ps1            are the files unchanged? (-Deep also proves the password)
 5. .\Restore-Pki.ps1 -Destination C:\PKI-DevSecOps -Check      try it, nothing is written
 6. .\Restore-Pki.ps1 -Destination C:\PKI-DevSecOps
 7. In the restored folder:  .\pki_setup.ps1 -InstallTrust

====================================================================================================
 13  RECIPES, COPY AND PASTE
====================================================================================================
 What would be backed up?          .\Backup-Pki.ps1 -Check
 Back up                           .\Backup-Pki.ps1
 Back up to another folder         .\Backup-Pki.ps1 -BackupRoot D:\backups
 List the backups                  .\Backup-Pki.ps1 -List
 Test every zip, deep              .\Test-PkiBackup.ps1 -Backup .\backup-pki -Deep
 Restore, try first (zip)          .\Restore-Pki.ps1 -Package .\x.zip -Destination C:\PKI -Check
 Restore from a zip                .\Restore-Pki.ps1 -Package .\x.zip -Destination C:\PKI
 Restore, answer yes to all        .\Restore-Pki.ps1 -Destination C:\PKI -Yes
 Restore, lock the folders         .\Restore-Pki.ps1 -Destination C:\PKI -RestrictAccess

====================================================================================================
 14  PROBLEMS AND ANSWERS
====================================================================================================
 "needs PowerShell 7" (Windows PowerShell 5.1)
     Start pwsh, not powershell.
 Exit 2, "not an Administrator window"
     Close it. Start PowerShell 7 with "Run as administrator".
 Exit 3, password refused
     A rule of section 6 is broken, or the password is wrong. For a restore you need the password
     of THAT backup.
 Exit 4, "run Prepare-Computer.ps1"
     Some software is missing. Run Prepare-Computer.ps1 in Windows PowerShell, open a NEW pwsh
     window, try again.
 Exit 5, "system not supported"
     Section 3: Windows version, edition, ARM, or not Windows.
 Exit 6, a checksum does not match
     The zip is damaged or was changed. Copy it again from another place, or use another backup.
     Never restore from a zip that fails the test.
 "Nothing to restore"
     Everything is there already. This is not an error.
 After a restore the browser does not trust the PKI
     You did not run pki_setup.ps1 -InstallTrust (section 10).
 A CA certificate without a key (WARN)
     Normal for a CA that SignExternalCa signed: its key is in the other department.
 I lost the password
     The backup cannot be opened. Nobody can recover it. Make a new backup from a PKI that works.

====================================================================================================
 15  LIMITS YOU MUST KNOW
====================================================================================================
 - Windows and PowerShell 7 only. Linux and macOS are not supported by these scripts.
 - The password cannot be recovered.
 - A backup is a snapshot. Anything made after it is not inside.
 - The Windows certificate stores, OpenSSL and Python are not inside.
 - Certificates of other CAs are left out on purpose.
 - Restore-Pki.ps1 writes what is missing. It does not make your folder equal to the backup. To get
   an exact copy of a changed folder, use -Force (the old folder is renamed, not deleted).

 16  ALL OPTIONS AND EXIT CODES
====================================================================================================
 Backup-Pki.ps1     -PkiRoot <folder>   -BackupRoot <folder>   -Check   -List   -Help
 Test-PkiBackup.ps1 -Backup <zip|folder|backup-pki>   -Deep   -Help
 Restore-Pki.ps1    -Package <zip|.certpacked|folder>   -Destination <folder>   -Check   -Yes
                    -Force   -RestrictAccess   -Help

 Exit  Meaning
 ----  -------------------------------------------------------------------------------------
   0   ok
   1   error
   2   not an Administrator window
   3   password refused or wrong
   4   Prepare-Computer.ps1 not run (PowerShell 7, OpenSSL 4, Python 3, .NET SDK 8 or 10 missing)
   5   system not supported (Windows version, edition, ARM, not Windows)
   6   a checksum does not match (damaged or changed)

 VERSION REPORT (new in 6.4.13).  Every script answers -Version (PowerShell) or --version (bash).
 It prints the script version, author, company, e-mail, the operating system with its version and
 patch level (or kernel), and the newest .NET, Node.js, Python 3, Java, shell, Schannel and OpenSSL
 found, with the vendor of each OpenSSL. It changes nothing. Details: VERSION-INFO.txt.

====================================================================================================
 17  WHAT WAS TESTED, WHAT WAS NOT
====================================================================================================
 Built and tested on Ubuntu 24.04 with PowerShell 7 and the Windows checks simulated (PKI_FAKE_OS,
 PKI_FAKE_ARCH, PKI_FAKE_ADMIN): password policy, backup, checksum check (also a changed file),
 restore (identical files), the one-by-one comparison (all identical, one file different, all CA
 certificates in a fake store, empty destination), wrong password, -Force, refusal without
 Prepare-Computer or without a .NET SDK.
 NOT tested on real Windows: the Windows version names (DisplayVersion), the ARM check, the
 Administrator check, icacls (-RestrictAccess), Windows PowerShell 5.1 showing the "needs
 PowerShell 7" message. What to run on your machines: PKI-Acceptance-Checklists.txt, E33.
