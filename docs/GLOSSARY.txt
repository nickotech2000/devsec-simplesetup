 READ THIS FIRST
----------------------------------------------------------------------------------------------------
 These are short, plain answers. If a word in a manual is new to you, look here.

 THE BASICS
----------------------------------------------------------------------------------------------------
 PKI
   Public Key Infrastructure. All the parts that make certificates work: CAs, certificates, keys,
   and the lists that say which certificates are no longer good.

 Certificate
   A digital ID card for a server, a person or a program. It says who it is and carries a public
   key.

 Key (private key)
   The secret that goes with a certificate. Never share it. Whoever has it can act as you.

 CA (Certificate Authority)
   The one who signs certificates. Your computer trusts a certificate when a CA it trusts signed it.

 Root CA
   The top CA. It is kept offline and used rarely. Everything else depends on it.

 Intermediate CA
   A CA signed by the root. It signs the day-to-day certificates, so the root can stay offline.

 Leaf certificate
   The last certificate in a chain, the one a server, person or program uses.

 Chain
   Leaf, then intermediate, then root. A client checks the whole chain.

 CSR
   Certificate Signing Request. A file you send to a CA to ask for a certificate. It has no secret.

 PEM, CRT, CER, DER, PFX
   File formats. PEM is text (-----BEGIN ...). DER is binary. CRT and CER are certificates, in
   either form. PFX (PKCS#12) holds a certificate and its key together, with a password.

 Purpose (of a certificate)
   What the certificate may be used for: a web server, a web client, code signing, e-mail, time
   stamping or OCSP. The list is stored inside the certificate (see EKU). Do not mix purposes.

 CN (Common Name)
   The main name in the subject of a certificate, for example www.example.com. Browsers check the
   SAN, not the CN.

 Custom EKU
   A purpose you invent, written as a dotted number such as 1.3.6.1.4.1.99999.1.2. No program trusts
   it until that program is told to.

 S/MIME
   A standard for signed and encrypted e-mail. A certificate with the Secure Email purpose does it.

 Signer
   A person who signs documents with a certificate, for example in Word, Excel or a PDF.

 DevKit
   One zip file for developers. It holds the PKI (encrypted) and the scripts that install the trust
   and make test certificates. Built with PkiTransport.ps1 -DevKit.

 .certpacked
   The encrypted file inside the DevKit. It holds the PKI. It has a password.

 Trust (install the trust)
   Put the root CA into a computer, so programs accept certificates of your PKI.

 Package (.certpacked)
   The one encrypted file that the transport makes. Rename it to .zip or .7z and 7-Zip opens it with
   the password.

 Source, destination
   The source is the computer that holds the PKI. The destination is a computer that receives it.

 Scope (of a package)
   What a package holds: only public CA certificates, or also private keys.

 Trust kit
   A zip for one operating system with the CA certificates of the PKI (no private key) and a small
   script. The person unzips it, runs the script and types the password. After that the computer
   trusts the PKI.

 OCSP responder
   The server that answers OCSP questions. It has its own certificate with the usage "OCSP
   Signing". It is renewed with PkiRevocation.ps1 -Action NewOcsp.

 Local Machine and Current User store (Windows)
   Two places for trusted certificates. Local Machine is for all users and needs an
   Administrator window. Current User is for one user only.

 TSA (Time Stamping Authority)
   The server that gives time stamps. Its certificate has only the usage "timeStamping". It is a
   normal leaf certificate.

 Bootstrap
   A first installer that gets a computer ready: it installs the tools that the other scripts
   need.

 PPA (personal package archive)
   An Ubuntu software source run by one person or company. Install-DevEnvironment.sh can add yours
   to get OpenSSL 4 and nginx.

 Stripped OpenSSL
   An OpenSSL built without the FIPS module, or a "light" package. It says 4.x but cannot do what
   the PKI needs, so the scripts refuse it.

 Name constraints
   A rule inside a CA certificate that limits which names the CA may issue certificates for, for
   example only *.sales.example.com. A client that checks it refuses any other name. SignExternalCa
   can write them (-PermitDns, -PermitEmail).

 Origin (CDN)
   Your own web server that sits behind a CDN. The CDN opens a connection to it. Export-PkiCa gives
   the CDN the CA certificate it needs to trust the origin.

 OCSP stapling
   The web server fetches a fresh OCSP answer for its own certificate and hands it to the visitor
   with the certificate. The visitor does not have to ask the CA. Faster and more private.

 HSTS
   A web header that tells a browser: use only HTTPS for this site, for this long.

 AIA (CA Issuers)
   The address inside a certificate where the certificate of its CA can be downloaded.
   Export-PkiCa -FetchAia uses it.

 Execution policy (Bypass)
   The PowerShell rule about which scripts may run. Bypass blocks and warns about nothing.
   Enable-DevMachine.cmd / .ps1 set it for a development computer. See its manual.

 Unblock (Zone.Identifier)
   Windows marks files from the Internet as "downloaded" and may refuse to run them. Unblock-File
   removes that mark.

 SHA256SUMS
   A list of the fingerprints (SHA-256 hashes) of every file in the release. Compare it with your
   copy to see that no file was changed after it was built. See SECURITY-AUDIT.txt.

 False positive
   A warning of an antivirus program about a file that is really harmless. Security programs
   judge by behaviour patterns ("heuristics"), so a script that starts programs and changes
   certificate stores can look suspicious. See SECURITY-AUDIT.txt.

 -VerifyAll
   Option of pki_setup.ps1: runs -Verify for every PKI that was built (all companies, all
   releases) and shows every result.

 -Version / --version
   An option of every script. It prints the version of the script, the author, the operating
   system and the versions of .NET, Node.js, Python, Java, the shells, Schannel and OpenSSL, and
   changes nothing. Send its output to support. See VERSION-INFO.txt.

 Kernel
   The core of Linux. Its version (for example 6.18) is the "patch level" of a Linux computer, as
   the build number is on Windows.

 Vendor (of OpenSSL)
   The maker of one copy of OpenSSL: your Linux distribution (a package), FireDaemon, Shining
   Light, Git for Windows, or you (built from source code). Two copies can be the same version and
   come from different makers.
 Hash (SHA-256, SHA-512)
   A short fingerprint of a file. If one byte changes, the hash changes. The .sha256 and .sha512
   files next to your certificates let you check that a file was not damaged or changed.

 THE PKI IN THIS PROJECT
----------------------------------------------------------------------------------------------------
 Enterprise Root
   The top CA of this PKI. It signs the two Track Roots. It lives for 1000 years.

 Track
   A group of CAs with the same kind of key. This PKI has two: Classic (RSA, ECDSA) and Quantum
   (ML-DSA).

 Quadrant
   One of four CA families, numbered 1 to 4: 1 = Classic without FIPS, 2 = Classic with FIPS,
   3 = Quantum without FIPS, 4 = Quantum with FIPS.

 Quadrant Root
   The root of one quadrant. It signs the DV, OV and EV intermediates of that quadrant.

 DV, OV, EV
   Three levels of certificate. DV = domain checked. OV = organization checked. EV = extended
   checks. In this PKI the level sets the policy and the validity of the certificate.

 Policy (certificate policy, OID)
   A number inside a certificate that says which rules were used to issue it. For example
   2.23.140.1.1 means EV.

 PEN (IANA Private Enterprise Number)
   A number that IANA gives to a company. It lets you make your own policy numbers.

 Release
   One build of a PKI. Release 1 is the first. The next run builds release 2, with new keys.
   Old releases keep working.

 NoCR
   "No CA revocation information". A PKI whose CA certificates have no CRL or OCSP address.

 Profile
   The settings file <short>_pki.cnf of one company. One profile gives one PKI.

 SAN (Subject Alternative Name)
   The list of host names that a certificate is valid for, for example www.example.com.

 pathlen (path length)
   How many CA levels may be below a CA. pathlen 0 means: it signs end certificates only.

 EKU (Extended Key Usage)
   What a certificate may be used for: web server, web client, code signing, e-mail, time stamp.

 ML-DSA
   A signature type that quantum computers cannot break. ML-DSA-87 is the strongest size.

 ML-KEM, hybrid key exchange
   A way to agree on a secret key that quantum computers cannot break. The hybrid form
   X25519MLKEM768 uses it together with the normal X25519. It is part of TLS, not of the
   certificate.

 Preflight (-Check)
   A test before the real work. It changes nothing and says READY or NOT READY.

 Certificate store
   The place in Windows where certificates are kept. Trusted Root holds roots. Intermediate holds
   intermediate CAs. Personal holds certificates with a key.

 Schannel
   The TLS part of Windows. IIS and Kestrel on Windows use it.

 Manifest
   A file (pki-manifest.json) that lists everything that was built: each certificate, key, digest
   and expiry date.

 THE SERVICES
----------------------------------------------------------------------------------------------------
 CRL
   Certificate Revocation List. A signed list of certificates that must no longer be trusted.

 OCSP
   A small service that answers "is this certificate still good?" for one certificate.

 Timestamp (RFC 3161)
   A signed proof of the time. A code signature with a timestamp stays valid after the certificate
   expires.

 Revoke
   Say that a certificate is no longer good (for example, the key was stolen).

 CODE SIGNING AND BUILDS
----------------------------------------------------------------------------------------------------
 Code signing
   Putting a signature on a program so people can see who made it and that nobody changed it.

 OV / EV certificate
   Organization Validated / Extended Validation. Public certificates where a public CA checked your
   company. EV is the strictest check.

 Pipeline, CI/CD
   An automatic build that runs when code changes (GitHub Actions, Azure DevOps, AWS CodeBuild,
   Google Cloud Build, Alibaba Yunxiao).

 Secret (pipeline secret)
   A password or token stored safely in the pipeline. The scripts read it from an environment
   variable, never from the command line.

 KMS, HSM, Key Vault
   A safe place where the key lives and signs for you. The key never leaves it.

 WEB SERVERS
----------------------------------------------------------------------------------------------------
 TLS 1.3
   The current secure protocol of HTTPS. The web-server tool uses only TLS 1.3 by default.

 QUIC / HTTP/3
   A faster way to carry HTTPS over UDP.

 ECH
   Encrypted Client Hello. Hides the website name in the first message of a connection.

 PQC
   Post-quantum cryptography. Algorithms (such as ML-DSA and ML-KEM) that quantum computers cannot
   break.

 Kestrel
   The built-in web server of ASP.NET. nginx or Apache sits in front and sends traffic to it.

 CDN
   A network that serves your site near the user (Cloudflare, CloudFront, Azure, Akamai, ...).

 FIPS
   A US standard for approved cryptography. "Level" and "track" in these documents refer to the
   choices made at setup.
