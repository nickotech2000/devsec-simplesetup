 1  WHAT THE TWO SCRIPTS DO
====================================================================================================

 They prepare a machine for development and for the Agantra PKI scripts, and install what is MISSING (nothing that is present is replaced):
     Install-DevEnvironment.ps1   Windows 11, through WinGet. Runs in Windows PowerShell 5.1 and PowerShell 7. Elevated, except -Check, -Help, -Unblock.
     Install-DevEnvironment.sh    Linux (Ubuntu / Debian, RHEL / CentOS Stream / Rocky / Oracle / Alma, SLES / openSUSE) and macOS, through the
                                  package manager of the system, and for OpenSSL and pwsh through the official source / release.
 The PKI scripts call them when something they need is missing: Windows PKI scripts suggest  Install-DevEnvironment.ps1 -Only OpenSSL,7Zip ;
 PkiTransport.ps1 and Unpack-PkiTransport.ps1 run it when you give -InstallMissing (or answer yes); pki-transport.sh runs Install-DevEnvironment.sh.
 The transport -Kit carries both scripts, so a destination needs nothing else.

 3  OPENSSL 4: "FULL", "READY", "STRIPPED"
====================================================================================================

 The PKI needs more than "an OpenSSL 4". It needs the FIPS provider (Quadrants 2 and 4) and the post-quantum algorithms ML-DSA and ML-KEM
 (Quadrants 3 and 4). A STRIPPED build (a build without enable-fips, a "light" package, an OpenSSL that only reports 4.x) is refused.

 READY means all of these are proven (the same five checks in both scripts, on the binary that will be used):
     version          4.0.1 or newer (4.0.1 to 4.0.3 tested)
     FIPS provider    loads with fipsmodule.cnf and reports active
     ML-DSA           ML-DSA-65 key, sign and verify
     ML-KEM           ML-KEM-768 key generation
     ML-DSA in FIPS   ML-DSA-65 key inside the FIPS provider (a warning only when a build lacks it)
 Windows also checks that the machine-wide OPENSSL_CONF loads without provider errors.

 WINDOWS  FireDaemon.OpenSSL by WinGet. If it reports less than 4.0.1 the script runs "winget upgrade". It writes fipsmodule.cnf
          (openssl fipsinstall), OPENSSL_MODULES, OPENSSL_CONF and a master openssl.cnf that activates default and FIPS.
          oqsprovider is OPTIONAL (-WithOqsProvider): OpenSSL 4 has native ML-DSA and ML-KEM, and the master configuration mentions
          oqsprovider only when its DLL exists (a missing DLL named in the configuration makes every openssl command print errors).
 PATH     Windows: the OpenSSL bin folder is added to the MACHINE Path (new terminals). Linux / macOS: the bin folder of OpenSSL 4 is put FIRST
          on the PATH of login shells: /etc/profile.d/openssl4.sh (with sudo) or a marked block in ~/.profile and ~/.bashrc; the system
          openssl files are not touched; a link  openssl4  is also made. --no-path leaves the PATH alone. Open a NEW terminal afterwards.
 LINUX / MACOS  A FULL build from https://github.com/openssl/openssl/releases (4.0.3; --openssl-version changes it):
     * the tarball is checked against the .sha256 file of the same release page; nothing is built when it differs;
     * ./Configure --prefix=<prefix> --openssldir=<prefix>/ssl --libdir=lib enable-fips -Wl,-rpath,<prefix>/lib   (no "no-docs" unless you ask)
     * make -j<cores> and  make install  (libraries, headers, documentation, the FIPS module, fipsmodule.cnf)
     * default prefix /opt/openssl-4.0.3 (macOS /usr/local/openssl-4.0.3); the system openssl is NOT replaced; a link  openssl4  is put in
       /usr/local/bin. The rpath means the binary runs without LD_LIBRARY_PATH.
 BUILD TIME  About 5 minutes on 8 cores, 15 to 25 on 2 cores, over an hour on ONE core. Measured here: on a 1-core VM 542 object files in two
     minutes and more than 30 minutes without finishing. --openssl-no-docs shortens it a little; --openssl-jobs N sets the parallel jobs.
 After the build the five checks run; the script fails (exit 4) when they do not pass. pki-transport.sh and the PowerShell PKI scripts accept
 only a READY OpenSSL.

 5  UNBLOCK AND UNLOCK
====================================================================================================

 Both scripts do it at EVERY start, silently, for their own folder (children and recursive), before anything else; -Unblock / --unblock does only that.
   Windows    UNBLOCK: the "downloaded from the Internet" mark (Zone.Identifier) is removed from every file.   UNLOCK: the Read-only attribute.
   Linux      UNLOCK: write permission is set (chmod -R u+rw), scripts get the execute bit, the immutable flag is removed where chattr exists.
   macOS      UNBLOCK: the quarantine mark (xattr -dr com.apple.quarantine).   UNLOCK: write permission and the locked flags (chflags nouchg,noschg).
 A script that is blocked the very first time cannot run its own bootstrap: Windows  Get-ChildItem -Path . -Recurse -File | Unblock-File ;
 macOS  xattr -dr com.apple.quarantine . ; Linux  chmod +x *.sh .  The same mechanism is in pki_setup.ps1, GenerateLeafCertificate.ps1,
 PkiTransport.ps1, Unpack-PkiTransport.ps1 and pki-transport.sh.

 6  HOW THE PKI SCRIPTS USE THEM
====================================================================================================

   PkiTransport.ps1 -Install ... -InstallMissing      OpenSSL 4 missing or not ready on the Windows destination: installs it with
                                                      Install-DevEnvironment.ps1 -Only OpenSSL, then scans again
   PkiTransport.ps1 -Pack -ArchiveFormat 7z -InstallMissing        7-Zip missing: installs it
   Unpack-PkiTransport.ps1 -Package x.certpacked -InstallMissing   a 7z package and no 7-Zip: installs it (Windows: the bootstrap or WinGet;
                                                      Linux / macOS: Install-DevEnvironment.sh --only 7zip)
   pki-transport.sh                                   when OpenSSL 4 is missing it asks (or --install-openssl) and runs Install-DevEnvironment.sh
                                                      when it sits next to it, else its own copy of the same build; 7-Zip and the store tooling
                                                      are installed on demand
 Without -InstallMissing the PowerShell scripts ASK when a person is at the console and stop with a clear message otherwise.
 The scripts look for the bootstrap next to themselves and in the parent folder; the transport kit has them.

 7  WHAT I CHANGED IN YOUR Install-DevEnvironment.ps1, AND WHY
====================================================================================================

 CHECKED. Parsed without errors; -Help, -Unblock and the OpenSSL readiness code were run (on PowerShell 7 / Linux). NOT run on Windows. Found and changed:
   1. The master openssl.cnf always activated oqsprovider, even when the DLL download had failed: every openssl command then prints a provider
      error. Now oqsprovider appears only when oqsprovider.dll exists, and the download is opt-in (-WithOqsProvider).
   2. The download came from  oqs-provider/releases/latest/download/oqsprovider-win64.zip : no version, no checksum, and I could not confirm that
      file exists. OpenSSL 4 does not need it (native ML-DSA / ML-KEM). Removed from the default path.
   3. "winget install FireDaemon.OpenSSL" could leave an older OpenSSL. The version is read and "winget upgrade" runs when it is below 4.0.1.
   4. The final scan only printed algorithm lists. It now PROVES version, FIPS, ML-DSA, ML-KEM, ML-DSA in FIPS (section 3) and exits 4 when not ready.
 ADDED (additive: everything else behaves as before):
   -Help, -Check, -Only <list>, -Skip7Zip + the 7-Zip component (7zip.7zip), -WithOqsProvider, -Unblock and the silent unblock / unlock at start.
   The administrator check does not apply to -Check. Windows PowerShell 5.1 syntax only in the new code ($IsWindows, ?: and -AsHashtable are not used).
 NOT changed: the list of WinGet packages, the PATH functions, the logging, the Windows 11 check.

 9  TROUBLESHOOTING
====================================================================================================

 Symptom                                           Cause and fix
 ------------------------------------------------  --------------------------------------------------------------------------------------
 "a STRIPPED build: no FIPS module or no ML-DSA"   An OpenSSL 4 without enable-fips (Homebrew, a "light" package): build the full one (--only openssl)
 "NOT READY" after the Windows install              Read the readiness table: FIPS (fipsmodule.cnf missing), ML-DSA, ML-KEM; run the script again elevated
 FireDaemon reports 3.x                             The script runs winget upgrade; if it stays 3.x install a newer FireDaemon OpenSSL by hand
 The build seems to hang                            It is compiling: hundreds of files; one core needs over an hour. Use a machine with cores
 "SHA-256 of the tarball does not match"            Nothing was built. Retry (corrupt download) or check the proxy; never override
 7zip not installable on RHEL / Rocky / Oracle      Enable EPEL (and CRB), or install 7-Zip by hand and give --7z to pki-transport.sh
 pwsh: "could not read the latest release"          GitHub unreachable or rate limited: retry later or install PowerShell 7 by hand
 "Not root and no sudo"                             Run with sudo or as root (only --check, --dry-run and --unblock work without)
 Windows: the script window shows red text          Read the log: %ProgramData%\Agantra\WindowsDeveloperBootstrap\Logs
 macOS: the build needs a compiler                  xcode-select --install, then run again

 10  LIMITS AND WHAT WAS TESTED
====================================================================================================

 TESTED (Linux, Ubuntu 24.04 as root, OpenSSL 4.0.3 full build at hand):
   * Install-DevEnvironment.sh: syntax, --help, --check, the five readiness checks against the real OpenSSL 4.0.3 (all pass), rejection of the system
     OpenSSL 3.0 and of a fake "4.0.3" that is 3.0 underneath, REAL installation of 7-Zip with apt (and its verification), --unblock, dry runs for
     Ubuntu, Rocky, openSUSE Tumbleweed and macOS, the pwsh release lookup, the OpenSSL download with checksum and Configure;
   * the PowerShell side: -InstallMissing installed 7-Zip through the companion script for a 7z package; the kit carries both bootstraps;
   * Install-DevEnvironment.ps1: parses, -Help, -Unblock, and the readiness functions (run on PowerShell 7) against the real OpenSSL.
 NOT TESTED: Install-DevEnvironment.ps1 on Windows 11 (WinGet installs, the FireDaemon upgrade, Windows PowerShell 5.1), the finished OpenSSL
   COMPILE (a 1-core VM could not finish it), any install on the RHEL family, SUSE or macOS, the package names of dotnet / node / go / php, the
   pwsh download itself (only the version lookup and the plan).
 LIMITS: needs the Internet (package managers, GitHub). The OpenSSL source build trusts the checksum of the same release page, not a signature.
   Distribution packages for go / node / php / dotnet may be older than "latest". Nothing here removes or downgrades anything.

WHAT IT DOES   (run in an ELEVATED PowerShell; -Check, -Help and -Unblock need no elevation)

USAGE
  .\Install-DevEnvironment.ps1                          everything

  .\Install-DevEnvironment.ps1 -Only OpenSSL,7Zip       just these (what the PKI scripts need)
  .\Install-DevEnvironment.ps1 -SkipPHP -SkipGo         everything except these
  .\Install-DevEnvironment.ps1 -Unblock                 UNBLOCK + UNLOCK this folder, children and recursive, then stop

PARAMETERS
  -Only <list>           PowerShell, DotNet, NodeJS, Go, PHP, Python, Git, OpenSSL, 7Zip, WindowsTerminal. Installs only these.
  -SkipPowerShell -SkipDotNet -SkipNodeJS -SkipGo -SkipPHP -SkipPython -SkipGit -SkipOpenSSL -SkipWindowsTerminal -Skip7Zip
  -Check                 Scan only. Exit code 0 when OpenSSL is ready, 4 when it is not.
  -WithOqsProvider       Also download the third-party oqsprovider (NOT needed: OpenSSL 4 has native ML-DSA and ML-KEM).
                         Without it the master openssl.cnf does not mention oqsprovider at all.
  -Unblock               UNBLOCK (Internet mark) and UNLOCK (Read-only) every file below this script's folder, then stop.
                         The same is done silently at every start, before anything else.
  -Help                  This text.

OPENSSL
  FireDaemon.OpenSSL is installed by WinGet. If it reports less than 4.0.1 the script runs "winget upgrade". It then writes
  fipsmodule.cnf (openssl fipsinstall), the machine variables OPENSSL_MODULES and OPENSSL_CONF, and a master openssl.cnf that
  activates the default and FIPS providers. The PKI scripts ignore OPENSSL_CONF (they use their own configuration).

EXIT CODES   0 ok   1 error (for example not elevated)   4 OpenSSL not ready

WHAT IT DOES
  Installs what is MISSING, verifies each component, and prints a summary. Nothing that is already there is replaced.
    tools      curl, tar, gzip, unzip, ca-certificates, compiler, make, perl
    7zip       7-Zip: the archive tool of the .certpacked transport (AES-256 zip, 7z)
    openssl    OpenSSL 4.0.1 or newer as a FULL build, never a stripped one: FIPS provider with fipsmodule.cnf, native ML-DSA

               (the tarball is checked against the SHA-256 of the same release page) into --openssl-prefix. The system openssl
               is NOT replaced; a link  openssl4  is put in /usr/local/bin. Then PROVEN: version, FIPS provider active,
               ML-DSA-65 sign + verify, ML-KEM-768 key generation, ML-DSA inside the FIPS provider.
    git python go node php dotnet pwsh     developer tools (distribution packages; pwsh from the PowerShell GitHub release)

USAGE
  ./Install-DevEnvironment.sh --check                      what is installed, OpenSSL readiness; changes nothing
  ./Install-DevEnvironment.sh --yes                        install everything that is missing
  ./Install-DevEnvironment.sh --yes --only openssl,7zip    only these (what the PKI scripts need)
  ./Install-DevEnvironment.sh --yes --skip php,dotnet      everything except these
  ./Install-DevEnvironment.sh --dry-run --only openssl     show the commands, run nothing
  ./Install-DevEnvironment.sh --unblock                    UNBLOCK + UNLOCK this folder, then stop

OPTIONS
  --only LIST            Comma-separated components (above). Default: all.      --skip LIST   All except these.
  --check                Scan only: components found, OpenSSL readiness. Exit 0 when OpenSSL is ready, 4 when not.
  --yes, -y              Do not ask. Needed when there is no terminal.         --dry-run   Print system-changing commands.
  --openssl-prefix DIR   Where OpenSSL is installed. Default /opt/openssl-4.0.3 (macOS: /usr/local/openssl-4.0.3).
  --openssl-version V    Build this version instead of 4.0.3 (4.0.1 or newer).
  --openssl-no-docs      Skip the manual pages (shorter build). The cryptography is still the FULL build.
  --openssl-jobs N       Parallel compile jobs. Default: the number of CPU cores.
  --unblock              UNBLOCK (macOS quarantine mark) and UNLOCK (read-only, immutable, locked flags) this script's
                         folder, children and recursive, then stop. The same is done silently at every start.
  --version              Show the version.                                     --help, -h   This text.

OPENSSL BUILD TIME  (be warned)
  A full build compiles hundreds of files. About 5 minutes on 8 cores, 15 to 25 on 2 cores, and over an hour on ONE core
  (measured: more than 30 minutes without finishing on a 1-core VM). Use a machine with cores, or --openssl-no-docs.

PLATFORMS  (family: package manager)
  Ubuntu, Debian: apt     RHEL, CentOS Stream, Rocky, Oracle, Alma: dnf (yum)     SLES, openSUSE: zypper     macOS: Homebrew
  macOS needs the Xcode command line tools (xcode-select --install) for the OpenSSL build and Homebrew for the others.

EXIT CODES   0 ok   1 error   2 platform not supported   4 OpenSSL not ready   6 a component could not be installed

LIMITATIONS
  * Needs root (or sudo) to install packages and into /opt. Not needed for --check and --unblock.
  * Package names differ between distributions and versions; each component is tried with the usual names and then
    verified, never assumed. dotnet, node, go and php are best effort (your distribution may not ship a current version).
  * Tested on Ubuntu 24.04 (real apt). The other platforms are tested only by simulation (--dry-run). The OpenSSL source build
    was NOT completed here (a 1-core VM); the Configure step, the download, the checksum and the readiness checks were tested.
