 4.5.2  2026-10-05
   + Found by the 4.5.1 read-back on your machine: 6 roots "in BOTH stores". Cause: each leaf PFX contains the
     leaf plus intermediate, Quadrant Root and Track Root (4 certificates); Windows files every non-leaf
     certificate of an imported PFX under Intermediate, so the PFX import put the roots back there AFTER the
     per-certificate placement. Fix: the PFX is loaded in .NET and only the leaf (the certificate with the
     private key) goes to My; and the "remove the copy in the wrong store" pass now runs AFTER the PFX import.
     If the leaf-only route fails (an ML-DSA key an older .NET cannot read) the Windows import is used and the
     final pass cleans up. Tested: leaf extraction from the real PFX files (RSA, ECDSA).
