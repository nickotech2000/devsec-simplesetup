    * Docs: DevKit-MANUAL (sections 4, 5, 6, 8, 15, 17), Install-DevEnvironment-MANUAL (11, 12, 17),
      PkiTransport-MANUAL (5, 7, 14), START-HERE, scripts-README, design 10.192, html.

  7.9.1  2026-10-22  MINOR + REVISION (minor +1, revision 1)
    * PkiTransport.ps1 -Pack: ONE package can hold MANY PKIs. Without a choice it packs EVERY CA of every
      company and every release (normal and NoCR) found in .\pki (also -AllCa). New choices, combinable:
      -Pki a,b (a company name or a <name>_pki.cnf file; -ConfigFile <file> too), -Release 1,3, -Latest,
      -NoCaRevocationInfo, -PkiFolder pki-raksaka-01, -PkiRoot <dir,dir>, -Ca <id | slug | name, wildcards>
      (a root brings every CA below it, any CA its parents: a chain is always complete), -ListCa (show what
      would be packed). Keys: none by default; -IncludeCaKeys (with -Ca: only the keys of the chosen CAs,
      never of a parent that is only there for the chain), NEW -IssuingKeysOnly (intermediate keys only).
      Paths per PKI folder: ca/roots/<folder>-<slug>.crt, ca/intermediates/..., ca/chains/...,
      ca/publish/<folder>/, pki/<folder>/; certpack.json lists the PKIs (pkis) and gives every CA and file
      its company (pki) and folder (release); certpack.tsv has the columns pki, release, id, parent.
      formatVersion stays 1: older readers still open it. Default file name allpki-<date>.certpacked.
    * Unpack-PkiTransport.ps1, PkiTransport.ps1 -Install / -List / -RemoveTrust and pki-transport.sh read
      every PKI of a package (several roots, intermediates, companies, releases); -Pki, -Release (number or
      folder, wildcards), -PkiFolder, -Ca (pki-transport.sh: --pki, --release, --ca) choose some. -List shows
      the PKIs and every CA with company, folder and id. Packages of older versions are read as one PKI
      named from their source folder; the DevKit package now carries the same names.
    * REPLACE: installing a PKI first removes its OLDER copy (same company AND same PKI folder), then adds
      the new certificates. STRICT: a certificate goes only when it is proven ours - its thumbprint is in
      the list of what PkiTransport installed (NEW: %ProgramData%\PkiTransport\installed.tsv, Linux
      /var/lib/pki-transport/installed.tsv) or a trust kit installed for the computer, for that company
      and folder; Windows also: a certificate file of that folder in .\pki. Linux checks that the listed
      file still holds that thumbprint. Never by name: public CAs, other companies' PKIs, other private
      PKIs, a certificate with the same name, a public CA in a file named like ours stay. -KeepOld /
      --keep-old adds only. -RemoveTrust / --remove-trust also update the list (and on Linux check the
      thumbprint before deleting a file). A computer set up before 7.9.1 has no list: nothing is removed
      there (said in the log).
    * Fixed: New-CodeSignCatalog.ps1 / .sh reported version 7.7.1 in -Version / --version.
    * Docs: PkiTransport-MANUAL.txt (sections 4, 5, 7, 8, 9, 11 new, 13, 16, 17), -Help / --help of the
      three transport scripts, design 10.191. Tested on Linux with four test PKIs (two companies, two
      releases, NoCR); the Windows store steps only with simulated stores (no Windows here).

  7.8.3  2026-10-22  MINOR + REVISION (minor +1, revision +2)
    * NEW New-CodeSignCatalog.ps1 / New-CodeSignCatalog.sh (standalone): a signed CATALOG of files that
      cannot hold a signature (json, config, xml, js, css, html, images). PORTABLE catalog on any system:
      <name>.sha256 / .sha512 lists (sha256sum format), each with a detached CMS signature (.p7s) and an
      RFC 3161 timestamp (.tsr). WINDOWS catalog (.cat, version 2 = SHA-256) on Windows with
      New-FileCatalog, signed and timestamped; the .sh signs an existing .cat (--sign-cat). -Verify /
      --verify checks the signature, the certificate, the timestamp, the chain and EVERY file
      (TAMPERED, missing; added files WARN, -Strict FAIL). Each script checks the catalogs of the other.
      Only SHA-256 / SHA-512. Exit 0 / 1 / 2 / 3 / 4 / 6 / 7.
    * Sign-Code.ps1 -Catalog <file.cat>|Auto [-CatalogFolder]: after the files are signed, a Windows
      catalog of the folders (also json, config ...) is made and signed with the same certificate and
      timestamp; -Catalog alone (no file to sign) makes only the catalog. Sign-Code.sh --catalog
      <name>|auto [--catalog-folder] makes a portable catalog (New-CodeSignCatalog.sh next to it).
    * Sign-Code -RemoveOldSignature / --remove-old-signature: a signed file (PowerShell, Windows files)
      gets its old signature removed, then it is signed with the current certificate.
    * Sign-Code faster: -NoRevocationCheck / --no-revocation-check (no CRL / OCSP download while
      signing; NuGet offline revocation), -Timestamp takes a LIST (default DigiCert,GlobalSign): the first
      server that answers is used, and a file whose timestamp fails is signed again with the next one.
      -TimestampCheckCache / --timestamp-check-cache: a server checked less than 30 minutes ago is not
      checked again. The fallback order is DigiCert, GlobalSign, Sectigo, SSL.com, Certum, Entrust,
      Microsoft. Sign-Code.sh also takes --timestamp none.
    * Sign-Code -ReportFile / --report-file: ONE report per build session (parallel builds add to it
      under a lock); -CleanReports / --clean-reports deletes the old sign-report_*.json first.
    * MSBuild (the MakananSisa CodeSigning.targets, Sign-Code-MANUAL section 19): PowerShell scripts that
      a build copies to bin\ / publish\ are signed there (Release by default, Debug optional, their own
      certificate per configuration, an old signature removed first); a new sign report per build;
      the log folders of the project are deleted before every build (never a folder with source code);
      optional signed catalog of the publish folder; DigiCert,GlobalSign; no revocation download in Debug.

  7.7.1  2026-10-22  MINOR + REVISION (minor +1, revision 1)
    * NEW Convert-CodeSignCert.ps1 / Convert-CodeSignCert.sh (standalone, one file each): convert a
      code-signing certificate from a public CA or the private PKI between pfx, p12, keystore, jks,
      pem, crt, cer, key, p7b, spc, pvk and bundle, and back. Platform presets for Windows, Java,
      Android, Apple, Linux, Azure, AWS and Google Cloud. The tools are checked first (exit 4, nothing
      written), the key must match the certificate (exit 2), every output is read back (exit 5), and
      every output gets a .sha256 and a .sha512 file plus <name>-certificate-fingerprints.txt (SHA-256
      and SHA-512 only, never MD5 or SHA-1). Passwords only from environment variables.
    * NEW Verify-CodeSign.ps1 / Verify-CodeSign.sh (standalone): check signed files (Windows files and
      PowerShell, Java jar / aab, Android apk, NuGet, Apple): signed, NOT tampered (the signed hash and
      the -signed.sha256 / .sha512 files of Sign-Code), the signing certificate (subject, issuer,
      serial, RSA / EC key size, digest, SHA-256 and SHA-512 fingerprints), the timestamp and its
      server, and the chain (-ChainFile for a private PKI, at the time of the timestamp). Rules:
      -ExpectSha256, -ExpectSubject, -MinRsaBits, -RequireTimestamp, -Strict; MD5 / SHA-1 digests fail.
      Exit 0 / 1 / 4 / 6 / 7, a JSON report, annotations for GitHub, Azure DevOps and MSBuild.
    * Manuals Convert-CodeSignCert-MANUAL.txt and Verify-CodeSign-MANUAL.txt (also as html pages).

  7.5.2  2026-10-21  MAJOR + MINOR + REVISION (major +1, minor 5, revision 2)
    * New: GenerateCodeSigningCertificate.ps1 and its Linux twin devkit/GenerateCodeSigningCertificate.sh.
      CODE SIGNING certificates only, OV or EV (default EV), one per platform you name: Windows
      (Authenticode exe dll sys msi msix cab cat, PowerShell, VBA, NuGet; -LifetimeSigning,
      -KernelMode), Java (jarsigner), Android (apksigner; OV valid 25 years), Apple (Mach-O, .app,
      .dmg; -AppleType Installer adds the .pkg purpose), All, or -Combined (one for all).
    * Issuer: the intermediate of the level (q1-ev / q1-ov ...), the Quadrant Root (-Issuer
      QuadrantRoot), any CA of this PKI (-IssuerId), or a CA on this computer that is not of this
      PKI: PEM files (-IssuerCert / -IssuerKey), a PFX (-IssuerPfx), the Windows store
      (-IssuerThumbprint). -ListIssuers shows them. The Enterprise Root and the Track Roots never sign.
    * RSA 4096 + SHA-256 by default; -KeyBits 4096 6144 7680 8192, -Curve P-384 P-521, -Hash sha256
      sha384 sha512 sha3-256 sha3-384 sha3-512. Weak values are rejected. EV adds businessCategory,
      jurisdiction and serialNumber and is valid 397 days at most. CA/B Forum code signing policy
      (OV 2.23.140.1.4.1, EV 2.23.140.1.3) unless -NoCabfPolicy.
    * Every format of GenerateLeafCertificate (crt key pub pem der cer cert p7b rfc7468 pfx, chain,
      fullchain, hash files, convert-formats.ps1) plus CODESIGN-NOTES.txt with the signing commands.
      Output: leafcerts\codesign\<company>\<platform>\ (only code signing certificates), never
      overwritten, all or nothing. PFX password Abc12345! by default (change it for real use).
      leafcerts\codesign\codesign-index.json / .tsv lists them (no passwords) for Sign-Code.
    * New: [ codesign ] section in agantra_pki.cnf (Level Platform KeyType KeyBits Curve Hash DaysOV
      DaysAndroid Company CabfPolicy Folder). New module scripts\24_CodeSigning.ps1.
    * GenerateLeafCertificate: -Hash also takes sha3-256 / sha3-384 / sha3-512, RSA also 6144 /
      7680 / 8192 (shared code in 14_LeafGenerator.ps1; 06_Validation.ps1 accepts SHA-3).
    * Sign-Code.ps1 / Sign-Code.sh, updated:
      - -UseGenerated / --use-generated: takes, per file, the newest valid generated certificate of
        its platform and its chain (password SIGN_PFX_PASSWORD, else Abc12345!).
      - New certificate sources: -CertFolder / --cert-folder (a local folder), -Subject with
        -StoreLocation CurrentUser | LocalMachine and -StoreName (Windows certificate manager).
        Sign-Code.sh checks the chain against the ca-certificates bundle (--trust-store).
      - Timestamp: DigiCert stays the default; added Microsoft, Apple, IdenTrust, QuoVadis,
        SwissSign, Buypass, HARICA, FreeTSA; -TimestampFallback / --timestamp-fallback tries the
        next server when one fails its check.
      - Apple: Mach-O (found by its first bytes), dylib, bundles (.app .framework ...), dmg, pkg,
        signed with rcodesign (installed with cargo when missing).
      - Build systems detected: GitHub Actions, Azure DevOps Services (cloud) and Azure DevOps
        Server (on premises), GitLab, Jenkins, TeamCity, Bitbucket, AWS, Google Cloud, Visual
        Studio / MSBuild; pipeline mode switches on by itself there. Annotations for GitHub, Azure
        DevOps, TeamCity and the Visual Studio Error List. New -Template azure-server, gitlab,
        jenkins, bitbucket, teamcity; Sign-Code.targets takes -p:SignCodeArgs (e.g. -UseGenerated).
      - -Verbose / --verbose: every step, every command line (passwords as ***) and tool output.
      - Fixes: -File / -Folder lists work under pwsh -File ("a.exe,b.dll"); the Java key alias
        is read from keytool -v (an alias with a comma failed); Sign-Code.sh checks the code signing
        purpose with OpenSSL 3.4+ ("codesign"; "codesigning" was refused, so no chain ever
        verified); its temporary files are in one private folder that is always removed.
    * Tested here (Linux, OpenSSL 4, pwsh 7, a local RFC 3161 server): every platform, EV and OV,
      FIPS ECDSA P-521, RSA 8192 + SHA3-512, an external CA as files and as PFX, both twins; jar
      files signed and timestamped by both Sign-Code scripts. NOT tested: signtool, osslsigncode,
      apksigner, rcodesign and the real timestamp servers (not on this machine / no internet),
      real pipelines, Windows.
