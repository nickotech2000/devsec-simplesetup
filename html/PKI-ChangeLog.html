Change log

What changed in each version.

 Version : 6.4.1                      Updated: 2026-10-17
 Author  : Nicko Satria Utama   Company: Agantra Inovatif OU (NextMantra)
 Email   : nicko@nextmantra.com
 What    : what changed in each version, newest first. The reasons are the numbered decisions in
           PKI-Design-with-FIPS-and-PQC.txt (section 10);  what to run to accept a version is in
           PKI-Acceptance-Checklists.txt.
 Rule    : major.minor.revision. A major update changes the architecture, a minor one adds a

feature, a revision is a fix or any update not called major / minor.#

READ THIS FIRST#

 What it is   : What changed in each version, newest first.
 Who reads it : Everyone.
 You need     : None.
 Start with   : Read the top entry.
 Words        : GLOSSARY.txt (technical terms), GLOSSARY-ENGLISH.txt (everyday English words)
  6.4.1  2026-10-17  MINOR UPDATE (minor 4, revision 1)
    + pki_setup: the manual is written again from the start (docs\pki_setup-MANUAL.txt) in short,
      dry English for people who are new to PKI: what the script does, the words you need, before
      you start, first run step by step, which quadrant, what is created, trust on every device,
      many PKIs and releases, names, public CA root, maintenance, removing, problems and answers,
      limits, all options, what was tested (10.171).
    + pki_setup -Help is written again with the same order as the manual: what it does, quick
      start, common commands, what is built, where it runs, options in groups, names, releases,
      Windows trust, check, public CA root, output, limits. 100 columns, one page at a time
      (10.171).
    + Wrong or old statements are gone: Windows 10, RHEL 9 and macOS are not supported hosts (the
      platform check refuses them); "Phase A" notes; the copy of the old -Help inside the manual;
      the nginx / Apache examples (now Create-WebServerConfig); a command that the line wrapping
      had joined to its comment.
    + Glossary: new words for quadrant, track, release, NoCR, profile, PEN, SAN, pathlen, EKU,
      PFX, ML-KEM, ML-DSA and more (10.172). Other documents point to the new section numbers.
    + The script itself is unchanged. Only the help text, the manual and the documents changed.

  6.3.6  2026-10-17  MAJOR UPDATE (major 6, minor 3, revision 6)
    + NEW Export-PkiCa.ps1: takes CA certificates out of the PKI (all roots, one root, one
    intermediate, or a whole path from a root to an intermediate; normal PKI, NoCR PKI or both) in
    PEM, CRT, CER, DER, P7B and TXT, each CA in its own sub-folder, with .sha256 / .sha384 / .sha512
    hash files (or one hash chosen by the key strength). No key by default; -IncludeKey adds an
    encrypted key and PFX (10.150).
    + Export-PkiCa.ps1 -Target: copies named for CDNs and clouds (xxx.cloudflare.pem / .crt, azure,
    cloudfront, alibaba, google, akamai); default Cloudflare. Warnings for ML-DSA CAs (not accepted
    by CDNs) and RSA-8192 (too big for many services). The folder is
    transport\ca-export_<where>_<what>_<key|nokey>_<targets>_<date-time>\ (10.151). +
    Export-PkiCa.ps1 -Leaf: give a leaf certificate (PEM, DER, chain, P7B, PFX; with or without its
    key) and it finds and exports the intermediates and the root, for your PKI or a public CA
    (10.152). + NEW Create-WebServerConfig.ps1 / .sh: nginx and Apache configuration for a leaf
    certificate, in separate folders under transport\webconfig_...; HTTPS only, TLS 1.3 by default
    (-Tls12 adds 1.2), Kestrel as the upstream, server names from the certificate, ciphers / groups
    / signature algorithms chosen from the certificate type, level and FIPS flag, QUIC / HTTP/3,
    Brotli and gzip, TCP and UDP stream, ECH, nginx 1.30 or newer only, step-by-step wizard, output
    to screen and / or files (10.153 - 10.156). + Create-WebServerConfig has -Distro Auto | Ubuntu |
    RHEL: Ubuntu / Debian paths, users and tools, or CentOS Stream / RHEL / Rocky / Oracle Linux
    paths, users, SELinux and firewalld (10.154). + Create-WebServerConfig.ps1 / .sh are inside the
    DevKit, inside every PkiTransport package kit and inside every package of
    New-PkiServerPackage.ps1 (10.157). + NEW Sign-Code.ps1 (Windows 11, Server 2022 / 2025) and
    Sign-Code.sh (Ubuntu 24 / 25, CentOS Stream 10, Rocky 10, Oracle Linux 10): signs Windows files,
    PowerShell scripts, .NET assemblies and NuGet packages, Java (jar war ear aab), Android APK and
    Office VBA with a private-PKI leaf or a public OV / EV certificate (10.158, 10.161). + Sign-Code
    checks the certificate BEFORE signing and refuses (exit 2) one that is not a code-signing
    certificate, is a CA, is expired, too weak or ML-DSA; it checks the timestamp server with a real
    RFC 3161 request and checks the timestamp certificate (exit 3). Default timestamp server
    DigiCert; GlobalSign, Certum, Sectigo, SSL.com, Entrust or any URL by parameter (10.158,
    10.159). + Sign-Code installs missing tools: winget (default) or Chocolatey on Windows; apt
    (with a PPA), dnf (with EPEL or a COPR) or Maven Central on Linux (10.160). + Sign-Code writes
    <file>-signed.sha256 and <file>-signed.sha512 for every signed file, shows the certificate, and
    writes sign-report_<time>.json (10.162). + Sign-Code runs in build environments (same version,
    6.3.6): -Ci / --ci pipeline mode; secrets from environment variables (PFX as base64); key
    services through -Provider (Azure Key Vault, Artifact Signing, AWS KMS, Google Cloud KMS,
    PKCS#11, DigiCert KeyLocker); -Template writes starting files for GitHub Actions, Azure DevOps
    (Services and Server), AWS CodeBuild, Google Cloud Build, Alibaba Cloud Yunxiao and a Visual
    Studio 2026 / MSBuild .targets file; the manual has a DevSecOps setup chapter and -Help / --help
    a BUILD ENVIRONMENT SETUP section (10.163). + The three leaf generators
    (GenerateLeafCertificate, GeneratePersonLeafCertificate, GenerateOffice365LeafCertificate; .ps1
    and .sh) now write hash files next to every certificate: <name>.sha256 and <name>.sha512, and
    other hashes with -HashFile / --hash-file (10.164).
    + Build-HtmlDocs.ps1 -Watch rebuilds the html\ folder on every save of a text document; -IfStale
    rebuilds only when needed; the git pre-commit hook does it before every commit. + ALL
    documentation: rewritten for junior developers and infrastructure staff in plain English,
    wrapped for 100 columns (laptop 720p and Full HD), and made into single-file HTML5 pages in the
    folder html\ (index.html + one page per document; no zip) for Chrome, Edge, Firefox, Safari,
    Brave, Opera, UC and QQ browsers (10.165). -Help / --help texts wrapped the same way. + The
    version in every .ps1 and .sh is 6.3.6. Sign-Code and Create-WebServerConfig have no "Pki" in
    the name (10.166).

 4.5.2  2026-10-05
   + Found by the 4.5.1 read-back on your machine: 6 roots "in BOTH stores". Cause: each leaf PFX
   contains the leaf plus intermediate, Quadrant Root and Track Root (4 certificates); Windows files
   every non-leaf certificate of an imported PFX under Intermediate, so the PFX import put the roots
   back there AFTER the per-certificate placement. Fix: the PFX is loaded in .NET and only the leaf
   (the certificate with the private key) goes to My; and the "remove the copy in the wrong store"
   pass now runs AFTER the PFX import. If the leaf-only route fails (an ML-DSA key an older .NET
   cannot read) the Windows import is used and the final pass cleans up. Tested: leaf extraction
   from the real PFX files (RSA, ECDSA).
 4.5.1  2026-10-05
   + The stores are READ BACK after every install and in -Verify (Get-PkiStorePlacement, pure and
   tested): roots must be in Trusted Root, intermediates in Intermediate, none in both. A wrong
   placement is an ERROR (install) / FAIL (-Verify) with the certificate named; "older generation"
   certificates with this PKI's name that are not in the current PKI are listed and left alone.
   Tested with your screenshot state: 6 roots under Intermediate = 6 x WRONG STORE, fixed by
   -ReinstallTrust.
 4.5.0  2026-10-05
   + Found in your A4 run and fixed: ConvertFrom-PkiPemToDer returned object[] (PowerShell unrolled
   the bytes), so X509Certificate2 read it as a path ("cannot find the path"); installs had worked
   only through the certutil fallback, and -Verify could not read the leaves. Now byte[] everywhere.
   + Stores: every root (Enterprise, Track, Quadrant) -> Trusted Root, every intermediate ->
   Intermediate; certificates in the wrong store are moved. The decision comes from the kind of CA,
   not from the manifest. + -ReinstallTrust: install the existing PKI again, no rebuild, no OpenSSL.
   + OpenSSL: every candidate is asked, the newest 4.x wins (a 3.x earlier in PATH is skipped and
   named); 3.x is refused with HOW TO FIX steps naming Install-DevEnvironment.ps1; discovery covers
   the FireDaemon folders. Commands without a PKI configuration use a neutral config, so a
   machine-wide OPENSSL_CONF (master file with oqsprovider) cannot interfere.
   + Capability gate before generation: ML-DSA (quadrant 3 non-FIPS, quadrant 4 FIPS) and the FIPS
   provider are proven first.
