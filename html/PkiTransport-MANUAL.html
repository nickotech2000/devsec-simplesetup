1 WHAT THE TRANSPORT IS

A PKI built by pki_setup.ps1 lives on one machine. The transport carries it to your other machines (development and staging VMs, Mac minis) as ONE password-protected file with the extension .certpacked, and puts it where it is needed: the system certificate store (to TRUST the PKI), a folder (to use the files), or the whole PKI (to ISSUE).

 Three scripts, each with its own job:
     PkiTransport.ps1          SOURCE: -Pack makes the .certpacked.   DESTINATION (Windows 11 25H2
                                                                      or newer only):
                               -Install scans the machine, unpacks, installs the trust.
     Unpack-PkiTransport.ps1   DESTINATION, UNPACK ONLY: any machine with PowerShell 7 (Windows,
                               Linux, macOS).
     pki-transport.sh          DESTINATION, Linux and macOS: scan, prepare, unpack, install the
                               trust in the system store.
 They reuse the scripts folder (module set Transport: 00_Common, 02_OpenSSL, 07_TrustStore,
 09_Administrator, 16_CertPack, 17_Transport). -Pack with -Kit writes a small kit next to the

package so a destination needs nothing else.#

2 THE .CERTPACKED FILE AND ITS SECURITY

A .certpacked IS an archive under another name. Rename it to .zip or .7z and 7-Zip opens it with the password. The scripts read the first bytes of the file, never the extension.

   Kind                      Made and read by                           Needs on the destination
   ------------------------  -----------------------------------------  ------------------------------------------
   zip + AES-256 (default)   PkiTransport.ps1 itself (WinZip AE-2:      Windows: nothing. Linux /
                                                                        macOS: 7-Zip
                             PBKDF2-HMAC-SHA1, AES-256-CTR, HMAC-SHA1   (7z, 7zz, 7za); pki-transport.sh installs it
                             over every file)                           where it can
   zip + ZipCrypto           the same engine (-ZipEncryption            Plain unzip. WEAK (known-plaintext attack):
                             ZipCrypto)                                 only for packages without private keys
   7z + AES-256              7-Zip (-ArchiveFormat 7z): LZMA2, file     7-Zip on both sides
                             names encrypted too, much smaller
 WHAT IS IN IT (the SCOPE; certpack.json says which)
   CA certificates only (default)   roots, intermediates, chains, bundles, CRLs: PUBLIC data; enough
                                    to TRUST the PKI
   + -IncludeLeafCerts              the leafcerts folders: leaf certificates AND THEIR PRIVATE KEYS
   + -IncludeCaKeys                 the whole pki folder with the CA PRIVATE KEYS: the destination
                                    can ISSUE certificates
 Files in the archive: certpack.json (everything, for PowerShell), certpack.tsv (one line per file,
 for shell scripts), SHA256SUMS, README.txt, ca\roots\<slug>.crt (Enterprise, Track and Quadrant
 roots), ca\intermediates\<slug>.crt (DV /
     OV /
 EV), ca\ca-bundle-roots.crt, ca\ca-bundle-all.crt, ca\chains\<slug>-fullchain.crt (an intermediate
 and its parents, one
     file
 each), ca\publish\*, [ca\external-chain.pem, ca\cross-sign\*], [leafcerts\*], [pki\*].
 SAFEGUARDS
   * Every file has its SHA-256 in the package. The destination checks ALL of them before it writes
     anything, and the AES-256 zip authenticates every entry: one changed byte stops the unpack.
   * A wrong password writes nothing. A name inside the archive that tries to leave the destination
     (../..) is refused.
   * ZipCrypto is refused for a package with private keys. The password must be printable ASCII, 12+
     characters, three
       of
     four character classes (7-Zip cannot create AES zips with other characters).
   * The SHA-256 of the .certpacked itself is printed by -Pack: compare it after the transfer.
   * You must still protect the file and the password. Send them by different channels. A package
     with private keys is as sensitive as the keys: delete the package and the extracted keys when

the job is done.#

3 QUICK START

 SOURCE (your build machine, PowerShell 7):
     .\PkiTransport.ps1 -Pack -GeneratePassword -Kit                   CA certificates only; shows the password ONCE
     .\PkiTransport.ps1 -Pack -IncludeLeafCerts -GeneratePassword -Kit      with the leafcerts folders (private keys)
 Copy the .certpacked and the <name>-kit folder to the destination; send the password another way.
 DESTINATION, Windows 11 25H2 or newer (elevated PowerShell 7), in the kit folder:
     .\PkiTransport.ps1 -Check                                          the scan only
     .\PkiTransport.ps1 -Install -Package ..\name.certpacked             scan, unpack, install the trust
 DESTINATION, any OS with PowerShell 7, unpack only:
     .\Unpack-PkiTransport.ps1 -Package ..\name.certpacked -Extract roots
 DESTINATION, Linux or macOS:
     sudo ./linux/pki-transport.sh --package name.certpacked --yes            unpack the CAs, install the roots in the system
         store
     ./linux/pki-transport.sh --package name.certpacked --no-trust --extract fullchain      unpack everything, install nothing

4 PACK (THE SOURCE MACHINE)#

 .\PkiTransport.ps1 -Pack [options]        Every option: section 13.   The PKI is read from .\pki
                                                                       (-PkiRoot), the leaf
 certificates from <script folder>\leafcerts (the folder of GenerateLeafCertificate.ps1).
   -Out <file>           default .\transport\agantra-pki-<yyyyMMdd-HHmmss>.certpacked. The extension is always
                         .certpacked (a
                         name ending in .zip or .7z is changed, with a warning).
   -GeneratePassword     a 20-character password, shown once at the end. Otherwise -PackagePassword,
                         the environment variable PKI_TRANSPORT_PASSWORD, or a prompt (asked twice).
   -ArchiveFormat zip|7z and -ZipEncryption Aes256|ZipCrypto (section 2).     -SevenZipPath for 7z.
   -IncludeLeafCerts [-LeafName a*,b]   the leafcerts folders (all, or those whose top-level folder
                                        matches).
   -IncludeCaKeys        the whole PKI with the CA private keys. Use it only for a machine that must
                         issue certificates.
   -Kit                  writes <name>-kit\: the three transport scripts, the modules, the manual.
   -Comment <text>       stored in the package and shown on opening.        -NoVerify   skip the read-back.
 After writing, the package is read back (every entry decrypted and authenticated) unless -NoVerify.
 A PKI whose Enterprise Root was signed by a public CA is packed with ca\external-chain.pem and the

cross-certificates.#

5 WINDOWS DESTINATION: SCAN AND INSTALL

 .\PkiTransport.ps1 -Check [-Package <file>]     the scan; with -Package also whether the password
                                                 opens the file
 .\PkiTransport.ps1 -Install -Package <file>     the scan, then (only if it passes) unpack and
                                                 install
 THE SCAN (nothing is unpacked or installed unless all of it passes)
   Windows      Windows 11 client, version 25H2 (build 26200) or NEWER. Not supported, with the
                reason printed and exit code 2:
                  Windows 11 24H2 / 23H2 / 22H2 / 21H2, Windows 10, 8.1, 7, Vista, XP, every Windows
                  Server and domain
                      controller,
                  anything that is not Windows.   (Windows 11 26H2, build 26300, is accepted.)
   OpenSSL      4.0.1 or newer (4.0.1 to 4.0.3 tested). Missing or older: the script stops with exit
                code 4 and prints the way to
                  install it: run Install-DevEnvironment.ps1 (OpenSSL with FIPS and quantum
                  support). -SkipOpenSslCheck
                      goes on anyway.
   Elevation    an administrator PowerShell, checked BEFORE anything is unpacked.
   Also shown   the PowerShell version and whether 7-Zip exists (only a 7z package needs it).
 Only a Windows 11 25H2+ machine can hold the post-quantum (ML-DSA) CA certificates of the Quantum
 quadrants; this is
     why older
 Windows is refused instead of installing half of the PKI.
 WHAT -Install DOES, IN ORDER
   1. opens the package, checks the SHA-256 of every file;       2. writes the selection (-Extract, default ca) to
                                                                 -Destination
   3. every ROOT -> Trusted Root Certification Authorities, every INTERMEDIATE -> Intermediate
      Certification Authorities (the rules of pki_setup.ps1 -InstallTrust); the stores are read back
      and any wrong placement is an error
   4. -InstallLeafPfx: the leaf PFX files into LocalMachine\My - the LEAF only, never the chain
      certificates inside the
       PFX
   5. OpenSSL 4 proves that every CA and every extracted leaf chains to the roots of the package
      (ML-DSA signatures too)
 -RemoveTrust -Package <file> removes the package's CA certificates from the stores (leaf PFX files
 in My stay). Exit codes: 0 ok, 1 error, 2 Windows not supported, 3 not Windows (use
 pki-transport.sh), 4 OpenSSL 4.0.1+ missing.

Test exit codes with pwsh -File .\PkiTransport.ps1 ... ("pwsh -Command" only reports 0 or 1).#

6 UNPACK ONLY (ANY MACHINE, POWERSHELL 7)

 .\Unpack-PkiTransport.ps1 -Package <file> [-Extract <list>] [-LeafName <w>] [-Destination <folder>] [-List] [-Force]
 It installs NOTHING and has no operating-system restriction. Default destination
 .\certpacked-received\<package name>. certpack.json and README.txt are always written. Identical
 files already there are left alone; a different file stops
     the
 run unless -Force. -Extract pki also rewrites the absolute paths of pki\pki-manifest.json to the
 new place, so GenerateLeafCertificate.ps1 -PkiRoot <folder>\pki issues certificates from the

transported PKI (tested).#

7 LINUX AND MACOS: pki-transport.sh

 ./linux/pki-transport.sh --package <file> [options]   Every option: section 15. Written for bash
                                                       3.2 (macOS) and newer.
 It does only this: scan, prepare, unpack, install the CA certificates in the system store, prove
 the chains, nothing
     else.
 PLATFORMS                                  trust anchors go to                      store command
   Ubuntu, Debian                           /usr/local/share/ca-certificates         update-ca-certificates
   RHEL 9, CentOS Stream 10, Rocky 10,      /etc/pki/ca-trust/source/anchors         update-ca-trust extract
     Oracle Linux 10, Alma Linux
   SLES 16, openSUSE Leap / Tumbleweed      /etc/pki/trust/anchors                   update-ca-certificates
   macOS (M2, M4, Intel)                    /Library/Keychains/System.keychain       security add-trusted-cert (roots)
   other Linux                              --store-dir DIR                          --update-cmd CMD
 The family is read from /etc/os-release (ID and ID_LIKE). Files it adds are named agantra-pki-*, so
 --remove-trust
     takes
 out exactly those.
 THE STEPS
   SCAN      platform, privileges (root or sudo), OpenSSL 4.0.1+, 7-Zip, unzip, the
             certificate-store tooling.
   PREPARE   * certificate store missing (a minimal image): installs ca-certificates with the
             package manager of the family. * 7-Zip missing and the package needs it (AES-256 zip or
             7z): installs it. Order tried: 7zip, p7zip +
                 p7zip-plugins,
               p7zip-full; on the RHEL family EPEL is added when needed; macOS: brew sevenzip. A
               ZipCrypto zip needs
                   only unzip.
             * OpenSSL 4.0.1+ missing: asks to build OpenSSL 4.0.3 from the official source release
               (or
                 --install-openssl; or exit
               code 4 without a terminal). The tarball is checked against the .sha256 of the same
               release page; built
                   with the FIPS
               module into --openssl-prefix (default /opt/openssl-4.0.3); the system openssl is left
               alone.
   UNPACK    password from --password-file, PKI_TRANSPORT_PASSWORD or a prompt; every SHA-256
             checked; the selection is written.
   INSTALL   --trust roots (default: Enterprise, Track and Quadrant roots), enterprise (only the
             Enterprise Root), all-ca (roots and intermediates; macOS: intermediates without trust
             settings), none. Then the store is rebuilt and
                 OpenSSL 4
             verifies every CA against the SYSTEM store.
 --no-trust unpacks only. --remove-trust takes the CAs out (with --package: exactly that package's;
 without: every
     agantra-pki-*).
 --dry-run prints every system-changing command. --destdir DIR puts the anchors under DIR and does
 not rebuild the store
     (image builds).
 --check is the scan only. Exit codes: 0 ok, 1 error, 2 platform not supported, 4 OpenSSL missing, 5
 wrong password, 6

prerequisite.#

                                  for what the

9 PASSWORDS

 Printable ASCII only, at least 12 characters, at least 3 of: lower case, upper case, digits,
 symbols.
     -AllowWeakPassword relaxes
 length and classes, never the ASCII rule. -GeneratePassword makes a 20-character password without
 quotes, $, ! or
     backslash, so it
 pastes safely into any shell. Where the password goes at the destination, safest first: the prompt,
 a file
     (--password-file, on
 the shell side only), the environment variable PKI_TRANSPORT_PASSWORD, then -PackagePassword /
 --password (visible in a
     process

list and in the shell history).#

 A smaller package (7z)                          .\PkiTransport.ps1 -Pack -ArchiveFormat 7z -GeneratePassword
 No 7-Zip anywhere, CA certificates only         .\PkiTransport.ps1 -Pack -ZipEncryption ZipCrypto -GeneratePassword
                                                 (then unzip -P works)
 Take the CAs out again                          .\PkiTransport.ps1 -RemoveTrust -Package <file>        or        sudo
                                                 ./linux/pki-transport.sh --package <file> --remove-trust

                                                 ./linux/pki-transport.sh --package <file> --list
 Image build (Dockerfile, VM template)           ./linux/pki-transport.sh --package <file> --destdir /target --yes     then

11 TROUBLESHOOTING

Message / symptom Cause and fix#

 "Windows 11 before 25H2 ... not supported"         Update to Windows 11 25H2 (build 26200) or
                                                    newer. Windows 10 and older cannot be used for
                                                    -Install
 "Windows Server ... not supported"                 Client Windows 11 only. Use
                                                    Unpack-PkiTransport.ps1 and import the roots by
                                                    hand if you must
 "OpenSSL ... not found / too old" (exit 4)         Run Install-DevEnvironment.ps1 (output says
                                                    how), new window; or -OpenSslPath; shell:
                                                    --install-openssl
 WRONG_PASSWORD (exit 5 on the shell side)          Wrong password or damaged file; nothing was
                                                    written. Compare the SHA-256 printed by -Pack
 "AUTHENTICATION_FAILED: x is damaged"              A byte changed in transit: copy the file again
 "The package does not match its own list"          Same: damaged or changed
 "password is not accepted"                         12+ printable ASCII characters, 3 classes: use
                                                    -GeneratePassword
 "ZipCrypto ... refused for a package with keys"    Use Aes256 when the package has private keys
 "7-Zip was not found"                              7z packages and (Linux, macOS) AES zips need
                                                    7-Zip: the shell script installs it; --7z /
                                                    -SevenZipPath
 7-Zip install fails on RHEL / Rocky / Oracle        Enable EPEL (and CRB / CodeReady) or give --7z;
                                                     or re-pack with -ZipEncryption ZipCrypto (CA
                                                     certificates only)
 "exists and differs"                               -Force / --force, or another destination
 "Nothing in this package matches ..."              The package lacks it (scope): the message lists
                                                    what it holds
 macOS refuses ML-DSA certificates                  Expected on a macOS without post-quantum
                                                    support: the classic CAs install, the script
                                                    says which were refused
 Exit code is always 0 or 1                         You used pwsh -Command: use pwsh -File to see 2,
                                                    3, 4
 Blocked / read-only files                          .\PkiTransport.ps1 -Unblock (the same mechanism

as the other scripts)#

anchor on Linux.#

13 PkiTransport.ps1 -Help (THE COMPLETE TEXT)

PkiTransport.ps1 - carry the PKI to other machines (.certpacked) Version 6.4.1 Author : Nicko Satria Utama Company: Agantra Inovatif OÜ (NextMantra) Email : nicko@nextmantra.com

 Manual : docs\PkiTransport-MANUAL.txt   Design : docs\PKI-Design-with-FIPS-and-PQC.txt (section 17)
 Needs  : PowerShell 7+. Source: the PKI made by pki_setup.ps1. Destination: see -Install.
WHAT IT DOES
  -Pack      SOURCE.      Makes a password-protected  .certpacked  file from the PKI.
  -DevKit    SOURCE.      ONE zip for your developers: the .certpacked, the installers (Windows ps1,
                          Ubuntu sh), the leaf / person /
             Office 365 generators and SignCsr (ps1 and sh), Make-ShExecutable.ps1 /
             make-executable.sh, devkit.env, the manuals. See DEVKIT.
  -CrlServer SOURCE.      ONE SMALL zip (-Tar: also .tar.gz) for a CRL / CA-certificate server ONLY
                          on Ubuntu 24.04 / 26.04 (nginx; no OCSP, no time stamping,
             no OpenSSL 4, no key): pki-server.sh + pki\publish + pki\server. See chapter 21.
  -CrlOcspServer SOURCE.  ONE zip for a CRL + OCSP server on Ubuntu 24.04 / 26.04 WITHOUT time stamping (pki-server.sh install --no-tsa). No key inside. See chapter 22.
  -TimestampServer SOURCE. ONE zip for a TIME STAMP server only (RFC 3161) on Ubuntu 24.04 / 26.04
  (pki-server.sh install --tsa-only). No key inside. See chapter 23.
  -Server    SOURCE.      ONE zip (-Tar: also .tar.gz) for the Ubuntu CRL / OCSP / time stamp
                          server: pki-server.sh + the PKI without private keys
             (the CA keys NEVER go there) + the server\ files of the PKI. No password: the package
             holds nothing secret. See SERVER.
  -Install   DESTINATION. Windows 11 25H2 or newer ONLY. Scans the machine; only if the scan passes
             it unpacks the package and installs the CA certificates in the Windows certificate
             stores.
  -Check     DESTINATION. The scan only (nothing is changed): READY or NOT READY.
  -List      Shows what is inside a package.
  -RemoveTrust  Removes the CA certificates of a package from the Windows stores (elevated).
  The three scripts of the transport:
      PkiTransport.ps1           pack (source) and install (Windows 11 25H2+)          this script
      Unpack-PkiTransport.ps1    destination, UNPACK ONLY (any machine with PowerShell 7)
      pki-transport.sh           Linux and macOS: unpack and install the trust in the system store
A .certpacked IS an archive: rename it to .zip or .7z and 7-Zip opens it with the password.
  zip + AES-256 (default)  made and read by this script itself: nothing to install on Windows.
  zip + ZipCrypto          legacy, weak: only for packages with NO private keys. Plain "unzip -P"
                           reads it.
  7z  + AES-256            file names hidden too. Needs 7-Zip to make and to read.
PACK  (source)
  .\PkiTransport.ps1 -Pack -GeneratePassword                      CA certificates only
