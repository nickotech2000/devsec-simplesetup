READ THIS FIRST#

 What it is   : Three scripts that move the PKI from one computer to another in ONE encrypted file
                (.certpacked), and install the trust there. PkiTransport.ps1 also builds the
                DevKit and the server packages.
 Who reads it : The OWNER of the PKI, and the IT staff who install on other computers. No PKI
                knowledge is needed. Every new word is explained in GLOSSARY.txt and
                GLOSSARY-ENGLISH.txt.
 Time needed  : 15 minutes to read sections 1 to 5. A pack or install takes about one minute.
 You need     : Source: the PKI from pki_setup.ps1 and PowerShell 7.
                Destination: Windows 11, Windows Server or Linux. Section 3 lists the details.
 Start with   : Section 3 (Before you start), then section 4 (Quick start).
 Related manuals:

1 WHAT THE TRANSPORT DOES#

The PKI from pki_setup.ps1 lives on one computer. Your other computers must trust it. The transport carries it there:

     SOURCE (the computer with the pki folder)          DESTINATION (the other computers)
     PkiTransport.ps1 -Pack  --->  name.certpacked  --->  Windows : PkiTransport.ps1 -Install
                                   (one encrypted        any OS   : Unpack-PkiTransport.ps1
                                    file + password)     Linux    : pki-transport.sh

There are three scripts:

 Script                     Where     Job
 -------------------------  --------  -----------------------------------------------------------
 PkiTransport.ps1           Source    -Pack makes the package. -DevKit, -Server and others make
                                      special zips.
                            Windows   -Install checks the computer, unpacks and installs the trust.
 Unpack-PkiTransport.ps1    Any       Only unpacks. Installs nothing.
 pki-transport.sh           Linux     Checks, prepares, unpacks and installs the trust in the
                                      system store.

With -Kit, -Pack also writes a small folder (<name>-kit) with the scripts, so that the destination needs nothing else.

2 THE WORDS YOU NEED#

 Package        The .certpacked file. It is an archive with a password.
 Source         The computer that holds the PKI. You pack here.
 Destination    The computer that receives the package.
 Trust          Put the root CAs into the computer, so that programs accept your certificates.
 Root, intermediate   The CAs at the top and the CAs below them. Roots go to the "Trusted Root"
                store. Intermediates go to the "Intermediate" store.
 Scope          What the package holds: only public CA certificates, or also private keys.
 SHA-256        A fingerprint of a file. If one byte changes, it changes.
 AES-256        A strong way to encrypt. The package uses it.
 Full list      GLOSSARY.txt and GLOSSARY-ENGLISH.txt.

3 BEFORE YOU START#

SOURCE 1. The PKI exists (pki_setup.ps1 was run, folder .\pki). 2. PowerShell 7. 3. A way to send the file, and ANOTHER way to send the password.

 DESTINATION (the scripts refuse other systems with exit code 5)
   Windows   : Windows 11 24H2 or newer, Windows Server 2025, Windows Server 2022. Windows Server
               2022 gets the Classic CAs only (no post-quantum CAs). Administrator rights are
               needed for -Install.
   Linux     : Ubuntu 24+, CentOS Stream 10+, RHEL 10+, Rocky 10+, Oracle Linux 10+, SUSE Linux
               Enterprise 15+, openSUSE. root or sudo for the system store.
   Not supported: Windows 10, older Windows 11, macOS and the special editions.
   Unpack-PkiTransport.ps1 needs only PowerShell 7 and runs on the same systems.
   OpenSSL 4.0.1 or newer is needed to prove the chains. 7-Zip is needed only for 7z packages (and
   for AES-256 zips on Linux). The scripts can install both (section 12).

4 QUICK START#

 1. SOURCE. Make the package:
        .\PkiTransport.ps1 -Pack -GeneratePassword -Kit
    The password is shown ONCE at the end. Write it down.
 2. Copy the .certpacked and the <name>-kit folder to the destination. Send the password another
   way.
 3. DESTINATION, Windows (PowerShell 7 as administrator, in the kit folder):
        .\PkiTransport.ps1 -Check                                      the scan only
        .\PkiTransport.ps1 -Install -Package ..\name.certpacked        scan, unpack, install
    DESTINATION, Linux:
        sudo ./linux/pki-transport.sh --package name.certpacked --yes
    DESTINATION, only unpack, any computer:
        .\Unpack-PkiTransport.ps1 -Package ..\name.certpacked -Extract roots
 4. Test: open a page with a certificate from your PKI. The browser must show no warning
    (Firefox has its own store: import the root there).

5 MAKE A PACKAGE (-Pack)#

 .\PkiTransport.ps1 -Pack [options]
 The PKI is read from .\pki (or -PkiRoot). Leaf certificates are read from .\leafcerts.

WHAT IS IN THE PACKAGE (the scope; certpack.json says which)

 Scope                       Option             Contains                          Private keys
 --------------------------  -----------------  --------------------------------  ---------------
 CA certificates (default)   (none)             Roots, intermediates, chains,     none
                                                bundles, CRLs
 + leaf certificates         -IncludeLeafCerts  The leafcerts folders             leaf keys
 + CA keys                   -IncludeCaKeys     The whole pki folder              ALL CA keys
 DevKit                      -DevKit            See DevKit-MANUAL.txt             issuing CAs only

Files in the archive: certpack.json and certpack.tsv (the list), SHA256SUMS, README.txt, ca\roots\*.crt, ca\intermediates\*.crt, ca\ca-bundle-roots.crt, ca\ca-bundle-all.crt, ca\chains\*-fullchain.crt, ca\publish\*, and when packed leafcerts\* and pki\*. A PKI whose Enterprise Root was signed by a public CA also gets ca\external-chain.pem and the cross-certificates.

FORMATS. A .certpacked IS an archive under another name. Rename it to .zip or .7z and 7-Zip opens it with the password. The scripts read the first bytes, never the extension.

 Kind                     Made by                       Needs at the destination
 -----------------------  ----------------------------  ----------------------------------------
 zip + AES-256 (default)  PkiTransport.ps1 itself       Windows: nothing. Linux: 7-Zip (installed
                                                        for you).
 zip + ZipCrypto          the same (-ZipEncryption      Plain unzip. WEAK. Only for packages
                          ZipCrypto)                    WITHOUT private keys.
 7z + AES-256             7-Zip (-ArchiveFormat 7z)     7-Zip on both sides. Smaller. File names
                                                        are encrypted too.
 OPTIONS
   -Out <file>           Default .\transport\agantra-pki-<yyyyMMdd-HHmmss>.certpacked. The
                         extension is always .certpacked.
   -GeneratePassword     A 20-character password, shown once at the end.
   -PackagePassword <t>  Your own password (alias -Password). Also: PKI_TRANSPORT_PASSWORD, or a
                         prompt (asked twice).
   -ArchiveFormat zip|7z     -ZipEncryption Aes256|ZipCrypto     -SevenZipPath <exe>
   -IncludeLeafCerts [-LeafName a*,b]   Add the leafcerts folders (all, or those that match).
   -IncludeCaKeys        Add the whole PKI with the CA private keys. Only for a machine that must
                         issue certificates.
   -Kit                  Also write <name>-kit\ : the three scripts, the modules, the bootstrap
                         scripts, the CSR tools, Create-WebServerConfig and the manuals.
   -Comment <text>       Stored in the package, shown when it is opened.
   -NoVerify             Do not read the package back after writing.
 After writing, the script reads the package back (every entry is decrypted and authenticated).
 SAFEGUARDS
   * Every file has its SHA-256 in the package. The destination checks ALL of them before it writes
     anything. One changed byte stops the unpack.
   * A wrong password writes nothing. A name inside the archive that tries to leave the destination
     (../..) is refused.
   * ZipCrypto is refused for a package with private keys.
   * -Pack prints the SHA-256 of the package. Compare it after the transfer.
   * Send the package and the password by different ways. A package with private keys is as
     sensitive as the keys. Delete it and the extracted keys when the job is done.

6 PASSWORDS#

 A package password has these rules:
   * Printable ASCII only. At least 12 characters. At least 3 of 4: lower case, upper case, digits,
     symbols.
   * -AllowWeakPassword relaxes the length and the classes. Never the ASCII rule.
   * -GeneratePassword makes 20 characters without quotes, $, ! or backslash, so it pastes safely
     into any shell.

Where to put the password at the destination, safest first: 1. The prompt (not shown on screen). 2. A file: --password-file (Linux scripts only). 3. The variable PKI_TRANSPORT_PASSWORD. 4. -PackagePassword / --password. Visible in the process list and the shell history.

7 WINDOWS: SCAN AND INSTALL#

 .\PkiTransport.ps1 -Check [-Package <file>]   The scan. With -Package also: does the password open
                                               the file?
 .\PkiTransport.ps1 -Install -Package <file>
 The scan, then (only if it passes) unpack and install.

THE SCAN. Nothing is unpacked or installed unless all of it passes.

 Check       Rule
 ----------  -----------------------------------------------------------------------------------
 Windows     Windows 11 24H2 (build 26100) or newer, Server 2025 or Server 2022. Others: the reason
             is printed and the script stops (exit code 2 or 5).
 OpenSSL     4.0.1 or newer. Missing: it is installed when you agree or give -InstallMissing,
             otherwise the script stops (exit code 4). -SkipOpenSslCheck goes on anyway.
 Elevation   An administrator PowerShell. Checked BEFORE anything is unpacked.
 Also shown  The PowerShell version, and whether 7-Zip exists (only a 7z package needs it).
 WHAT -Install DOES, IN ORDER
   1. Opens the package and checks the SHA-256 of every file.
   2. Writes the selection (-Extract, default ca) to -Destination
      (default .\certpacked-received\<package name>).
   3. Puts every ROOT in Trusted Root Certification Authorities and every INTERMEDIATE in
      Intermediate Certification Authorities. The stores are read back. A wrong placement is an
      error.
   4. -InstallLeafPfx: imports the leaf PFX files into LocalMachine\My (the leaf only). -PfxPassword
      is their password (default Abc12345!).
   5. OpenSSL 4 proves that every CA and every extracted leaf chains to the roots (ML-DSA too).
 Remove the trust again:   .\PkiTransport.ps1 -RemoveTrust -Package <file>
 (The leaf PFX files in My stay.)
 Exit codes: 0 done, 1 error, 2 Windows not supported, 3 not Windows (use pki-transport.sh),
 4 OpenSSL 4.0.1+ missing, 5 this system is refused.
 To see the exit code use  pwsh -File .\PkiTransport.ps1 ...  ("pwsh -Command" shows only 0 or 1).

8 UNPACK ONLY (ANY COMPUTER)#

 .\Unpack-PkiTransport.ps1 -Package <file> [-Extract <list>] [-LeafName <w>] [-Destination <folder>]
                           [-List] [-Force]

It installs NOTHING and touches no certificate store. Use it to get the files, for example for a server that reads a CA file. * Default destination: .\certpacked-received\<package name>. certpack.json and README.txt are always written. * Identical files that already exist are left alone. A different file stops the run unless -Force. * -List shows what is inside and writes nothing. * -Extract pki also rewrites the absolute paths in the manifest and the CA settings to the new place. Then GenerateLeafCertificate.ps1 -PkiRoot <folder>\pki can issue from the moved PKI. * A wrong password, a damaged or a changed file: it says so and writes nothing.

9 LINUX: pki-transport.sh#

 ./linux/pki-transport.sh --package <file> [options]
 It does these four things, and nothing else:
   1. SCAN     platform, privileges (root or sudo), OpenSSL 4.0.1+, 7-Zip, unzip, store tools.
   2. PREPARE  installs what is missing (ca-certificates, 7-Zip; OpenSSL 4 with your consent).
   3. UNPACK   asks for the password, checks every SHA-256, writes the selection.
   4. INSTALL  puts the CA certificates in the system store and proves the chains with OpenSSL 4.

SYSTEM STORES

 Family                                   Anchors go to                       Store command
 ---------------------------------------  ----------------------------------  ---------------------
 Ubuntu                                   /usr/local/share/ca-certificates    update-ca-certificates
 CentOS Stream, RHEL, Rocky, Oracle       /etc/pki/ca-trust/source/anchors
 update-ca-trust extract
 SUSE Linux Enterprise, openSUSE          /etc/pki/trust/anchors              update-ca-certificates
 Another Linux                            --store-dir DIR                     --update-cmd CMD

The family is read from /etc/os-release. The files it adds are named agantra-pki-*, so --remove-trust takes out exactly those.

 WHICH CAs GO IN (--trust)
   roots (default)   every root: Enterprise, Track and Quadrant roots. A Linux store has one kind of
                     anchor, so every root goes in.
   enterprise        only the Enterprise Root. Servers must then send the whole chain.
   all-ca            roots and intermediates.
   none              install nothing (same as --no-trust).
 An Enterprise Root signed by a public CA is not installed as an anchor on Linux.
 USEFUL SWITCHES
   --yes             Do not ask. Install what is missing. Needed when there is no terminal.
   --dry-run         Print every system-changing command instead of running it.
   --destdir DIR     Put the anchors under DIR and do not rebuild the store (image builds).
   --check           The scan only.
   --list            What is inside. Nothing is written.
   --remove-trust    Take the CAs out (with --package: exactly that package's).
 Exit codes: 0 done, 1 error, 2 platform not supported, 4 OpenSSL missing, 5 wrong password (or this
 system is refused), 6 a prerequisite could not be installed.
 OpenSSL 4 missing: --install-openssl builds a FULL OpenSSL 4.0.3 from the official release into
 /opt/openssl-4.0.3 (the system openssl is not replaced). It takes about 5 minutes on 8 cores and
 over an hour on one core.

10 PACKAGES FOR SERVERS#

PkiTransport.ps1 makes more than the .certpacked. Each mode writes a zip to .\transport\.

 Mode                  Package                              For
 --------------------  -----------------------------------  ------------------------------------
 -DevKit               agantra-pki-devkit-<date>.zip        Developers. See DevKit-MANUAL.txt.
 -CrlServer            agantra-pki-crl-server-<date>.zip    CRL and CA certificates only.
 -CrlOcspServer        agantra-pki-crl-ocsp-server-...zip   CRL and OCSP, no time stamping.
 -TimestampServer      agantra-pki-timestamp-server-...zip  Time stamp server (RFC 3161) only.
 -Server               agantra-pki-server-<date>.zip        CRL, OCSP and time stamping.
 The server modes run New-PkiServerPackage.ps1. Rules:
   * No password. The package holds nothing secret and NO private key. The script opens the package
     again and scans it. One private key inside = the package is deleted (exit 5).
   * The modes cannot be combined with each other. -IncludeServiceKeys (the OCSP and time stamp
     keys) is a LAB option. -CrlServer and -TimestampServer refuse it. A CA key is never packed.
   * Options: -Out <file.zip>  -Force  -Tar (also a .tar.gz)  -Release  -NoCaRevocationInfo
     -PkiRoot.
 On the Ubuntu 24.04 / 26.04 server:
     unzip agantra-pki-crl-server-*.zip
     sudo ./linux/pki-server/pki-server.sh install --crl-only --source ./pki
     ./linux/pki-server/pki-server.sh dns          the hosts-file lines or router DNS records
 For OCSP and time stamping the keys are made ON the server and signed on the CA machine:
     sudo ./linux/pki-server/pki-server.sh csr --no-tsa --source ./pki --out ./csr
     (sign) PkiRevocation.ps1 -Action SignCsr -For Ocsp          (time stamping: -For Tsa -Ca <ca>)
     sudo ./linux/pki-server/pki-server.sh import-cert --cert ./signed/ocsp-<ca>.crt
     sudo ./linux/pki-server/pki-server.sh install --no-tsa --source ./pki
 Use --tsa-only for the time stamp server, and no flag for all three. A new CRL: run
 PkiRevocation.ps1 -Action NewCrl, build the package again, copy it, unzip it, and run
  pki-server.sh update --crl-only --source ./pki .
 The CRL and certificate addresses are the ones in the certificates, for example
 http://crl.nextmantra.internal/<ca>.crl. Full steps: PKI-SERVER-MANUAL.txt.

11 WHICH PKI GOES INTO A PACKAGE#

 One package holds ONE PKI.
   * By default: the latest release of the normal family.
   * -Release N: release N. A release that no longer exists = the latest, with a warning.
   * -NoCaRevocationInfo: the NoCR family (CAs without CRL and OCSP addresses).
   * -PkiRoot <folder>: exactly this folder.
   * -Pki <name>: the company. The file <name>_pki.cnf is used. File names follow it
     (agantra-pki-<date>.certpacked, raksaka-pki-<date>.certpacked).
 Inside the package the PKI is always the folder pki/, so the destination scripts need no change.
 devkit.env holds PKI_RELEASE and PKI_VARIANT. Make one kit for each release.
 Settings for all runs: pki_tools.cnf has TransportFolder, ArchiveFormat and ZipEncryption.
 See pki_setup-MANUAL.txt, section 9.

12 WHAT IS INSTALLED FOR YOU#

The transport needs three programs. When one is missing, the scripts install it.

 Program                 Needed for                  Windows                        Linux
 ----------------------  --------------------------  -----------------------------  ---------------
 OpenSSL 4.0.1+ (ready)  The scan, the chain proof   -InstallMissing, or answer
 --install-openssl
                         (ML-DSA too)                yes. Uses                      (a full build)
                                                     Install-DevEnvironment.ps1
                                                     -Only OpenSSL.
 7-Zip                   A 7z package; on Linux an   -InstallMissing (winget        asks, or --yes
                         AES-256 zip                 7zip.7zip)
                         (apt, dnf, zypper)
 Store tools             The system store            not needed                     asks, or --yes

"Ready" OpenSSL means: the FIPS module, ML-DSA and ML-KEM are present. A stripped build is NOT accepted by pki-transport.sh. On Windows, Install-DevEnvironment.ps1 -Check shows the table. The bootstrap scripts are looked for next to the running script and in its parent folder. The kit copies them. Without -InstallMissing the PowerShell scripts ask when a person is at the console, and otherwise stop with the exact command to run. More: Install-DevEnvironment-MANUAL.txt.

13 RECIPES, COPY AND PASTE#

 Trust only, for many Linux or Windows machines
     .\PkiTransport.ps1 -Pack -GeneratePassword -Kit
     then on each:  sudo ./linux/pki-transport.sh --package <file> --yes
 A service identity for one VM
     .\PkiTransport.ps1 -Pack -IncludeLeafCerts -LeafName api.example.com -GeneratePassword
     ./linux/pki-transport.sh --package <file> --extract ca,leafcerts --leaf 'api*' --no-trust
 A build computer that issues certificates
     .\PkiTransport.ps1 -Pack -IncludeCaKeys -IncludeLeafCerts -GeneratePassword
     .\Unpack-PkiTransport.ps1 -Package <file> -Extract pki -Destination D:\pki-build
     .\GenerateLeafCertificate.ps1 -PkiRoot D:\pki-build\pki -DnsName x.example.com
 A smaller package
     .\PkiTransport.ps1 -Pack -ArchiveFormat 7z -GeneratePassword
 No 7-Zip anywhere, CA certificates only
     .\PkiTransport.ps1 -Pack -ZipEncryption ZipCrypto -GeneratePassword      (then unzip -P works)
 Take the CAs out again
     .\PkiTransport.ps1 -RemoveTrust -Package <file>
     sudo ./linux/pki-transport.sh --package <file> --remove-trust
 Look inside, write nothing
     .\Unpack-PkiTransport.ps1 -Package <file> -List
     ./linux/pki-transport.sh --package <file> --list
 Image build (Dockerfile, VM template)
     ./linux/pki-transport.sh --package <file> --destdir /target --yes
     then run update-ca-certificates in the image
 Developers get one zip
     .\PkiTransport.ps1 -DevKit -GeneratePassword

14 PROBLEMS AND ANSWERS#

 Message or problem                              Cause and fix
 ----------------------------------------------  ----------------------------------------------
 "Windows ... not supported" (exit 2 or 5)       The computer is older than Windows 11 24H2, or a
                                                 special edition. Use Unpack-PkiTransport.ps1 and
                                                 import the roots by hand (certlm.msc).
 "OpenSSL ... not found / too old" (exit 4)      Run with -InstallMissing, or
                                                 Install-DevEnvironment.ps1, then open a NEW
                                                 window. Or -OpenSslPath. Linux: --install-openssl.
 WRONG_PASSWORD (exit 5 on Linux)                Wrong password or damaged file. Nothing was
                                                 written. Compare the SHA-256 printed by -Pack.
 "AUTHENTICATION_FAILED: x is damaged"           A byte changed on the way. Copy the file again.
 "The package does not match its own list"       Same: damaged or changed.
 "password is not accepted"                      12+ printable ASCII characters, 3 classes. Use
                                                 -GeneratePassword.
 "ZipCrypto ... refused for a package with keys" Use Aes256 when the package has private keys.
 "7-Zip was not found"                           Needed for 7z packages (and AES zips on Linux).
                                                 Use -InstallMissing / --yes, or -SevenZipPath /
                                                 --7z.
 7-Zip install fails on the RHEL family          Enable EPEL (and CRB), or give --7z, or pack with
                                                 -ZipEncryption ZipCrypto (CA certificates only).
 "exists and differs"                            Use -Force / --force, or another destination.
 "Nothing in this package matches ..."           The package lacks it (scope). The message lists
                                                 what it holds.
 Exit code is always 0 or 1                      You used pwsh -Command. Use pwsh -File.
 Files are blocked or read-only                  .\PkiTransport.ps1 -Unblock (Linux: --unblock).
 A browser still warns                           Firefox has its own store. Import the root there.
 -Server: "private key inside, deleted" (exit 5)  A key got into the package. Do not use it. Check
                                                 the pki\server folder.

15 LIMITS YOU MUST KNOW#

  • 7-Zip receives the password as an argument. It is visible in the process list while it runs. The default zip engine of the script has no such process.
  • A package with private keys is only as safe as its password and its handling.
  • The ZipCrypto zip is weak. Use it only without private keys.
  • An Enterprise Root signed by a public CA is not installed as an anchor on Linux.
  • Windows Server 2022 gets no post-quantum CAs. Older Windows is refused instead of installing half of the PKI.
  • macOS is refused since version 5.0.0. The macOS code paths in pki-transport.sh are not reachable.
  • The trust is installed per computer. Firefox, Java and some containers have their own stores.

17 WHAT WAS TESTED, WHAT WAS NOT#
