READ THIS FIRST#

 What it is   : A small kit that makes a computer TRUST your PKI. One zip per operating system, one
                script inside, one password. The kit holds public certificates only. No private
                key.
 Who reads it : Sections 1 to 6: the OWNER of the PKI who builds the kits. Section 7: the PEOPLE who
                receive a kit (junior developers, testers, customers). No PKI knowledge is needed.
                Every new word is explained in GLOSSARY.txt and GLOSSARY-ENGLISH.txt.
 Time needed  : 10 minutes to read. Building the kits takes about one minute.
 You need     : Owner: a PKI from pki_setup.ps1 and PowerShell 7. People: Windows 11 or Linux, and
                Administrator rights (or sudo) to install for all users.
 Start with   : Owners: section 4. Receivers: section 7.
 Related manuals:
   NewPkiCsr-MANUAL.txt        the request tool that is inside every kit
   PrepareComputer-MANUAL.txt  the tool that installs OpenSSL, Python, PowerShell 7
   DevKit-MANUAL.txt           the bigger kit for developers who also SIGN certificates
   PkiTransport-MANUAL.txt     carry the whole PKI (with keys) to another machine
   pki_setup-MANUAL.txt        build the PKI first
 Help in the terminal:   .\New-PkiTrustKit.ps1 -Help     .\Install-PkiCa.ps1 -Help
                         .\Remove-PkiCa.ps1 -Help        bash install-pki-ca.sh --help
                         bash remove-pki-ca.sh --help     (one page at a time)

1 WHAT A TRUST KIT IS#

Your PKI signs certificates. A computer only believes them if it TRUSTS the CA certificates of your PKI. A trust kit brings those CA certificates to the computer.

     OWNER                                           RECEIVER
     New-PkiTrustKit.ps1 -All
        windows-pki-....zip   --- (e-mail, share) -->  unzip, run Install-PkiCa.ps1, password
        ubuntu-pki-....zip
        PASSWORD.txt          --- (another way) ---->  the password

The kit is for people who only TRUST. They do not sign and they need no key. Developers who also issue certificates use the DevKit (DevKit-MANUAL.txt).

2 THE WORDS YOU NEED#

 Trust          The computer accepts certificates that this PKI signed.
 Root           The top CA certificate. It goes to the "trusted roots" store.
 Intermediate   A CA below the root. Windows keeps it in a second store.
 Store          The place where the operating system keeps trusted certificates.
 .certpacked    One encrypted file with the CA certificates (public only).
 Local Machine  The Windows store for ALL users. Needs an Administrator window.
 Current User   The Windows store for ONE user. No Administrator needed.
 Kit            The zip: scripts + the .certpacked.
 PEN            A company number. Not needed for the kit.

3 WHAT IS IN EVERY ZIP#

 Windows zip   Install-PkiCa.ps1       install the PKI
               Remove-PkiCa.ps1        take a PKI away again
               New-PkiCsr.ps1          make a key and a request, step by step
               Prepare-Computer.ps1    install PowerShell 7, .NET SDK 8 and 10, OpenSSL, Python and
                                       put them on the PATH
               + the .certpacked
 Linux zips    install-pki-ca.sh   remove-pki-ca.sh   new-pki-csr.sh   prepare-computer.sh
 (ubuntu,      + the .certpacked
 redhat, suse)

All scripts stand alone. No other file of the project is needed. The installers need no OpenSSL. The request tools work whether or not the PKI is installed on the computer.

4 QUICK START (OWNER)#

     .\New-PkiTrustKit.ps1 -All

This builds the kits for all four systems for the latest release of your PKI. Open transport\pki-trust-<name>-<unique>-<date>-<time>\. Send each person the zip for his system. Send the password (PASSWORD.txt) by ANOTHER way.

5 BUILD THE KITS#

     .\New-PkiTrustKit.ps1 -All                        all four systems
     .\New-PkiTrustKit.ps1 -Target Windows,Ubuntu      some of them (Windows, Ubuntu, Redhat, SUSE)
     .\New-PkiTrustKit.ps1 -All -Pki agantra,raksaka   several companies in ONE .certpacked
     .\New-PkiTrustKit.ps1 -All -AllReleases           every release of the company
     .\New-PkiTrustKit.ps1 -All -AllProfiles           every company, every release
     .\New-PkiTrustKit.ps1 -All -SelfExtract           also .sh files (Linux) that only EXTRACT
     .\New-PkiTrustKit.ps1 -All -Release 2             a given release
     .\New-PkiTrustKit.ps1 -All -NoCaRevocationInfo    the NoCR family

Result: transport\pki-trust-<name>-<unique>-<date>-<time>\ with

   windows-pki-....zip   ubuntu-pki-....zip   redhat-pki-....zip   suse-pki-....zip
   PASSWORD.txt          README.txt (what to tell the people)

<name> is <PkiName>-r<release>, or <PkiName>-nocr-r<release>, or <PkiName>-all. Several companies: agantra-raksaka. More than three: multipki. -AllProfiles: allpki-all. <unique> is 6 random characters, the same for the whole run.

The password: by default a strong password is made and written to PASSWORD.txt. Windows zips use AES-256. Linux zips use ZipCrypto, because python3, unzip and 7z open it on every distribution. The content is public anyway: the password guards against a wrong or changed package, it is not a secret keeper.

-SelfExtract: a Linux .sh (bash file.sh, or --dir F) that only EXTRACTS the zip. There is none for Windows since 6.4.16 (security products block a .cmd that carries a payload): right-click the zip, Extract All. The installer stays a script you can read.

6 SEND THE KIT#

  • Send the zip and the password by DIFFERENT ways (zip by e-mail, password by chat or phone).
  • Tell the receiver which zip is his. README.txt in the folder has the text.
  • There is no private key in any file. Even so, send only to the people who need it.
  • Tell the receivers to try it on one laptop and one QA machine first.

7 INSTALL THE KIT (RECEIVER)#

 WINDOWS (Windows 11 24H2 or newer, Windows Server 2022 or 2025)
   1. Unzip. Open PowerShell in that folder.
   2. powershell -NoProfile -ExecutionPolicy RemoteSigned -File .\Install-PkiCa.ps1
   3. Type the password.
   Administrator window = Local Machine stores (all users). Normal window = Current User stores;
   Windows then asks about each root: click Yes. Roots go to "Trusted Root Certification
   Authorities", intermediates to "Intermediate Certification Authorities". An older version of the
   same organization is replaced. Other organizations are never touched. Windows Server 2022 gets
   the Classic CAs only (the post-quantum ones are skipped, with a warning).
   At the end the extracted files, the install script and the .certpacked are deleted. The zip and
   the other scripts stay. -Keep keeps everything. Options: -Firefox, -Check, -Scope
   Machine|User|Auto.
 LINUX (Ubuntu 24+, CentOS Stream / RHEL / Rocky / Oracle 10+, SLES / openSUSE 15+)
   1. Unzip. Open a terminal in that folder.
   2. bash install-pki-ca.sh
   3. Type the password. The script calls sudo by itself.
   The roots go to the system store: Ubuntu /usr/local/share/ca-certificates (and
   update-ca-certificates), Red Hat family /etc/pki/ca-trust/source/anchors (and update-ca-trust),
   SUSE /etc/pki/trust/anchors (and update-ca-certificates). The files are called
   pki-<company>-<release>-<root>.crt. The opened package stays in the folder pki/.
   Options: --firefox, --check, --password-file.

AFTERWARDS (optional): run Prepare-Computer, then New-PkiCsr.ps1 / new-pki-csr.sh to ask for your own certificate (NewPkiCsr-MANUAL.txt).

The password: -Password / --password on the command line shows in a process list. Type it at the prompt, or use PKI_PACKAGE_PASSWORD, instead.

8 TAKE A PKI AWAY AGAIN#

Remove-PkiCa.ps1 and remove-pki-ca.sh stand alone. They need no password and no package. They read the list that the installer wrote.

     .\Remove-PkiCa.ps1 -List                 what the kit installed
     .\Remove-PkiCa.ps1 -Pki raksaka -Check   only show what would go
     .\Remove-PkiCa.ps1 -Pki raksaka          remove one company
     .\Remove-PkiCa.ps1 -Pki agantra,raksaka | -All | -Org "Raksaka"
     bash remove-pki-ca.sh --list | --pki raksaka | --all | --org raksaka | --check

-Org / --org works without the list: certificates whose organization contains the text. Windows: only certificates in the list (same SHA-1 thumbprint) are removed.

9 SUPPORTED SYSTEMS#

The installers check first. Anything else: exit 5, nothing is changed.

 Windows 11 24H2 or newer, Windows Server 2025   everything is installed
 Windows Server 2022                             the Classic CAs only
 Ubuntu 24+, CentOS Stream / RHEL / Rocky / Oracle Linux 10+, SLES / openSUSE 15+
 Refused: Windows 10 and earlier, Windows 11 before 24H2, Server before 2022, Chinese /
 Government / IoT / SE / Embedded editions, Debian, AlmaLinux, Fedora, Mint, older Linux releases,
 macOS.

Test variables (for testers only): PKI_FAKE_OS=Client:19045 (Windows), PKI_OS_RELEASE_FILE=<file> (Linux), PKI_ANCHOR_DIR, PKI_UPDATE_CMD, PKI_BUNDLE_FILE, PKI_KIT_STATE_DIR.

10 WHAT IS INSTALLED, AND WHERE#

 The installer writes a list of what it installed:
   Windows Local Machine   %ProgramData%\PkiTrustKit\installed.tsv
   Windows Current User    %LOCALAPPDATA%\PkiTrustKit\installed.tsv
   Linux                   /var/lib/pki-trust-kit/installed.tsv
 One line per certificate: company, release, store, name. The remove scripts use it.

Linux only gets the ROOTS in the system store (that is how Linux trust works). Windows gets roots and intermediates.

11 WHICH PKI GOES INTO A KIT#

 Default: the latest release of the company agantra.
   -Pki <a,b>           other companies, or several
   -Release <n>         a given release
   -NoCaRevocationInfo  the NoCR family
   -PkiRoot <folder>    one exact PKI folder
   -AllReleases         every release (and NoCR release) of the chosen companies
   -AllProfiles         every company that has a PKI, every release
 -AllReleases is not combined with -Release, -NoCaRevocationInfo or -PkiRoot.
 A company in -Pki that has no PKI yet stops the run (exit 4). Build it first:
 pki_setup.ps1 -Pki <name>.

12 SEVERAL PKIs IN ONE KIT#

One kit has one .certpacked. It can hold many PKIs. The installer installs EVERY PKI in it in one run and writes one line per PKI to the list. Replacement works by organization name: the old and new generation of a PKI share it. A kit with all PKIs replaces older certificates of those organizations, so give people a kit of ALL PKIs when they must trust everything. Each extra PKI makes the kit about 0.8 MB bigger per encryption type.

13 RECIPES, COPY AND PASTE#

 All systems, latest release:        .\New-PkiTrustKit.ps1 -All
 Windows and Ubuntu only:            .\New-PkiTrustKit.ps1 -Target Windows,Ubuntu
 Two companies in one kit:           .\New-PkiTrustKit.ps1 -All -Pki agantra,raksaka
 Everything that exists:             .\New-PkiTrustKit.ps1 -All -AllProfiles
 With your own password:             .\New-PkiTrustKit.ps1 -All -PackagePassword "..."
 A different output folder:          .\New-PkiTrustKit.ps1 -All -OutDirectory D:\kits
 Receiver, Windows (all users):      (Administrator PowerShell)
     powershell -NoProfile -ExecutionPolicy RemoteSigned -File .\Install-PkiCa.ps1
 Receiver, test only:                .\Install-PkiCa.ps1 -Check
 Receiver, Linux:                    bash install-pki-ca.sh
 Receiver, Linux with Firefox:       bash install-pki-ca.sh --firefox
 Remove one company (Windows):       .\Remove-PkiCa.ps1 -Pki raksaka
 Remove one company (Linux):         bash remove-pki-ca.sh --pki raksaka

14 PROBLEMS AND ANSWERS#

 "running scripts is disabled" (Windows)
     Use the command in section 7. It allows this one script.
 Wrong password (exit 3)
     Ask the owner. Check for spaces and typing mistakes.
 "administrator window needed" (exit 2)
     You asked for -Scope Machine in a normal window. Start PowerShell as administrator, or use
     the default scope (Current User).
 The browser still does not trust the site
     Close the browser and start it again. Firefox has its own store: use -Firefox / --firefox.
 Exit code 5
     This computer is refused (section 9). Nothing was changed.
 Exit code 4 when building
     A company in -Pki has no PKI. Build it first.
 Server 2022: "post-quantum CAs skipped"
     Expected. Server 2022 takes the Classic CAs only.
 I installed the wrong kit
     Use Remove-PkiCa.ps1 -List, then -Pki <name> (section 8).

15 LIMITS YOU MUST KNOW#

  • The kit makes a computer TRUST the PKI. It does not give the computer a certificate. For that use New-PkiCsr (and the owner's SignCsr).
  • The installer on Windows needs Administrator rights for the Local Machine store.
  • Firefox and some Java and Python programs keep their own stores. -Firefox covers Firefox only.
  • Downloaded scripts may carry the Internet mark. The command in section 7 avoids the block.
  • The kit does not update itself. When you build a new release of the PKI, build and send new kits.

16 ALL OPTIONS#

 New-PkiTrustKit.ps1
   -Target <list>        Windows, Ubuntu, Redhat, SUSE.        -All   all four.
   -Release <n>          The release. Default: the latest.     -NoCaRevocationInfo   NoCR family.
   -Pki <a,b,...>        Company or companies. Default agantra.
   -AllProfiles          All companies, every release.
   -AllReleases          Every release of the chosen companies (alias -AllPki).
   -PkiRoot <folder>     One PKI folder.       -PkiName <text>   Name in the file names.
   -OutDirectory <dir>   Default .\transport.  -PackagePassword <text>   Your own password.
   -SelfExtract          Also make the extract-only files.     -Force   Overwrite a run folder.
   -Help
 Install-PkiCa.ps1                               install-pki-ca.sh
   -Password -Package -Scope -Firefox -Check -Keep   --password --password-file --package --target
   -Help                                             --firefox --check --help
 Remove-PkiCa.ps1                                remove-pki-ca.sh
   -List -Pki -All -Org -Scope -Check -Yes -Help     --list --pki --all --org --keep-files --check
                                                     --yes --help
 Exit codes: New-PkiTrustKit 0 ok, 1 error, 4 PKI not found. Install: 0 ok, 1 error, 2 admin needed
 (Windows), 3 wrong password. Remove: 0 ok, 1 error, 2 admin needed (Windows). All: 5 system
 refused.

VERSION REPORT (new in 6.4.13). Every script answers -Version (PowerShell) or --version (bash). It prints the script version, author, company, e-mail, the operating system with its version and patch level (or kernel), and the newest .NET, Node.js, Python 3, Java, shell, Schannel and OpenSSL found, with the vendor of each OpenSSL. It changes nothing. Details: VERSION-INFO.txt.

17 WHAT WAS TESTED, WHAT WAS NOT#

 Tested on Ubuntu 24.04 with PowerShell 7: the kit build, the Ubuntu install for real (system
 store, replace, check, remove), the request tools after the install (the returned certificate
 verifies against the system store), RHEL / SUSE paths with test folders, the Windows script in
 PowerShell 7 against the .NET store of a Linux user.
 NOT tested: a real Windows (Local Machine and Current User stores, the security questions,
 Windows PowerShell 5.1, antivirus reaction), real RHEL / SUSE machines, a real Firefox. Try the
 Windows kit on one laptop and one QA machine first. PKI-Acceptance-Checklists.txt (E44).
