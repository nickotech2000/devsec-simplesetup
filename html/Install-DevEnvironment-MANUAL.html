READ THIS FIRST#

 What it is   : Two scripts that install the developer tools on a computer and PROVE that OpenSSL
                can do what the PKI needs. They install only what is missing.
 Who reads it : Developers and infrastructure staff. No PKI knowledge is needed. Every new word is
                explained in GLOSSARY.txt and GLOSSARY-ENGLISH.txt.
 Time needed  : 10 minutes to read sections 1 to 5. The install takes 2 to 10 minutes. A source
                build of OpenSSL on Linux takes longer (section 7).
 You need     : Internet access. Administrator (Windows) or root / sudo (Linux).
 Start with   : Section 4 (Quick start).

1 WHAT THE TWO SCRIPTS DO#

They prepare a computer for development and for the PKI scripts. They install what is MISSING. Nothing that is present is replaced, downgraded or removed.

     Install-DevEnvironment.ps1   Windows, through winget. Windows PowerShell 5.1 or PowerShell 7.
                                  Elevated, except -Check, -Help and -Unblock.
     Install-DevEnvironment.sh    Linux, through the package manager of the system. OpenSSL and
                                  pwsh can come from the official source or release.

Other PKI scripts call them when something is missing: PkiTransport.ps1 and Unpack-PkiTransport.ps1 run them with -InstallMissing, and pki-transport.sh runs the .sh script. The transport kit carries both, so a destination needs nothing else.

2 THE WORDS YOU NEED#

 Bootstrap      A first installer that gets a computer ready.
 winget         The Windows package manager from Microsoft.
 FIPS provider  The part of OpenSSL that does the certified cryptography. Quadrants 2 and 4 need it.
 ML-DSA, ML-KEM The post-quantum algorithms. Quadrants 3 and 4 need them. OpenSSL 4 has them built
                in.
 Stripped       An OpenSSL built without the FIPS module, or a "light" package, or one that only
                says 4.x. The PKI refuses it.
 Ready          All checks of section 6 pass.
 PPA            A personal package archive of Ubuntu. Yours is ppa:nickotech2000/nicko-su-prod.
 Unblock        Remove the "downloaded from the Internet" mark from files.
 Unlock         Remove Read-only or immutable flags from files.
 -Check         Look only. Nothing is installed.

3 BEFORE YOU START#

  • Internet access (package managers, GitHub).
  • Windows: an elevated PowerShell for the install. winget must work.
  • Linux: root, or sudo. Not needed for --check, --dry-run and --unblock.
  • A computer that is allowed: Windows 11 24H2 or newer, Windows Server 2025 and 2022. Linux: Ubuntu 24+, CentOS Stream / RHEL / Rocky / Oracle Linux 10+, SLES / openSUSE 15+. Others: exit 5, nothing is done. macOS is refused.

4 QUICK START#

     .\Install-DevEnvironment.ps1 -Check                         what does this computer have?
     .\Install-DevEnvironment.ps1 -Only OpenSSL,7Zip             just what the PKI tools need
     .\Install-DevEnvironment.ps1                                everything
     ./linux/Install-DevEnvironment.sh --check
     sudo ./linux/Install-DevEnvironment.sh --yes --only openssl,7zip
     sudo ./linux/Install-DevEnvironment.sh --yes                everything

Then close the window and open a NEW one. The PATH is read when a window starts.

6 OPENSSL: "READY" AND "STRIPPED"#

The PKI needs more than "an OpenSSL 4". It needs the FIPS provider (Quadrants 2 and 4) and the post-quantum algorithms (Quadrants 3 and 4). READY means that all of this is proven on the binary that will be used. The same checks run in both scripts:

 Check            What is proven
 ---------------  ---------------------------------------------------------------------------
 version          4.0.1 or newer (4.0.1 to 4.0.3 tested)
 FIPS provider    loads with fipsmodule.cnf and reports active
 ML-DSA           an ML-DSA-65 key signs and verifies
 ML-KEM           an ML-KEM-768 key is made
 ML-DSA in FIPS   an ML-DSA-65 key inside the FIPS provider (only a warning when a build lacks it)

Windows also checks that the machine-wide OPENSSL_CONF loads without provider errors.

 The Linux default is different on purpose. With --openssl-source system (the default) "ready" means
 OpenSSL 3.0.0 or newer, enough for the DevKit generators. What the system OpenSSL cannot do (FIPS
 config, ML-DSA, ML-KEM) is shown as NOTE, not as a failure. With ppa and build "ready" means 4.0.1
 or newer, the full checks above.

WINDOWS: what the script does. It installs FireDaemon.OpenSSL by winget. If it reports less than 4.0.1 it runs "winget upgrade". It writes fipsmodule.cnf (openssl fipsinstall), OPENSSL_MODULES, OPENSSL_CONF and a master openssl.cnf that activates default and FIPS. The OpenSSL bin folder goes on the MACHINE Path. oqsprovider is OPTIONAL (-WithOqsProvider): OpenSSL 4 has native ML-DSA and ML-KEM, and the master configuration names oqsprovider only when its DLL exists. The PKI scripts ignore OPENSSL_CONF: they use their own configuration.

7 OPENSSL ON LINUX: THREE SOURCES#

 --openssl-source system   DEFAULT. The OpenSSL of your distribution. Nothing is built, replaced or
                           put on the PATH. Ubuntu 26.04 ships 3.5.x (RSA, ECDSA and ML-DSA).
                           Ubuntu 24.04 ships 3.0.x (RSA and ECDSA only).
 --openssl-source ppa      OpenSSL 4 from your PPA (package nicko-su-openssl4 4.0.3), Ubuntu 24.04
                           and 26.04, amd64. The PPA is added with add-apt-repository.
 --openssl-source build    A FULL build from the official source release
                           (https://github.com/openssl/openssl/releases, 4.0.3; change it with
                           --openssl-version, 4.0.1 or newer):
     * the tarball is checked against the .sha256 file of the same release page. Nothing is built
       when it differs.
     * ./Configure --prefix=<prefix> --openssldir=<prefix>/ssl --libdir=lib enable-fips
       -Wl,-rpath,<prefix>/lib
     * make -j<cores>, then make install (libraries, headers, docs, the FIPS module,
       fipsmodule.cnf).
     * default prefix /opt/openssl-4.0.3. The system openssl is NOT replaced. A link openssl4 goes
       in /usr/local/bin. The rpath lets the binary run without LD_LIBRARY_PATH.
     * after the build the checks of section 6 run. The script fails (exit 4) when they do not pass.
 pki_setup.ps1 on a CA machine needs OpenSSL 4.x: on Linux use ppa or build.
 PATH (ppa and build): the bin folder of OpenSSL 4 goes FIRST on the PATH of login shells:
 /etc/profile.d/openssl4.sh (with sudo) or a marked block in ~/.profile and ~/.bashrc. The system
 openssl files are not touched. --no-path leaves the PATH alone. Open a NEW terminal afterwards.

BUILD TIME: about 5 minutes on 8 cores, 15 to 25 on 2 cores, over an hour on ONE core. Measured here: on a 1-core VM 542 object files in two minutes and more than 30 minutes without finishing. --openssl-no-docs shortens it a little. --openssl-jobs N sets the parallel jobs.

nginx: --only nginx installs your nginx from the PPA (package nicko-su-nginx 1.31.6), Ubuntu only. Another nginx that is already installed is NOT replaced (the scan says "NOT from the PPA"). --ppa and --nginx-package change the names. Other systems skip it.

8 LOOK FIRST: -Check / --check#

     .\Install-DevEnvironment.ps1 -Check            ./linux/Install-DevEnvironment.sh --check
     ./linux/Install-DevEnvironment.sh --check --only openssl,7zip

It lists every component (found or missing) and the OpenSSL readiness. It installs nothing and needs no elevation. Exit 0 = OpenSSL ready, 4 = not ready. --dry-run (Linux) prints the commands that would change the system and runs none of them.

9 UNBLOCK AND UNLOCK; HOW THE PKI SCRIPTS USE THESE SCRIPTS#

 UNBLOCK AND UNLOCK. Both scripts do it at EVERY start, silently, for their own folder (children
 and recursive), before anything else. -Unblock / --unblock does only that.
   Windows  UNBLOCK removes the Internet mark (Zone.Identifier). UNLOCK removes Read-only.
   Linux    UNLOCK sets write permission (chmod -R u+rw), gives scripts the execute bit and removes
            the immutable flag where chattr exists.
 A script that is blocked the very first time cannot run its own bootstrap. Then do it by hand:
   Windows  Get-ChildItem -Path . -Recurse -File | Unblock-File
   Linux    chmod +x *.sh
 The same mechanism is in pki_setup.ps1, GenerateLeafCertificate.ps1, PkiTransport.ps1,
 Unpack-PkiTransport.ps1 and pki-transport.sh.

HOW THE PKI SCRIPTS USE THEM

   PkiTransport.ps1 -Install ... -InstallMissing   OpenSSL 4 is missing or not ready on the
                                                   Windows destination: installs it with
                                                   Install-DevEnvironment.ps1 -Only OpenSSL, then
                                                   scans again
   PkiTransport.ps1 -Pack -ArchiveFormat 7z -InstallMissing    7-Zip is missing: installs it
   Unpack-PkiTransport.ps1 -Package x.certpacked -InstallMissing
                                                   a 7z package and no 7-Zip: installs it
   pki-transport.sh                                OpenSSL 4 is missing: it asks (or
                                                   --install-openssl) and runs
                                                   Install-DevEnvironment.sh when it sits next to
                                                   it. 7-Zip is installed on demand.

Without -InstallMissing the PowerShell scripts ASK when a person is at the console and stop with a clear message otherwise. They look for the bootstrap next to themselves and in the parent folder.

12 PROBLEMS AND ANSWERS#

 Symptom                                        Cause and fix
 ---------------------------------------------  -----------------------------------------------
 "a STRIPPED build: no FIPS module or no        An OpenSSL 4 without enable-fips (a "light"
 ML-DSA"                                        package). Install the full one: --only openssl
                                                with --openssl-source ppa or build.
 "NOT READY" after the Windows install          Read the readiness table: FIPS (fipsmodule.cnf
                                                missing), ML-DSA, ML-KEM. Run the script again
                                                elevated.
 FireDaemon reports 3.x                         The script runs winget upgrade. If it stays 3.x,
                                                install a newer FireDaemon OpenSSL by hand.
 The build seems to hang                        It is compiling hundreds of files. One core needs
                                                over an hour. Use a machine with cores.
 "SHA-256 of the tarball does not match"        Nothing was built. Retry (corrupt download) or
                                                check the proxy. Never override.
 7zip not installable on RHEL / Rocky / Oracle  Enable EPEL (and CRB), or install 7-Zip by hand and
                                                give --7z to pki-transport.sh.
 pwsh: "SHA-256 does not match hashes.sha256"   An old version had this (Windows line ends in the
                                                hash file). It is fixed. There is no apt package
                                                "pwsh" on Ubuntu: the script unpacks the official
                                                release.
 pwsh: "could not read the latest release"      GitHub is unreachable or rate limited. Retry
                                                later, or install PowerShell 7 by hand.
 FIPS: "no fipsmodule.cnf / fips.so found"      A WARN, not a failure: the FIPS quadrants (Q2, Q4)
                                                are unavailable with this OpenSSL. The script
                                                looks in the package files and makes
                                                fipsmodule.cnf with "openssl fipsinstall" when
                                                only fips.so exists (/etc/agantra-pki or
                                                ~/.config/agantra-pki). By hand:
                                                openssl4 fipsinstall -out fipsmodule.cnf
                                                -module <.../ossl-modules/fips.so>, then give
                                                -FipsModuleConfig <path> to the PKI script.
 "Not root and no sudo"                         Run with sudo or as root. Only --check, --dry-run
                                                and --unblock work without.
 Windows: red text in the window                Read the log:
                                                %ProgramData%\Agantra\WindowsDeveloperBootstrap\Logs
 Exit 5                                         This computer is refused (section 3).
 "The property 'Patch' cannot be found on this  Windows PowerShell 5.1 (a [System.Version] has
 object" (line 590, Windows Sandbox)            Build, not Patch) under Set-StrictMode. Fixed in
                                                7.9.5: the script reads Patch or Build.
 Stuck at "Starting package install..."         The installer waits without a word: a prompt
 (for example .NET 10 SDK in Windows Sandbox)   nobody sees, or Windows Installer still busy
                                                with another install - often the installer of a
                                                run cancelled with Ctrl+C (closing PowerShell does
                                                not stop it). 7.9.10: every minute the log names
                                                what still runs; after -PackageTimeoutMinutes
                                                (default 30) winget and its installer are
                                                stopped and the next component follows. A new run
                                                first waits (max. 10 min) for a leftover installer
                                                and for Windows Installer to be idle, then stops
                                                only an installer from %TEMP%\WinGet. Still busy:
                                                restart (or open a new Sandbox). Skip it:
                                                -SkipDotNet, or -Only without DotNet.
 "Cannot bind argument to parameter 'Message'   winget printed an empty line (after "Successfully
 because it is an empty string" (line 748)      installed", Windows Sandbox). Fixed in 7.9.9: empty
                                                lines and the spinner are skipped; stderr lines no
                                                longer stop Windows PowerShell 5.1.
 "WinGet was not detected"                      Windows Sandbox, LTSC, some Server images. 7.9.5
                                                installs winget itself (needs the Internet and
                                                the PowerShell Gallery). By hand: the three lines
                                                the script prints, or RUN-SCRIPTS-WINDOWS.txt.

13 LIMITS YOU MUST KNOW#

  • It needs the Internet (package managers, GitHub).
  • The source build trusts the checksum of the same release page, not a signature.
  • Distribution packages for go, node, php and dotnet may be older than "latest".
  • Nothing here removes or downgrades anything.
  • Package names differ between distributions and versions. Each component is tried with the usual names and then checked, never assumed.
  • macOS is refused by the platform check. The script still holds old macOS code. It cannot be reached.

16 PLATFORMS#

 Windows 11 24H2 or newer (Home, Pro, Pro for Workstations, Education, Pro Education,
 Enterprise), Windows Server 2025 and 2022.
 Linux (VM, bare metal, WSL): Ubuntu 24+, CentOS Stream 10+, RHEL 10+, Rocky 10+, Oracle Linux 10+,
 SLES 15+, openSUSE 15+. Package managers: apt, dnf, zypper.
 Refused (exit 5, nothing done): Windows 10 and earlier, Windows 11 before 24H2, Server before
 2022, the Chinese, Government, IoT, SE and Embedded editions, other Linux distributions, older
 versions, macOS.

VERSION REPORT (new in 6.4.13). Every script answers -Version (PowerShell) or --version (bash). It prints the script version, author, company, e-mail, the operating system with its version and patch level (or kernel), and the newest .NET, Node.js, Python 3, Java, shell, Schannel and OpenSSL found, with the vendor of each OpenSSL. It changes nothing. Details: VERSION-INFO.txt.

17 WHAT WAS TESTED, WHAT WAS NOT#

TESTED (Linux, Ubuntu 24.04 as root, a full OpenSSL 4.0.3 at hand): syntax, --help, --check, the five readiness checks against the real OpenSSL 4.0.3 (all pass), rejection of the system OpenSSL 3.0 and of a fake "4.0.3" that is 3.0 underneath, a REAL installation of 7-Zip with apt, --unblock, dry runs for Ubuntu, Rocky and openSUSE Tumbleweed, the pwsh release lookup, the OpenSSL download with checksum and Configure. PowerShell side: -InstallMissing installed 7-Zip through the companion script for a 7z package; the kit carries both bootstraps; Install-DevEnvironment.ps1 parses, -Help, -Unblock and the readiness functions run on PowerShell 7 against the real OpenSSL. NOT TESTED: Install-DevEnvironment.ps1 on Windows 11 (winget installs, the FireDaemon upgrade, Windows PowerShell 5.1); the finished OpenSSL source build (a 1-core VM could not finish it); any install on RHEL, SUSE; the PPA (add-apt-repository, the two PPA packages: no Launchpad access in the sandbox); the package names of dotnet, node, go and php; the pwsh download itself (only the version lookup and the plan). What to run on your machines: PKI-Acceptance-Checklists.txt, E45. 7.9.5: the 'Patch' fix was tested on PowerShell 7 with Set-StrictMode against a [System.Version] like the one of Windows PowerShell 5.1 (the old line fails with PropertyNotFoundStrict, the new one reads Build). NOT tested: the winget bootstrap in a real Windows Sandbox. 7.9.10: Invoke-WinGetTimed was tested on PowerShell 7 (Linux) with a stand-in for winget: normal end (exit code kept, empty and spinner lines and a progress bar left out of the log), and an install that never ends with a 1-minute limit: a heartbeat after 1 minute, then the process tree was stopped and -1 returned after 60 s. NOT tested: the Windows parts (the _MSIExecute check, the leftover installer in %TEMP%\WinGet, taskkill /T, Win32_Process) and the real .NET 10 SDK hang. 7.9.9: Invoke-NativeLogged was tested on PowerShell 7 with Set-StrictMode and ErrorAction Stop against a program that prints empty lines, spinner lines with carriage returns, a stderr line and exit code 3: only the text lines are logged, the exit code is kept, nothing stops.
