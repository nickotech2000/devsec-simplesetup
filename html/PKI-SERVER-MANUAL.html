The PKI server (Ubuntu)

Publish CRL, OCSP and time stamping from a Linux server.

Author: Nicko Satria Utama Company: Agantra Inovatif OU (NextMantra) Email: nicko@nextmantra.com

READ THIS FIRST#

 What it is   : Publishes CRL, OCSP and time stamping from an Ubuntu server.
 Who reads it : Infrastructure staff.
 You need     : An Ubuntu 24/26 server, the server package.
 Start with   : Follow the quick start steps.
 Words        : GLOSSARY.txt (technical terms), GLOSSARY-ENGLISH.txt (everyday English words)
  1. WHAT YOU GET One Ubuntu VM that serves your private PKI to the developers' machines, all on plain HTTP port 80 (revocation data must not need TLS):
     CRL + CA certificates   http://crl.nextmantra.internal/<slug>.crl   (ONE host, the internal TLD only); CA issuer files: http://crt.nextmantra.internal/<slug>.crt (ONE host, internal TLD only)
                             (the host names and file names come from the PKI itself:
                             pki\pki-<name>-<NN>\server\ ; agantra_pki.cnf only as a fallback)
     OCSP                    http://ocsp.nextmantra.internal   (ONE host, the internal TLD only;
                                                               [ocsp_urls])
                             ONE URL for all CAs: one "openssl ocsp" responder per CA behind a small
                             dispatcher
     Time stamping RFC 3161  http://tsa.nextmantra.internal   and   http://timestamp.nextmantra.internal
                             "openssl ts -reply" signed with your TimeStamping certificate
                             (Authenticode /code signing, jarsigner, openssl ts)
   Software: nginx from YOUR PPA (default ppa:nickotech2000/nicko-su-prod), OpenSSL 4.0.x (PPA
             package nicko-su-openssl4, an existing build, or
   built by Install-DevEnvironment.sh --openssl-source build), python3 (the dispatcher and the TSA
   service use only the standard library).
  1. WHAT STAYS WHERE * The CA PRIVATE KEYS never go to the server. Only: publish\ (CA certificates, CRLs), the index.txt of each CA (OCSP status), and the key + certificate of the OCSP-signing and time-stamping certificates (best: made on the server by 'csr', so no key travels). * CRLs are made where the CA keys are (pki_setup.ps1 / openssl ca -gencrl). They expire (365 days by default). After a new CRL, or after issuing or revoking a certificate: copy the pki folder again and run "update". A daily timer (crl-check) warns in the journal when a CRL has less than 14 days left.
3. PREPARE ON THE CA MACHINE (Windows 11)
   a. Your PKI exists (pki_setup.ps1). Certificates carry the URLs above ([crl_urls], [ocsp_urls],
      [ca_issuer_urls] of agantra_pki.cnf). pki_setup.ps1 also made the revocation information
      (pki\revocation-info.json, REVOCATION-INFO.txt, pki\ocsp, pki\tsa).
   b. Build the package (NO private key inside, LF text, .sh executable):
          .\PkiTransport.ps1 -Server            (zip in .\transport)      -Tar (also .tar.gz)      -Release 2 / -NoCaRevocationInfo (which PKI)
          or  .\New-PkiServerPackage.ps1       (same package, next to the scripts)
      -> agantra-pki-server-<date>.zip: linux\ (this kit, pki-transport.sh,
      Install-DevEnvironment.sh), pki\ (public files, index.txt of each CA), agantra_pki.cnf, the
      documents, SHA256SUMS. Copy it to the Ubuntu VM (scp, or the WSL path /mnt/c/Users/<you>/...).
   c. THE KEYS OF THE OCSP RESPONDERS AND THE TIME STAMP SERVER stay on the server (recommended):
         server:   sudo ./linux/pki-server/pki-server.sh csr --source ./pki --out ./csr
         CA side:  .\PkiRevocation.ps1 -Action SignCsr -Csr .\ocsp-q1-ev.csr -For Ocsp -Ca q1-ev
                   (repeat per CA; -For Tsa -Ca q1-ev for tsa-q1-ev.csr)
         server:   sudo ./linux/pki-server/pki-server.sh import-cert --cert ocsp-q1-ev.crt --cert
                   ocsp-q1-ov.crt --cert tsa-q1-ev.crt
      Lab shortcut instead: New-PkiServerPackage.ps1 -IncludeServiceKeys (the OCSP / TSA keys made
      by pki_setup travel in the package; never a CA key), or --ocsp-leaf / --tsa-leaf folders of a
      GenerateLeafCertificate.ps1 set.
4. INSTALL ON UBUNTU
      unzip agantra-pki-server-*.zip && cd agantra-pki-server
      bash linux/fix-permissions.sh                    (only if "Permission denied"; the zip keeps
                                                       the execute bits)
      sudo ./linux/pki-server/pki-server.sh install --source ./pki
   (--source finds <source>/ocsp and <source>/tsa and the imported certificates by itself; --cnf is
   found next to the package.)
   What it does: apt update; adds the PPA; shows what the PPA publishes; installs nginx (package
                 found in the PPA, else "nginx"; override
   --nginx-package), python3, curl; finds OpenSSL 4 (an existing one, or the PPA package, or
   --build-openssl); creates the service user pki-server; publishes the files to
   /srv/agantra-pki/www; sets up one OCSP responder per CA (matching each OCSP certificate to its
   issuing CA by issuer hash, and refusing a key that does not match its certificate); sets up the
   TSA (policy OID from the certificate, default 1.3.6.1.4.1.67096.1.4); writes the nginx site
   (sites-available/agantra-pki-server.conf + symlink, or conf.d/), runs nginx -t and ROLLS BACK
   when it fails; writes and starts the systemd units; runs the self-test; prints the DNS records.
   THE PPA (read from the Launchpad API, 2026-10-11): ppa:nickotech2000/nicko-su-prod publishes for
   Ubuntu 24.04 (noble) and 26.04
   (resolute), amd64 only:   nicko-su-nginx 1.31.6-nicko-su-8     nicko-su-openssl4 4.0.3-nicko-su-4
   These are the defaults. The kit finds the nginx binary, service name and configuration folder,
   and the OpenSSL binary and its private library folder, from the package file lists (dpkg -L), so
   it does not matter where the packages put them. Options if you rename things:
      --ppa ppa:owner/name   --no-ppa   --nginx-package <name>   --openssl-package <name>   --openssl /path/to/openssl
   If your nginx.conf does not include sites-enabled or conf.d, the kit says so and prints the
   include line to add.
   TEST IN WSL (Ubuntu 24.04 / 26.04) FROM WINDOWS 11 PRO
      1  wsl --install -d Ubuntu-24.04   (or Ubuntu-26.04).  Work in the Linux file system (~), not
                                         in /mnt/c: unzip there, so that the execute bit and LF
                                         stay.
      2  systemd: WSL needs  [boot] systemd=true  in /etc/wsl.conf (then  wsl --shutdown). Without it use  --no-systemd  and  ... pki-server.sh run.
      3  In WSL:  ./linux/pki-server/pki-server.sh dns     prints the host names. WSL's IP:  hostname -I
      4  Windows: Notepad as ADMINISTRATOR -> C:\Windows\System32\drivers\etc\hosts, add one line per name, e.g.
              172.20.x.x   crl.nextmantra.internal crt.nextmantra.internal ocsp.nextmantra.internal tsa.nextmantra.internal timestamp.nextmantra.internal
         Windows 11 22H2+ with  [wsl2] networkingMode=mirrored  (in %UserProfile%\.wslconfig): use 127.0.0.1. With the default NAT mode the WSL IP changes at
         every start; localhost forwarding also reaches port 80 on 127.0.0.1. Run  ipconfig /flushdns  after editing.
      5  Windows: curl.exe http://crl.nextmantra.internal/agantra-q1-ev-g1.crl -o t.crl   certutil -URL <leaf.crt>   (the Windows revocation test)
         openssl ocsp ... -url http://ocsp.nextmantra.internal   and the time stamp commands of
                                                                 chapter 7.
      6  Port 80 busy on Windows (IIS, World Wide Web Publishing Service)? Stop it, or use the WSL IP in the hosts file.
5. DNS (your Wi-Fi router)
      ./pki-server.sh dns          prints the list. Create an A record for each name pointing to the
                                   VM's IP.
   Every name is .internal: nothing public is overridden. After  install / update  (nginx running) the script prints, with the VM's real IP:
     1. the lines for the Windows hosts file,   2. the records for the Wi-Fi router (NAME / TYPE A / VALUE),
     and writes /etc/agantra-pki-server/dns/hosts.txt, dns-records.csv and dnsmasq.conf (Pi-hole,
     OpenWrt). Show them again any time: ./pki-server.sh dns
     Another IP than the first one of the VM:  ./pki-server.sh dns --server-ip <IP>.   Without the server: pki\pki-<name>-<NN>\server\DNS-RECORDS.txt has the same lists with <SERVER-IP>.
6. DAILY WORK
      sudo ./pki-server.sh update --source ./pki     new CRLs, new index.txt (OCSP follows at once);
                                                     after every New-PkiServerPackage.ps1
      sudo ./pki-server.sh csr | import-cert         keys on the server (chapter 3c)           ./pki-server.sh info   status + DNS
      ./pki-server.sh status                 services, certificate dates, CRL expiry
      ./pki-server.sh test                   CRL download via nginx, OCSP query per CA (signature
                                             verified), time stamp create + verify
      ./pki-server.sh crl-check              CRL expiry only
      ./pki-server.sh check                  OpenSSL / nginx / python readiness, nothing changed
      sudo ./pki-server.sh uninstall [--purge]
   Without systemd (container, WSL):   sudo ./pki-server.sh install ... --no-systemd   then   sudo /opt/agantra-pki-server/pki-server.sh run
6a. CRL SERVER ONLY (4.9.5)  -  the small package, three commands, Ubuntu 24.04 / 26.04
   When you only need the CRLs and the CA certificates on the network (Word / Excel / Outlook
   signatures, certutil -urlfetch, browsers), and not OCSP or time stamping, use the SMALL package.
   It has no private key, needs no OpenSSL 4 and no python:
     Windows (CA machine):   .\PkiTransport.ps1 -CrlServer            -> .\transport\agantra-pki-crl-server-<date>.zip   (-Release 2, -Tar, -NoCaRevocationInfo, -Out, -Force as for -Server)
     Ubuntu:                 unzip agantra-pki-crl-server-*.zip && cd agantra-pki-crl-server
                             sudo ./linux/pki-server/pki-server.sh install --crl-only --source ./pki
                             ./linux/pki-server/pki-server.sh dns            the hosts-file lines and the router A records for crl. / crt.nextmantra.internal
   What --crl-only does: installs nginx (the PPA nicko-su-nginx; --no-ppa = the Ubuntu nginx),
   publishes pki/publish, writes the nginx site for the CRL / CA-issuer hosts, a daily CRL expiry
   timer, runs the self-test (every CRL and CA-issuer URL of the PKI is asked). It is remembered:
   update / test / crl-check / dns follow it. The system openssl 3.x is enough. WSL without systemd:
   add --no-systemd and start nginx yourself (sudo nginx). New CRL (they expire, see CRL_DAYS in
   server\server.env): on the CA machine  .\PkiRevocation.ps1 -Action NewCrl , build the package
   again, copy, unzip, then sudo ./linux/pki-server/pki-server.sh update --crl-only --source ./pki
   Later you want OCSP and time stamping too: build the full package (-Server) and run install
   WITHOUT --crl-only (the CRL host stays the same).
6b. CRL + OCSP SERVER, NO TIME STAMPING (4.9.5)
   Windows (CA machine):   .\PkiTransport.ps1 -CrlOcspServer      ->
                                                                  .\transport\agantra-pki-crl-ocsp-server-<date>.zip
                                                                  (-Release, -Tar,
                                                                  -NoCaRevocationInfo, -Out, -Force)
   Ubuntu 24.04 / 26.04:   unzip agantra-pki-crl-ocsp-server-*.zip && cd agantra-pki-crl-ocsp-server
     sudo ./linux/pki-server/pki-server.sh csr --no-tsa --source ./pki --out ./csr        OCSP keys are made on the server (no TSA key, no TSA CSR)
     (CA machine)  .\PkiRevocation.ps1 -Action SignCsr -Csr ocsp-q1-ev.csr -For Ocsp -Ca q1-ev        one per issuing CA
     sudo ./linux/pki-server/pki-server.sh import-cert --cert ./signed/ocsp-q1-ev.crt --cert ...
     sudo ./linux/pki-server/pki-server.sh install --no-tsa --source ./pki
     ./linux/pki-server/pki-server.sh dns          crl. / crt. / ocsp.nextmantra.internal (no tsa.
                                                   names)
   --no-tsa is remembered (update, test, dns). New CRL or new certificates: build the package again, copy, unzip, then  update --no-tsa --source ./pki.
   Time stamping later: install again without --no-tsa (with the TSA certificate imported). Only
   CRLs: chapter 6a (-CrlServer).
6c. TIME STAMP SERVER ONLY (4.9.5)
   Windows (CA machine):   .\PkiTransport.ps1 -TimestampServer      ->
                                                                    .\transport\agantra-pki-timestamp-server-<date>.zip
                                                                    (-Release, -Tar,
                                                                    -NoCaRevocationInfo, -Out,
                                                                    -Force)
   Ubuntu 24.04 / 26.04:   unzip agantra-pki-timestamp-server-*.zip && cd agantra-pki-timestamp-server
     sudo ./linux/pki-server/pki-server.sh csr --tsa-only --source ./pki --out ./csr          one TSA key + CSR (--tsa-ca <id>: the CA that signs it, default the first -ev CA)
     (CA machine)  .\PkiRevocation.ps1 -Action SignCsr -Csr tsa-q1-ev.csr -For Tsa -Ca q1-ev
     sudo ./linux/pki-server/pki-server.sh import-cert --cert ./signed/tsa-q1-ev.crt
     sudo ./linux/pki-server/pki-server.sh install --tsa-only --source ./pki
     ./linux/pki-server/pki-server.sh dns          tsa. and timestamp.nextmantra.internal only
   nginx answers on those two names and forwards to the TSA service (python3 + openssl ts); no CRL
   host, no OCSP. --tsa-only is remembered (update, test, dns). The clients still need the CRL (or
   OCSP) of the PKI to check the time stamp certificate: run -CrlServer / -CrlOcspServer / -Server
   on this or another machine. Cannot be combined with --crl-only or --no-tsa.
7. TESTS FROM A CLIENT
      OCSP     openssl ocsp -issuer ca.crt -cert leaf.crt -url http://ocsp.nextmantra.internal
               -CAfile ca-bundle.crt
      Stamp    openssl ts -query -data file -sha256 -cert -out q.tsq
               curl -H 'Content-Type: application/timestamp-query' --data-binary @q.tsq http://tsa.nextmantra.internal/ -o r.tsr
               openssl ts -verify -data file -in r.tsr -CAfile ca-bundle.crt
      Windows  signtool sign /fd sha256 /tr http://tsa.nextmantra.internal /td sha256 /f code.pfx file.exe
      CRL      curl -O http://crl.nextmantra.internal/agantra-q1-ev-g1.crl ; openssl crl -inform DER
               -in agantra-q1-ev-g1.crl -noout -text
      Windows chain check (Word / Excel "Recoverable Signature", after the hosts file or router DNS
      is set):
               certutil -urlcache * delete                                   clears what Windows remembered about failed downloads
               certutil -verify -urlfetch <leaf>-fullchain.crt               no REVOCATION_STATUS_UNKNOWN, the CRL line "Verified"
      (These two lines are NOT printed by Start-PkiCrlServer.ps1 any more: antivirus programs treat
      the certutil download-cache switch as a suspicious pattern in a script.)
8. FILES ON THE SERVER
      /opt/agantra-pki-server/     pki-server.sh, pki-ocsp-dispatch.py, pki-tsa.py, ocsp-run, tsa-run, dispatch-run
      /etc/agantra-pki-server/     kit.conf, tsa.cnf, ocsp-backends, ocsp/<ca>.env, keys/
                                   (responder + TSA keys: 640 root:pki-server)
      /var/lib/agantra-pki-server/ ocsp/<ca>/index.txt + ca.crt (the OCSP copy), tsa.serial
      /srv/agantra-pki/www/        everything published (CRLs, CA certificates, ca-bundle.crt,
                                   root.crt, index.html)
      /etc/nginx/sites-available/agantra-pki-server.conf    systemd: agantra-ocsp-<ca>, agantra-ocsp-dispatch, agantra-tsa, agantra-crl-check.timer

8A. RELEASES (R2, R3) AND THE NoCR PKI One server package holds ONE PKI: New-PkiServerPackage.ps1 takes the latest release (-Release N, -NoCaRevocationInfo choose another, -PkiRoot a folder). CRL and CA files have different names per release (agantra-q1-ov-g1.crl, agantra-q1-ov-g1-r2.crl), so installing the packages of several releases one after the other keeps the files of all of them in /srv/agantra-pki/www. OCSP and the time stamp service serve the release that was installed LAST. A NoCR PKI has no CRL / OCSP URL in its CA certificates; the server is then only needed for the leaf certificates that carry those URLs.

8B. THE PKI TELLS THE SERVER  (4.9.5; pki\pki-<name>-<NN>\server\ , written by pki_setup.ps1 and refreshed by every PkiRevocation.ps1 action)
   The server does not guess and does not depend on a file you keep in step: the PKI writes what it
   really contains.
       server-info.json     release, variant (normal | NoCR), name suffix, CRL days, the hosts, the
                            URL templates, and for every CA: id, common name, parent, level, track,
                            fips, slug, crl / crt file names, CRL number and next update,
                            "ocspResponder" yes / no
       ca-list.tsv          the same list for shell (tab separated: id kind slug level track fips
                            parent ocsp crl-file crt-file common-name crl-next-update)
       server.env           PKI_SRV_RELEASE, PKI_SRV_VARIANT, PKI_SRV_NAME_SUFFIX, PKI_SRV_HOSTS_CRL
                            (CRL + CA-issuer hosts), PKI_SRV_HOSTS_OCSP, PKI_SRV_CRL_DAYS
       expected-urls.tsv    EVERY CRL / CA-issuer / OCSP URL that the certificates of this PKI
                            contain: type, host, url
       DNS-RECORDS.txt      the host names to put in DNS (or the hosts file), with their role
   pki-server.sh install / update copies these files to
   /etc/agantra-pki-server/pki-info/<R1|R2|NoCR-R1>/, builds the nginx server_name lists from them,
   serves the CRL and CA files under the SAME file names (the slug of the URL: agantra-root-g1.crl,
   agantra-q1-ov-g1-r2.crl ...), creates the OCSP responders from the CA list, names the OCSP / time
   stamp requests the same way as the PKI does ("Agantra EV RSA-4096 G1 CA (NoCR) R2 OCSP
   Responder", "Agantra Time Stamping Authority (NoCR) R2"), and  pki-server.sh test  asks every URL
   of expected-urls.tsv (right host name, right path, the file parses as a CRL / certificate). The
   test therefore proves that the server satisfies the certificates that exist, not a fixed list.
   Several releases / families: install the package of each one; the files of all of them stay
   (their names differ), the host lists are added together, OCSP and the time stamp service serve
   the release installed LAST. A PKI made by an older version has no server\ folder: the hosts then
   come from agantra_pki.cnf, and  .\PkiRevocation.ps1 -Action Info  creates the folder. A NoCR PKI
   has no URL in its CA certificates; the server is still needed for the leaf certificates (they
   keep their CRL / OCSP URLs). NAMES of the CRL and CA-issuer files (the {ca} of the URLs) follow
   the CA names: Root CA -> agantra-root-g1, Classic Root -> agantra-classic-root-g1, PQC Root ->
   agantra-pqc-root-g2, Q1 / Q2 roots -> agantra-q1-root-g1 / -g2, intermediates -> agantra-q1-ov-g1
   ; NoCR adds -nocr, release 2+ adds -r2.
8C. PkiTransport.ps1 -Server  -  the server package from the transport script  (4.9.5)
   .\PkiTransport.ps1 -Server                 .\transport\agantra-pki-server-<date>.zip   (latest release, normal family)
   .\PkiTransport.ps1 -Server -Release 2 -Tar  also a .tar.gz       -NoCaRevocationInfo  the NoCR family       -PkiRoot <folder>  one folder
   -Out <file.zip>  -Force      -IncludeServiceKeys  LAB ONLY (the OCSP / time stamp keys; a CA key
                                is never packed)
   It runs New-PkiServerPackage.ps1 (same checks: no private key, LF text, execute bits; the package
   is opened again and scanned, one key = deleted) and prints the SHA-256. No password: the package
   holds nothing secret. Inside: linux\ (pki-server kit, pki-transport.sh,
   Install-DevEnvironment.sh), pki\ (the PKI WITHOUT keys, with server\), agantra_pki.cnf, the
   documents. On Ubuntu:  unzip; sudo ./linux/pki-server/pki-server.sh install --source ./pki
9. LIMITS AND SECURITY NOTES (read them)
   * The OCSP dispatcher chooses the responder by the issuer key hash of the request (OpenSSL 4
     answers 'unknown' for a foreign CA's certificate).
   * The time stamp certificate is the normal TimeStamping leaf (critical, alone), Classic non-FIPS
     by default; see PKI-Server-Design.txt D6.
   * "openssl ocsp -port" listens on ALL interfaces (it has no bind address). Ports 25001 and up,
     then answer plain OCSP. Block them from
     the LAN:   sudo ufw allow 80/tcp ; sudo ufw deny 25001:25099/tcp ; sudo ufw deny 2559:2560/tcp
                (the dispatcher and the TSA bind 127.0.0.1 only).
   * openssl ocsp is a simple responder: fine for a private PKI, no load balancing, answers valid
     for 1 day, signed on request.
   * The OCSP copy of index.txt replaces the subject column by the serial (OpenSSL refuses duplicate
     subjects of valid entries; the answer needs only serial and status). The CA's own index.txt is
     not touched.
   * Time stamping: RSA or ECDSA TSA keys, SHA-256 signature. A post-quantum (ML-DSA) TSA is not
     supported by this kit. Policy OID default 1.3.6.1.4.1.67096.1.4 (your PEN arc; taken from the
     TSA certificate, --tsa-policy overrides). The time comes from the VM clock: run chrony /
     systemd-timesyncd.
   * Plain HTTP only, as CRL / OCSP / AIA require. Do not put these hosts behind a redirect to
     HTTPS.
   * TESTED: the whole chain (CRL via nginx, OCSP good / revoked / unknown, time stamp create +
     verify, nginx -t rollback) on Ubuntu 24.04 with OpenSSL 4.0.3 and the Ubuntu nginx 1.24,
     WITHOUT systemd (the units are written by the same code but were not started here), and WITHOUT
     your PPA packages (the PPA is not reachable from the build machine; the package names come from
     the Launchpad API). First run on your VM: ./pki-server.sh check, then install, then test.

5.0.0: New-PkiServerPackage.ps1 / PkiTransport -Server take -Pki <name>; the package is <name>-pki-server-<date>.zip and holds <name>_pki.cnf. server.env has PKI_SRV_PROFILE; for a company other than agantra the release label on the server is <name>-R<n>. Folders: pki\pki-<name>-<NN>.
