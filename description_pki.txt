### The resulting behavior

**1. Current/latest certificates**

```powershell
.\pki_setup.ps1 -RemoveTrust
```

It uses the certificate files currently under:

```text
.\pki\root\root.crt
.\pki\intermediate\intermediate.crt
.\pki\leaf\*.crt
```

and removes their exact thumbprints from:

```text
LocalMachine\Root
LocalMachine\CA
LocalMachine\My
```

So it won't accidentally remove an older Agantra certificate that happens to have the same organization.

---

**2. Remove all matching trust**

```powershell
.\pki_setup.ps1 -RemoveAllTrust
```

It scans:

```text
LocalMachine\Root
LocalMachine\CA
LocalMachine\My
```

and matches against the configured organization and DNS names.

For example, it can identify certificates associated with:

```text
O=Agantra Inovatif OU (NextMantra)
```

and domains such as:

```text
makananmurah.com
www.makananmurah.com
nextmantra.com
www.nextmantra.com
```

The Personal store additionally checks SAN/issuer information, making it much less likely that an unrelated personal certificate is deleted.

If `ev_pki.cnf` is missing, the fallback organization is:

```text
Agantra Inovatif
```

---

**3. Rebuild everything**

```powershell
.\pki_setup.ps1 -Clean -InstallTrust
```

The sequence is:

```text
Remove current certificates
        ↓
Delete .\pki\
        ↓
Create new .\pki\
        ↓
Create CA database
        ↓
Generate Root RSA 8192
        ↓
Generate Intermediate RSA 4096
        ↓
Generate Leaf RSA 2048
        ↓
Generate Leaf RSA 3072
        ↓
Generate Leaf RSA 4096
        ↓
Validate certificate chains
        ↓
Install certificates
```
